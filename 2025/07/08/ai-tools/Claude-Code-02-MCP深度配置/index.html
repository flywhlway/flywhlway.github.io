Claude Code MCP 服务器深度配置

基于 Claude Code 1.0.44 与 MCP 2025-06-18 规范…

Flywhl 20 分钟 更新于 2026.09 #AI工具#开发效率#Claude Code

先读结论

  1. MCP 工具在 Claude Code 里与内置工具同等对待：名字是 mcp__服务器__工具，受同一套权限规则约束，工具定义常驻上下文。
  2. 作用域同名时 local 优先于 project 再优先于 user；.mcp.json 入库共享，但信任对话框选择启用会顺带写入 enableAllProjectMcpServers: true。
  3. 1.0.44 的 .mcp.json 不展开环境变量，stdio 服务器的密钥应从启动 Claude Code 的 shell 环境继承，而不是写进文件。
  4. 工具返回超过 MAX_MCP_OUTPUT_TOKENS（默认 25000）会直接报错而不是截断，服务器侧要支持分页或 LIMIT。
  5. 选服务器先问能不能用现成 CLI 解决；接入后坚持只读优先、版本固定、不可信输入与写权限不同场。

本文以 7 月 7 日发布的 Claude Code 1.0.44 为准。这个版本内置的 MCP SDK 以 2025-06-18 为最新协议版本，并向下兼容 2025-03-26 与 2024-11-05；文中命令、配置字段和行为都对照了当时的官方文档与安装包代码。基础的权限规则与 settings 层级见本系列第 1 篇。

MCP 在 Claude Code 中的角色

协议背景

Model Context Protocol 由 Anthropic 于 2024 年 11 月 25 日开源，首个规范版本号为 2024-11-05。之后两次修订与本文直接相关：

规范版本 与 Claude Code 使用相关的变化
2025-03-26 引入基于 OAuth 2.1 的授权框架；用 Streamable HTTP 取代原先的 HTTP+SSE 传输；工具注解（如只读、破坏性）
2025-06-18 MCP 服务器被定义为 OAuth 资源服务器，通过受保护资源元数据发现授权服务器，客户端必须实现 RFC 8707 资源指示符；结构化工具输出；工具结果可返回资源链接；新增 elicitation（服务器向用户索取信息）；移除 JSON-RPC 批处理

三类原语在 Claude Code 里的落点

Claude Code 是 MCP 客户端，为每个配置的服务器建立一条连接。服务器暴露的三类原语各有去处：

原语 在 Claude Code 中的形态 由谁触发
tools 与内置工具并列，名字为 mcp__<服务器名>__<工具名>，受权限规则约束 模型决定调用
resources 输入 @ 时出现在补全菜单里，引用后作为附件载入 用户引用；Claude Code 也会为支持资源的服务器提供列出与读取资源的工具
prompts 变成斜杠命令 /mcp__<服务器名>__<提示名> 用户输入命令

反方向的能力要看客户端声明了什么。1.0.44 在握手时只声明了 roots 能力，并把启动目录作为唯一的 root 返回给服务器；没有声明 sampling 和 elicitation。也就是说，服务器不能反过来借 Claude Code 调用模型，也不能在执行中途弹框向你要参数，这类服务器功能在 Claude Code 里会退化或不可用。

另一个方向是 claude mcp serve：把 Claude Code 自己的工具（读写文件、执行命令等）作为 MCP 服务器暴露给其他客户端，例如 Claude Desktop。此时逐次确认工具调用的责任落在那个客户端身上。

什么时候不需要 MCP

每个已连接服务器的全部工具定义（名称、描述、参数 schema）都会随每次请求进入上下文。GitHub 官方服务器全开时有数十个工具，这部分开销在整个会话里持续存在。接入前先比较一下现成 CLI：

需求 优先选择 理由
本机已装好并登录的 CLI（gh、psql、kubectl） Bash + 权限规则，如 Bash(gh issue view:*) 零上下文常驻成本，权限按命令前缀控制，团队成员行为一致
需要 OAuth 的 SaaS、没有 CLI 的系统 MCP 远程服务器 认证由 Claude Code 托管，不必把 token 交给 shell
需要结构化交互的能力，如浏览器操作 MCP CLI 很难把页面状态以结构化方式交还给模型
同一套集成要在多个 MCP 客户端复用 MCP 配置一次，Claude Code、Claude Desktop 等客户端共用

管理命令与三种作用域

常用命令

claude mcp add 的选项：

选项 取值 默认
-s, --scope local、project、user local
-t, --transport stdio、sse、http stdio
-e, --env KEY=value，可多次 无
-H, --header "Name: value"，用于 SSE 与 HTTP 无

-- 分隔符是最常见的坑。服务器命令本身带 -y、--isolated 这类参数时，不加 -- 会被 claude mcp add 当成自己的选项解析而报错或丢参数。约定：stdio 服务器一律在命令前写 --。

三种作用域

作用域 存放位置 可见范围 适合
local（默认） ~/.claude.json 中当前项目路径下 仅自己、仅当前项目 试验中的服务器、带个人凭据的服务器
project 项目根目录 .mcp.json 所有克隆仓库的人 团队约定的标准工具链
user ~/.claude.json 全局部分 自己的所有项目 与项目无关的个人工具，如文档检索

早期版本的命名不同：现在的 local 以前叫 project，user 以前叫 global。网上旧教程里的 -s global 对应现在的 -s user。

同名服务器出现在多个作用域时，按 local > project > user 取值。这个规则可以用来在本机覆盖团队配置，例如团队 .mcp.json 里的 github 连远程服务，你在 local 里加一个同名的 Docker 版本做调试。副作用是：团队针对 mcp__github__* 写的权限规则会作用到你覆盖后的那个服务器上，覆盖前要确认工具名一致。

.mcp.json 与项目审批

claude mcp add -s project 会在项目根目录创建或更新 .mcp.json：

stdio 服务器写 command、args、env；远程服务器写 type（sse 或 http）、url 和可选的 headers。

.mcp.json 里的服务器能在你的机器上执行任意代码，所以 Claude Code 不会直接启用它们：

  • 首次进入目录的信任对话框：仓库含 .mcp.json 时，选项是「启用 MCP 服务器并继续」「禁用 MCP 服务器并继续」「退出」。选择启用会把当前所有服务器写进 .claude/settings.local.json 的 enabledMcpjsonServers，同时写入 enableAllProjectMcpServers: true。从此别人在 .mcp.json 里新增的服务器，你 git pull 之后不会再被询问。
  • 后续新增服务器：若没有开启上述总开关，每发现一个新服务器会单独询问，选项是「使用这个及以后所有服务器」「只使用这个」「不使用」。第一个选项同样会打开总开关。
  • 重置：claude mcp reset-project-choices 清空本项目的批准与拒绝记录，下次启动重新询问。

建议的做法：希望逐个把关时，把 .claude/settings.local.json 里的 enableAllProjectMcpServers 改为 false；团队共享的 .claude/settings.json 里不要出现这个字段；.mcp.json 的改动在代码评审里按 CI 配置同等对待。

一次性配置与 CI

--mcp-config <文件或 JSON 字符串> 为本次运行加载额外的服务器，配合 --strict-mcp-config 可以忽略所有其他来源的配置，只用传入的这一份。CI 里跑 claude -p 时这样做能避免被开发者本地或仓库里的服务器影响：

-p 模式下没有人点确认，MCP 工具必须显式放行，否则调用会被拒绝。

三种传输与远程认证

传输 服务器在哪运行 典型认证 适用 注意
stdio 本机子进程，由 Claude Code 启动 环境变量里的 token 本地工具、需要访问本机资源的服务器 子进程继承 Claude Code 的环境变量；启动慢会触发超时
SSE 远程 OAuth 或请求头 只提供 SSE 端点的旧服务 2025-03-26 规范已用 Streamable HTTP 取代 HTTP+SSE；1.0.18 起断线会自动重连
Streamable HTTP 远程 OAuth 或请求头 新的远程服务首选 1.0.27 起支持

同一个服务同时提供两种端点时（例如 Sentry 的 /mcp 与 /sse），选 HTTP。

OAuth 流程

1.0.27 起远程服务器支持 OAuth，1.0.35 补上了授权服务器发现。以 Sentry 为例：

在 /mcp 菜单里选中 sentry 并选择认证，浏览器会打开授权页面，完成后 Claude Code 保存并自动刷新令牌。同一菜单还能查看每个服务器的连接状态、工具列表（含工具注解与标题），以及清除认证。浏览器没有自动打开时，可以手动复制菜单里给出的链接。

OAuth 的好处是令牌不经过你的 shell，也不出现在任何配置文件里，最适合放进 project 作用域共享：.mcp.json 里只有一个 URL，每个人各自授权。

密钥与环境变量：1.0.44 的现实做法

1.0.44 不会展开 .mcp.json 里的 ${VAR}，写进去的就是字面量。团队共享配置又不能带密钥，可用的办法是利用 stdio 子进程的环境继承：Claude Code 启动服务器时使用「自身进程环境 + 配置里的 env」合并后的环境。于是：

  • 非敏感参数（工具集、只读开关）写进 .mcp.json 的 env，随仓库共享；
  • 敏感值（token、DSN）不写进文件，由每个人在启动 claude 的 shell 里提供，可以用 direnv 或从系统钥匙串读取后 export；
  • Docker 启动的服务器用 -e 变量名（不带值），docker 会从自己的环境里取值，而这个环境正是从 Claude Code 继承来的。

两个边界情况：

  • DBHub 读取 DSN 的优先级是命令行参数 > DSN 环境变量 > 启动目录下的 .env 文件。如果项目 .env 里恰好有 DSN，而你的 shell 没有设置，它会连到 .env 指向的库，启动前用 echo $DSN 确认。
  • 远程服务器的请求头无法借助环境继承，这也是它们只适合 local 或 user 作用域的原因；需要团队共享的远程服务，优先选支持 OAuth 的。

权限、资源与提示词

权限规则写法

MCP 工具使用与内置工具相同的 allow / deny 规则，1.0.44 文档给出两种写法：

  • mcp__github：匹配 github 服务器的全部工具；
  • mcp__github__get_issue：只匹配这一个工具。

服务器名是配置里起的名字，不是包名。这也是团队 .mcp.json 值得统一命名的原因：名字一致，.claude/settings.json 里的规则才能对所有人生效。

.mcp.json 已经开了只读模式，deny 里的写工具理论上不会出现，这几条规则是给在 local 作用域另配了可写版本的成员兜底的。

用 hook 留痕

6 月 30 日发布的 1.0.38 加入了 hooks，PreToolUse 的 matcher 支持正则，可以覆盖某个服务器乃至所有 MCP 工具。deny 规则负责禁止，hook 负责留痕，两者分工：

hook 从标准输入收到包含 tool_name、tool_input 的 JSON。脚本以退出码 2 结束时会阻止这次调用，并把标准错误的内容反馈给模型；需要按参数内容拦截（例如禁止查询某些表）时可以在这里实现。

引用资源

输入 @ 时，已连接服务器提供的资源与本地文件一起出现在补全菜单里，格式为 @服务器名:协议://资源路径，例如 @docs:file://api/authentication。引用的资源会被自动拉取并作为附件放进本轮上下文，同一条消息可以引用多个。能引用什么完全取决于服务器实现，以补全菜单列出的为准。

用提示词做斜杠命令

服务器暴露的 prompts 会以 /mcp__服务器名__提示名 的形式出现在斜杠命令列表里，参数以空格分隔跟在后面，例如 /mcp__github__pr_review 456。服务器名和提示名中的空格会被规范化为下划线。它和第 1 篇讲的自定义命令作用相同，区别在于提示词由服务器维护、随服务器版本更新。

输出上限、超时与调试

输出上限

1.0.44 对单次 MCP 工具返回有 token 上限，由环境变量 MAX_MCP_OUTPUT_TOKENS 控制，默认 25000。实现细节：

  • 先按字符数除以 4 粗估，每张图片按 1600 token 计；
  • 粗估超过上限的一半时，调用 token 计数接口精确计算；
  • 超过上限时不截断，而是整条结果作废，模型收到的错误信息会提示它改用分页、过滤或 limit 参数。

因此，数据库、日志、搜索类服务器是否支持分页或结果条数参数，是选型时的硬条件。调高上限（如 MAX_MCP_OUTPUT_TOKENS=50000 claude）能让大结果通过，但这些 token 会一直占着上下文，通常不如在提示词里要求加 LIMIT 划算。

超时

环境变量 作用 默认
MCP_TIMEOUT 服务器启动超时（毫秒） 30000
MCP_TOOL_TIMEOUT 单次工具调用超时（毫秒） 100000000，约 27.8 小时，相当于不限制

Docker 版服务器首次启动要拉镜像，npx 首次要下载包，很容易超过 30 秒。提前执行一次 docker pull ghcr.io/github/github-mcp-server 或 npx 预热，比调大超时更好。远程服务偶尔挂起时，设置一个合理的 MCP_TOOL_TIMEOUT 可以避免会话一直卡住。

排查顺序

现象 检查
服务器没出现在 /mcp 里 claude mcp list 与 claude mcp get <名字> 确认作用域；project 作用域检查是否被拒绝过（disabledMcpjsonServers）
显示连接失败 claude --debug 启动查看服务器报错（旧的 --mcp-debug 已弃用）；把 command 与 args 原样在终端里执行一遍
启动超时 预先拉取镜像或包，必要时 MCP_TIMEOUT=60000 claude
远程服务 401 /mcp 里重新认证或清除认证；请求头方式检查 token 是否过期
模型不调用某个工具 /mcp 查看工具是否已列出；检查是否被 deny 规则覆盖；工具描述含糊时在提示词里点名工具
需要单独调试服务器 用 MCP Inspector（npx @modelcontextprotocol/inspector）脱离 Claude Code 直接调用服务器

按场景选服务器

下表只列在 2025 年 7 月初可用、包名与启动方式已核对的服务器。modelcontextprotocol/servers 仓库里原先的 GitHub、PostgreSQL、Puppeteer、Sentry、Slack、SQLite 等参考实现已移入 servers-archived 归档，不再维护，旧教程里的 @modelcontextprotocol/server-github、@modelcontextprotocol/server-postgres 不要再用。

场景 服务器 接入方式 认证 收紧权限的手段
读 issue、PR、跨仓库搜代码 GitHub 官方 MCP Server（github/github-mcp-server） 远程 https://api.githubcopilot.com/mcp/，或 Docker 镜像 ghcr.io/github/github-mcp-server PAT（请求头或环境变量）；README 也给出了 OAuth 配置 远程在 URL 后加 /readonly 或发送 X-MCP-Readonly: true，按工具集用 /x/<工具集> 路径或 X-MCP-Toolsets；本地用 GITHUB_READ_ONLY=1、GITHUB_TOOLSETS；PAT 用细粒度令牌并限定仓库

排查线上错误 Sentry MCP 远程 https://mcp.sentry.dev/mcp；自建 Sentry 用 npx @sentry/mcp-server@latest --access-token=... --host=... 远程为 OAuth，stdio 为用户令牌 授权账号的组织权限决定可操作范围，用权限最小的成员账号授权

只读查询数据库 DBHub（@bytebase/dbhub），支持 PostgreSQL、MySQL、MariaDB、SQL Server、SQLite stdio：npx -y @bytebase/dbhub@0.10.0 --readonly DSN --readonly 按 SQL 关键字过滤，数据库账号本身也必须只读；提示词要求加 LIMIT，避免超出输出上限
访问项目之外的目录 通常不需要 MCP --add-dir 或 settings 的 additionalDirectories 无 用 Read / Edit 规则控制范围；@modelcontextprotocol/server-filesystem 只在需要与其他 MCP 客户端共用配置时才值得接入

几条选型经验：

  • Playwright MCP 默认用可访问性快照而不是截图驱动页面，不需要视觉模型，适合让 Claude 改完前端后自己点一遍；需要按像素坐标操作时才用 --vision。它默认使用持久化的浏览器 profile，登录态会保存在磁盘上，除非确实需要复用登录，否则加 --isolated。
  • GitHub 服务器的工具集里，context 工具集（当前用户与环境信息）被 README 标为强烈建议开启；其余按需开启，工具越少，模型选工具越准，上下文占用也越小。
  • 数据库场景先问一句：模型真的需要实时查库吗？很多时候导出 schema 文件放进仓库，让它读文件就够了，风险和成本都低一个数量级。

安全清单

MCP 把外部系统的能力和外部系统的文本同时带进了模型的上下文，风险也就有了两个来源。两起公开披露值得每个接入 MCP 的团队读一遍：

  • 工具投毒（Invariant Labs，2025-04-01）：恶意服务器在工具描述里藏入指令，这些文字模型看得到、用户在界面上通常看不到；同文还描述了「rug pull」，即服务器在获得批准后再悄悄更换工具描述。
  • GitHub MCP 数据外泄（Invariant Labs，2025-05-26）：攻击者在公开仓库提交一个带注入指令的 issue，持有广权限令牌的 agent 读取该 issue 后，被诱导读取私有仓库内容，并通过向公开仓库提交 PR 泄露出去。服务器本身没有漏洞，问题出在「不可信输入 + 过宽权限」的组合上。

对应的清单：

  1. 凭据最小化：GitHub 用细粒度 PAT，只授权需要的仓库与只读权限；数据库用专用只读账号。凭据能做的事，就是注入成功后攻击者能做的事。
  2. 能力最小化：优先开只读模式、只开需要的工具集；不常用的服务器不要常驻 user 作用域。每多一个工具，就多一段常驻上下文，也多一个可被诱导调用的入口。
  3. 项目审批当代码评审：.mcp.json 的改动走评审；需要逐个审批时把本地的 enableAllProjectMcpServers 设为 false；团队共享 settings 里不出现这个字段。
  4. 固定版本：npx 包写死版本号，Docker 镜像使用明确的版本标签。@latest 意味着每次启动都可能拿到新代码和新的工具描述，这正是 rug pull 在现实中的样子。远程服务器无法固定版本，定期在 /mcp 里核对工具列表是否有变化。
  5. 不可信输入与写权限不同场：会读取公开内容的服务器（浏览器、公开仓库的 issue、第三方文档）不要和拥有写权限的工具出现在同一会话里。确实需要时，写操作放进 deny，由人来执行。
  6. 密钥不入库：.mcp.json 只放非敏感配置；-H 写入的 token 以明文存在 ~/.claude.json，注意这个文件的权限；永远不要用 -s project 加带 token 请求头的服务器。
  7. 自动化只放行只读工具：claude -p 的 --allowedTools 只列只读的 MCP 工具，CI 里配合 --strict-mcp-config 固定服务器集合。
  8. 留痕：用 PreToolUse hook 记录所有 mcp__ 调用，出了问题能回溯模型在什么输入下调用了什么工具。

2026-09 补记：MCP 这一年的变化

本文示例对应 MCP 2025-06-18 规范与 Claude Code 1.0.44。以下变化会影响文中的做法：

变化 时间与版本 对本文做法的影响
.mcp.json 支持 ${VAR} 与 ${VAR:-默认值} 展开，可用于 command、args、env、url、headers 2025-07-10，1.0.48 「密钥与环境变量」一节的迂回做法不再必要：远程服务器的请求头可以写成 "Authorization": "Bearer ${GITHUB_PERSONAL_ACCESS_TOKEN}" 放进 project 作用域共享
支持 MCP 服务器 instructions 2025-07-15，1.0.52 服务器可以告诉模型何时该用它的工具，配合后面的 Tool Search 更重要
权限规则支持 mcp__server__* 通配；当前 deny / ask 规则还支持 mcp__* 这类工具名通配 2025-12-15，2.0.70 「只有两种写法」已过时，按服务器整体放行或禁止更方便
Plugins 与 marketplace 公测 2025-10-09，2.0.12 插件可在根目录 .mcp.json 或 plugin.json 的 mcpServers 中打包 MCP 服务器，路径用 ${CLAUDE_PLUGIN_ROOT}。启用插件就等于引入它带的服务器，插件要像依赖一样评审
MCP Tool Search 自动模式默认开启：工具描述超过上下文 10% 时延迟加载 2026-01-13，2.1.7 「工具定义常驻上下文」的顾虑大为缓解。当前文档中默认行为已是延迟加载，ENABLE_TOOL_SEARCH 可设为 true、auto、auto:N 或 false；该功能需要支持 tool_reference 的模型（Sonnet 4.5、Haiku 4.5、Opus 4.5 及更新版本），ANTHROPIC_BASE_URL 指向非官方网关时会回退为预加载
支持 elicitation：服务器可在执行中途通过对话框索取结构化输入 2026-03-14，2.1.76 正文所说「服务器无法向你要参数」已不成立；可以用 Elicitation hook 自动应答
企业托管的 MCP 白名单与黑名单 2025-10-17，2.0.22 企业可部署 managed-mcp.json（macOS /Library/Application Support/ClaudeCode/managed-mcp.json，Linux 与 WSL /etc/claude-code/managed-mcp.json，Windows C:\Program Files\ClaudeCode\managed-mcp.json）独占指定服务器集合，或用托管设置中的 managedMcpServers 统一提供、allowedMcpServers / deniedMcpServers 做白名单与黑名单。2.1.83 修复了 --mcp-config 可绕过白名单的问题
SSE 传输在官方文档中标为弃用 — 新接入一律用 HTTP

输出上限也有细化：当前版本在单次输出超过 10000 token 时给出警告，默认上限仍是 25000，MAX_MCP_OUTPUT_TOKENS 继续有效；服务器还可以用 anthropic/maxResultSizeChars 注解为单个工具声明更大的文本上限。

规范与治理层面：

  • 2025-11-25 规范：实验性的 tasks（可轮询、延后取结果的长任务）、URL 模式 elicitation、sampling 支持工具调用、以 OAuth Client ID Metadata Documents 作为推荐的客户端注册方式、支持 OpenID Connect Discovery、工具与资源可携带图标等。
  • 2026-07-28 规范：去掉了会话（session）机制，并把 Roots、Sampling、Logging 标为废弃。正文提到的 Claude Code 通过 roots 告诉服务器工作目录，这一机制在新规范下已不再推荐依赖。Claude Code 2.1.281（2026-09-23）起，在使用 2026-07-28 协议的连接上支持 URL 模式 elicitation。
  • 治理：2025 年 12 月 9 日，MCP 与 AGENTS.md 一起捐入 Linux 基金会旗下的 Agentic AI Foundation（AAIF）。2025 年 12 月 18 日发布的 Agent Skills 开放标准（agentskills.io）是另一条线，不属于 AAIF 项目。

回头看，本文仍然成立的是作用域与审批机制、「先问能否用 CLI」的取舍、只读优先与版本固定的安全原则；需要更新的是密钥处理（直接用 ${VAR} 展开）、权限通配写法，以及对工具数量的顾虑（Tool Search 之后可以放心多接几个服务器，但每个服务器带来的攻击面并没有因此变小）。
