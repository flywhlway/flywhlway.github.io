00 · 架构总览（Architecture Overview）

Enterprise AI Platform · Cloud–Pipe–Edge 一体化 AI Agent 平台
文档类型：架构设计说明书（ADD）总览章 · 版本 1.0

1. 平台定位

本平台是一套端云协同的多智能体（Multi-Agent）AI 应用平台，其核心命题不是”接一个大模型”，而是解决以下四个企业级问题：

  1. 异构入口统一：语音、文本、多模态输入通过统一链路进入统一编排层，避免每个业务方各自对接模型。
  2. 能力资产化：Agent、Skill、Tool（MCP）从”代码里的函数”升级为”平台上可注册、可发现、可鉴权、可计量、可下线的资产”。
  3. 端云分工可切换：同一意图可根据网络、时延、隐私、成本约束，在端侧小模型与云端大模型之间动态落点。
  4. 闭环可演进：埋点回流 → 数据平台 → 评测 → 训练 → 发布，形成可度量的自我改进循环，而不是一次性交付。

1.1 架构定位一句话

一个”注册驱动（Registry-Driven）”的端云协同 Agent 运行时：注册中心定义能力边界，网关层强制统一协议与安全，编排层负责意图到能力的映射，基础能力层（记忆／知识／能力）提供上下文，模型网关负责成本与稳定性，数据平台负责闭环。

4. 十条架构设计原则

# 原则 含义 违反后的典型后果
P1 注册优先（Registry First） 任何 Agent／Skill／Tool 未注册不得被调用 影子能力泛滥，无法审计与下线
P2 网关唯一入口（Single Ingress） 端侧不得直连云端模型或业务服务 认证、限流、审计全部失效
P3 编排与执行分离 Planner 只做决策，不做业务执行 Planner 膨胀为巨石，迭代阻塞
P4 上下文外置（Context as a Service） 记忆／知识由基础能力层统一供给 每个 Agent 自建记忆，用户体验割裂
P5 模型可替换（Model Agnostic） 业务代码不感知具体模型厂商 供应商锁定，无法做成本优化
P6 端云对等降级（Graceful Degradation） 断网／高时延时端侧可独立完成核心任务 隧道／地库场景直接不可用
P7 默认埋点（Telemetry by Default） SDK 内置埋点，业务无需手工记录 无法归因，评测与训练缺数据
P8 安全左右双拦（Bidirectional Guard） 输入侧防注入，输出侧防有害内容 越狱、PII 泄漏、合规事故
P9 成本可归因（Cost Attribution） Token 消耗可下钻到 Agent／会话／用户 成本失控且无法治理
P10 可解释与可干预 记忆与决策链路可视化、可人工回溯修正 用户投诉无法定位，记忆污染无法修复

5. 关键架构决策摘要（ADR Index）

以下为从架构图反推出的关键决策。完整论证见对应专章。

ADR 决策 取舍 详见
ADR-01 采用云／管／端三层强边界，管道层为唯一跨域通道 增加一跳延迟（约 5–15 ms），换取安全与可治理性 02
ADR-02 Planner 独立为服务，而非嵌入各 Agent 引入中心化风险，换取意图口径统一 03 / 07
ADR-03 引入 MCP 作为工具接入标准协议 生态早期规范波动，换取三方能力低成本接入 04 / 11
ADR-04 模型访问统一走 LLM 网关 单点依赖，换取多模型切换与成本治理 11
ADR-05 记忆分层为短期／长期／画像三段 存储与一致性复杂度上升，换取长程个性化 08
ADR-06 RAG 拆分为门户／评测／底座三件套 组织协作成本，换取 RAG 质量可度量 09
ADR-07 端侧部署 SLM 并配套端侧记忆／RAG 车机算力与包体压力，换取离线可用与隐私 07 / 10
ADR-08 端云通道使用双向认证（mTLS + 车辆身份） 证书生命周期管理成本，换取防伪造与防重放 12
ADR-09 流式响应统一为 SSE，而非 WebSocket 只支持单向流，换取穿透性与实现简洁 11
ADR-10 埋点 SDK 内嵌于 Planner 与 Agent 运行时 与运行时耦合，换取 100% 覆盖率 13
ADR-11 存量业务平台通过适配层接入而非重写 保留历史技术债，换取迁移可控 03
ADR-12 安全围栏部署在模型网关之后（出站侧） 增加尾延迟，换取输出可控 12

阶段 核心目标 退出准则（Exit Criteria）
一 · 收口 让所有 AI 流量可见、可管、可停 无旁路调用；Trace 覆盖率 100%；注册中心为唯一能力来源
二 · 闭环 让质量与成本可度量、可优化 RAG 有金标集与回归；缓存命中率达标；Token 成本可下钻
三 · 自演进 让平台自己变好 每次模型／Prompt 变更自动跑回归；反馈数据自动进入训练集

9. 风险登记册（Top Risks）

# 风险 影响 概率 缓解措施 责任域
R1 Planner 成为中心化单点，故障即全站不可用 高 中 无状态多副本 + 规则兜底路由 + 端侧降级 编排域
R2 LLM 网关限流／厂商故障导致雪崩 高 中 多厂商 Fallback + 熔断 + 缓存 + 排队降级 模型服务域
R3 记忆污染（错误记忆被长期固化） 中高 中 记忆置信度 + TTL + 回溯干预 + 人工审核 基础能力域
R4 RAG 幻觉与知识过期 高 高 评测金标集 + 引用强约束 + 知识时效字段 基础能力域
R5 提示注入经三方 MCP 工具返回值进入上下文 高 中 工具输出隔离 + 二次 Guard + 工具最小权限 安全域
R6 端侧 SLM 包体与算力占用影响车机整体体验 中 高 量化 + 按需下载 + 分级降载 端侧域
R7 端云记忆不一致导致回答自相矛盾 中 高 单写者原则 + 版本向量 + 冲突合并策略 基础能力域
R8 Token 成本随 DAU 线性甚至超线性上升 高 高 语义缓存 + 上下文压缩 + 小模型分流 + 配额 模型服务域
R9 证书／密钥生命周期管理缺位 高 中 自动轮转 + 短期证书 + 车辆身份绑定 安全域
R10 存量业务平台适配层演变为新的技术债 中 高 适配层设 Sunset 日期 + 能力逐步迁入注册中心 治理域

10. 本文档集的核心结论（前置）

  1. 这张图的本质是治理架构，不是模型架构。 图中被圈注的六处全部属于治理／可观测／成本／质量／安全，模型本身反而被抽象成网关后的可替换资源。这是成熟企业 AI 平台的正确形态。
  2. 最大的架构杠杆在”上下文供给”而非”模型选择”。 记忆中心 + 知识中心 + 能力中心三者决定了 80% 的效果差异，模型换代带来的增益远小于上下文质量提升。
  3. 端云协同的关键不是”都做一遍”，而是”落点决策”。 边缘 Agent 框架与端侧模型路由的价值，在于把落点决策变成可配置策略而非硬编码。
  4. 最容易被低估的风险是记忆污染与端云一致性。 这两项不会在 Demo 阶段暴露，会在上量后集中爆发，必须在阶段一就预留回溯干预能力。
  5. 闭环是唯一护城河。 埋点 → 评测 → 训练的飞轮一旦建成，平台效果会持续拉开与”直接调 API”的差距。
