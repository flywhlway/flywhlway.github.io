1.1 系统边界原则

边界 内 外 跨界唯一通道
端 ↔ 管 端侧运行时 云端服务 语音网关 / Agent 网关 / 双向认证网关
管 ↔ 云 网关层 编排与能力层 内网服务网格（mTLS + 服务身份）
平台 ↔ 模型 平台自研组件 模型供应商 LLM 网关（唯一出口）
平台 ↔ 工具 平台运行时 三方能力 MCP 注册中心 + 能力中心

3. 层间契约（Interface Contracts）

契约是分层架构能否长期成立的唯一保障。以下为推断设计的最小契约集。

3.1 端 → 管：请求契约

字段 类型 说明
trace_id string 全链路唯一 ID，端侧生成，贯穿到训练数据
session_id string 会话 ID，决定短期记忆边界
device_identity object 设备／车辆身份声明（由 mTLS 证书派生，不可自填）
user_ref string 用户匿名标识（非明文身份）
modality enum audio / text / image / mixed
payload object 原始输入或 ASR 文本
local_context object 端侧上下文快照（当前场景、可用能力、网络质量）
capability_hint array 端侧已知可用能力列表（用于落点决策）
privacy_flags object 数据可上云范围声明

3.2 管 → 编排：编排请求契约

字段 说明
normalized_text NLU 归一化后的文本
nlu_slots 预抽取的槽位（可为空，Planner 可覆盖）
context_bundle_ref 上下文包引用（避免大对象在链路中反复搬运）
budget 本次请求的时延／Token／成本预算
degradation_level 当前允许的降级等级

3.3 编排 → 模型网关：推理契约

字段 说明
model_intent 语义化模型意图（如 chat.long／classify.fast／vision.describe），不指定具体模型
messages 标准消息数组
tools 由能力中心裁剪后的工具集（含权限声明）
cache_policy 语义缓存策略（prefer／bypass／only）
guard_profile 出站围栏配置档位
cost_tag 成本归因标签（业务／Agent／场景）

关键设计（P5 模型可替换）：编排层只声明 model_intent，具体模型由网关按策略决定。这使得”换模型”是网关配置变更，而非业务代码变更。

3.4 基础能力层：上下文包（Context Bundle）契约

段 内容 大小预算（推断设计）
short_term 最近 N 轮对话摘要 ≤ 1500 token
long_term 相关长期记忆条目（带置信度） ≤ 800 token
profile 用户画像切片（仅本次意图相关字段） ≤ 300 token
knowledge RAG 检索片段（带引用元数据） ≤ 3000 token
capability 可用工具与技能描述（渐进式披露） ≤ 1200 token
system 系统指令与安全策略 ≤ 600 token

总预算控制在约 7.4k token 以内，为回答与工具调用留足空间。上下文预算必须显式管理，否则会出现”检索越多效果越差”的典型退化。

5.1 部署要点

组件 部署形态 弹性策略 有状态性
Planner K8s Deployment，多 AZ HPA（QPS + P95 延迟双指标） 无状态
Cloud Agents 每 Agent 独立 Deployment HPA + 按 Agent 独立配额 无状态（状态外置）
LLM 网关 Deployment，独立 namespace HPA + 连接池预热 半状态（缓存）
记忆服务 Deployment + Redis/PG/向量库 读写分离 有状态
知识服务 Deployment + 向量库 检索副本扩容 有状态
Guardrail Sidecar 或独立服务 与网关同比例扩容 无状态
注册中心 Deployment + PG 低 QPS，重可用性 有状态
端侧运行时 车机内进程／容器 分级降载 有状态（本地）

反模式提醒：不要把 Guardrail 做成”和模型网关共进程”的库调用。当 Guardrail 需要独立升级策略、独立模型时，进程内耦合会导致模型网关频繁重启。推荐 Sidecar 或独立服务 + 本地短超时。

6. SLO 与容量模型（推断设计）

6.1 SLO 分解

端到端 TTFT P95 ≤ 1200 ms 的预算分解：

环节 预算 说明
端侧采集与本地处理 80 ms VAD + 编码
端 → 网关网络 60 ms 4G/5G 平均
ASR + NLU 220 ms 流式 ASR 可与后续并行
网关校验（认证＋入站安全） 40 ms 内容安全需异步或轻量模型
Planner 意图分类 120 ms 小模型或分类器，禁用大模型
上下文并行拉取（记忆＋知识＋能力） 250 ms 三路并行，取最慢
Prompt 组装 30 ms
语义缓存查询 25 ms 向量检索
模型首 token 320 ms 供应商 P95
出站围栏（首包） 35 ms 流式分段校验
回传网络 60 ms
合计 1240 ms 超出 40 ms，需在意图分类与检索环节压缩

架构洞察：延迟预算表比架构图更能暴露设计问题。上表显示”上下文拉取 250 ms + 意图分类 120 ms”合计占 30%，这正是语义缓存与端侧预判价值最高的地方——命中缓存可直接省掉 700 ms 以上。

6.2 容量模型示例

参数 取值（示例）
日活设备数 100 万
人均 AI 会话数／日 3
人均轮次／会话 4
日请求量 1200 万
峰均比 4:1（早晚高峰）
峰值 QPS ≈ 555
单请求平均 Token（输入＋输出） 3500
峰值 Token/s ≈ 194 万
缓存命中率 30%
实际打到模型的峰值 Token/s ≈ 136 万

该量级下，语义缓存每提升 5 个百分点命中率，约等于省掉 10% 的推理算力预算。这是模型服务层最高 ROI 的优化项。

7. 降级矩阵（Degradation Matrix）

故障场景 检测方式 降级动作 用户可感知程度
外部模型超时 网关熔断器 切换备用模型 → 切小模型 → 语义缓存近似回答 低（措辞变化）
全部云端模型不可用 网关健康检查 下发”端侧兜底”指令，端侧 SLM 接管 中（能力受限）
知识中心不可用 熔断 跳过 RAG，纯模型回答并声明”未检索到资料” 中
记忆中心不可用 熔断 退化为无状态单轮对话 中（失去个性化）
能力中心不可用 熔断 使用本地缓存的工具清单快照 低
Planner 不可用 网关健康检查 规则路由兜底（关键词 → 固定 Agent） 中
Guardrail 不可用 熔断 不降级，直接拒绝输出（安全优先） 高（但必须）
网络中断 端侧探测 端侧全离线闭环 中
注册中心不可用 熔断 各服务使用本地能力快照，禁止新能力上线 无

原则：性能类组件（缓存、知识、记忆）可降级；安全类组件（Guardrail、认证）不可降级。这条区分必须写入运维手册，否则会出现”为了可用性把围栏关掉”的重大事故。

8. 可扩展性设计

扩展维度 扩展点 实现方式
新增业务 Agent 注册中心 + 能力中心 注册元数据 + 独立部署，Planner 无需改代码
新增工具 MCP 注册 三方以 MCP Server 形式接入，走审核流程
新增模型 LLM 网关策略 增加 provider 配置 + model_intent 映射
新增模态 输入融合层 增加模态编码器，统一为 Context Bundle
新增区域 多集群 网关就近接入 + 记忆知识按区域分片
新增端侧硬件 边缘 Agent 框架 抽象算力等级，按等级下发模型与策略

9. 风险与演进

风险 架构层面的对策
层级过多导致延迟累积 上下文并行化、缓存前置、端侧预判；每层设强制延迟预算并监控
契约漂移（各层自行加字段） 契约以 Schema 仓库集中管理，CI 校验，破坏性变更需版本化
网关成为瓶颈 网关无状态化 + 水平扩容 + 连接复用；重计算（内容安全）异步化
端云能力版本不一致 边缘 Agent 框架下发能力清单版本号，端侧按版本协商

演进方向（推断设计）

  1. 短期：把延迟预算表变成线上看板，逐环节压缩；契约进 Schema Registry。
  2. 中期：把落点决策从”规则”升级为”学习型策略”（用历史 Trace 训练落点分类器）。
  3. 长期：把 Planner 从”单点服务”演进为”编排层 + 可插拔策略”，支持多 Planner 并行 A/B。
