六、Rebase 冲突 vs Merge 冲突

对比 Rebase Merge
冲突次数 可能多次（每个 commit） 通常一次

七、最佳实践（关键）

✔ 推荐

  • 小步提交（减少冲突难度）

  • rebase 前先 git fetch

  • 使用 pull --rebase

❌ 避免

  • 在公共分支 rebase

  • rebase 已 push 的历史（除非强推）

八、一句话总结

Rebase 冲突处理 = “逐 commit 重放 + 每次冲突都要手动解决”

以下为一套 团队级 Git 提交流程最佳实践（接近大厂规范），覆盖 分支模型 → 提交流程 → PR 规范 → 发布策略 → 风险控制。

一、核心原则（必须统一）

  1. 主干始终可发布（main 永远稳定）

  2. 所有开发必须走分支

  3. 禁止直接 push 主分支

  4. 必须通过 PR + Code Review

  5. 提交历史清晰（线性优先）

二、分支模型（推荐：简化版 Git Flow）

1. 主分支说明

分支 作用 权限
main 生产代码 禁止直接提交
develop 集成测试（可选） 团队共享
feature/* 功能开发 个人分支
hotfix/* 紧急修复 高优先级
release/* 发布准备 短期存在
