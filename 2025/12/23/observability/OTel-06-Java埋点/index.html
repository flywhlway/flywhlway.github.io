06 · Java 侧埋点：Spring Cloud Gateway + Nacos 微服务

Java 控制面（网关、编排、管理服务）与 Python 执行面必须共享同一条 Trace。本篇给出两条埋点路线的完整配置、跨语言链路透传验证方法、以及日志三件套关联。基准：JDK 21 + Spring Boot 3.5.x + Spring Cloud Alibaba（Nacos 服务发现）。

1. 两条路线怎么选

路线 原理 优点 代价 适用
A. OTel Java Agent -javaagent 字节码增强，零代码 覆盖面最广（Servlet/WebFlux/JDBC/Kafka/Redis/gRPC 200+ 库），三信号齐全 启动稍慢、黑盒 默认推荐，存量服务批量接入
B. Micrometer Tracing 桥接 Spring Boot 原生 Observation API → OTel 导出 白盒、与 Spring AI 观测体系同源、可精细定制 只管 Trace/Metrics，日志需另配；覆盖面依赖 starter 新建服务、需要 Spring AI gen_ai 观测时

两条路线产出的都是标准 OTLP，可在同一集群混用（但同一服务只能选一条，避免重复 Span）。

4. Spring Cloud Gateway 的链路职责

SCG 在链路中承担「入口 Span + 上下文透传」职责，无论路线 A/B 均自动完成 W3C Trace Context 传播。需要人工确认的三点：

  1. 自定义 GlobalFilter 不要吞头：转发时保留 traceparent/tracestate/baggage 请求头；
  2. 路由级属性增强（可选）：
  1. Baggage 透传业务标识：user.id / session.id 放入 Baggage 后，Python 侧与 Langfuse 均可消费（文档 08 §4）。

6. Nacos 相关注意事项

  • Nacos 客户端心跳/配置轮询会产生大量低价值 Span，用 Agent 参数抑制：
    -Dotel.instrumentation.common.default-enabled=true -Dotel.instrumentation.okhttp.enabled=false（按实际客户端库微调），或在 Collector 用 filter 处理器按 url.path =~ "/nacos/" 丢弃；
  • 服务实例元数据建议写入 Resource：-Dotel.resource.attributes=...,nacos.cluster=替换点(项目方)，便于按集群维度聚合。

7. Spring AI 服务的 GenAI 观测（Java 侧 LLM 调用）

Java 服务直接调用 LLM（如经 Spring AI 调 DashScope/DeepSeek）时，Spring AI 内置 Observation 会产出 gen_ai.* Span 与指标：

如需把 Prompt/Completion 写入 Span 属性（供 Langfuse 展示），注册 ChatModelCompletionContentObservationFilter／ChatModelPromptContentObservationFilter 为 @Component。该链路与 Python 侧产出的 gen_ai.* 属性同构，Tempo/Langfuse 查询语句完全复用。

8. 验收清单

  • SCG 与 diag-agent 出现在同一条 Trace（trace_id 一致）；
  • Grafana 服务拓扑图（Tempo service graph）出现 scg-gateway → diag-agent 边；
  • Loki 中 Java 日志携带 trace_id，与 Tempo 双向互跳成功；
  • Prometheus 出现 http_server_request_duration_seconds（或 Agent 版 http.server.request.duration）与 JVM 指标；
  • Nacos 心跳类噪声 Span 已抑制。
