按顺序做 4 个请求，每次都要观察日志是否出现相应记录：

  1. 服务器本机：直打 NPM
  2. 服务器本机：直打 nginx-core
  3. 服务器本机：从 npm 容器打 nginx-core
  4. 外网：打域名

如果 1/2/3 都通，4 不通 → 99% 在 DNS/Cpolar/防火墙
如果 1 通但 3 不通 → Docker 网络
如果 3 通但外网访问 502 → NPM Proxy Host / SSL / Host 匹配

最常见 6 个“致命卡点”速查

  1. Cpolar 用了 proto: http 而不是 proto: tcp（443 必须 tcp）
  2. 域名没在 Cpolar 控制台正确绑定到隧道（或泛域名套餐不支持）
  3. 宿主机 443 被宝塔/nginx 占用，NPM 映射失败
  4. NPM/ nginx-core / app-main 不在同一个 backend_net 网络
  5. NPM Proxy Host 域名填错（实际访问 host 和配置不一致）
  6. nginx-core 的 server_name 不匹配导致落到 default server

  • 防止：
    • .txt 被当成 JS 执行
    • 上传文件被错误解析
  • 同源：完整 referrer
  • 跨域：只发域名，不发路径
  • 防止 /admin?token=xxx 泄露

invalid symlink "/tmp/.../fullchain.pem" -> "../../archive/npm-1/fullchain1.pem"

这是 Let’s Encrypt 的正常结构：live/npm-1/fullchain.pem 本来就是个 symlink 指向 ../../archive/npm-1/fullchain1.pem。
但 docker cp 在某些情况下（尤其是拷到临时目录、或跨文件系统/权限/安全策略）会拒绝这种相对 symlink，导致你现在的报错。

✅ 解决方案很简单：不要拷 live/ 里的 symlink 文件，而是直接从 archive/ 拷贝“真实文件”，或者在容器内把 symlink 解引用成真实内容再输出。
