02 · GenAI 语义约定与 AI 可观测标准

gen_ai.* 语义约定是整个 AI 可观测体系的数据契约：SDK 按它埋点，Collector 按它路由脱敏，Tempo/Langfuse/Grafana 按它检索与算成本。本篇给出 2026-07 时点的权威属性清单、Span 建模方式与版本迁移策略。

1. 现状与版本策略（务必先读）

  • GenAI 语义约定由 GenAI SIG 维护，2026 年起迁移至独立仓库 open-telemetry/semantic-conventions-genai，覆盖 GenAI 客户端 Span/Metrics/Events、MCP、以及 OpenAI 等 Provider 特定约定。
  • 截至 2026-05，GenAI 与 MCP 约定仍处于 Development（实验）状态，属性名仍可能调整；但客户端 Span 与 Token 指标在实践中已高度稳定，Datadog/Honeycomb/Grafana/Langfuse 均已原生消费。
  • v1.36.0 是迁移基线：既有埋点库默认继续输出旧版属性；通过环境变量切换到最新版：

新旧属性对照（工程中最常踩坑的三组）：

旧（≤ v1.36 / 社区惯用） 新（latest experimental）
gen_ai.system gen_ai.provider.name
gen_ai.usage.prompt_tokens / completion_tokens gen_ai.usage.input_tokens / output_tokens
gen_ai.prompt / gen_ai.completion（事件） gen_ai.input.messages / gen_ai.output.messages（结构化）

工程建议：平台内部统一锁定一个版本（建议直接 opt-in 最新版），并在 Collector 用 transform 处理器做旧→新映射兜底（见文档 03 §5），避免多语言 SDK 版本漂移导致同一含义两套属性名。

2. Span 建模：AI 链路的六类 Span

2.1 推理 Span（Inference）

每次 LLM 调用生成一个 Span，命名规则 {gen_ai.operation.name} {gen_ai.request.model}，如 chat deepseek-chat；SpanKind 为 CLIENT（远程模型）或 INTERNAL（进程内模型）。

核心属性：

属性 示例 说明
gen_ai.operation.name chat / text_completion / generate_content / embeddings 操作类型判别器
gen_ai.provider.name deepseek / openai / anthropic Provider 判别器，决定伴随哪些厂商特定属性
gen_ai.request.model deepseek-chat 请求的模型
gen_ai.response.model deepseek-chat-20260601 实际响应的模型（灰度/路由后可能不同）
gen_ai.usage.input_tokens 1834 输入 Token
gen_ai.usage.output_tokens 412 输出 Token
gen_ai.response.finish_reasons ["stop"] / ["tool_calls"] 停止原因，排查截断/循环的关键
gen_ai.request.temperature 等 0.2 采样参数族 gen_ai.request.*
error.type 429 / TimeoutError 低基数错误标识

2.2 Embedding 与检索 Span

  • Embedding：gen_ai.operation.name=embeddings，附 gen_ai.request.encoding_formats；
  • RAG 检索：gen_ai.data_source.id 标识数据源（Milvus collection、文档库等），gen_ai.retrieval.documents 以结构化形式记录召回文档（必须遵循官方 JSON schema）。

2.3 工具执行 Span（execute_tool）

注意：工具内部的真实动作（HTTP 调用、SQL、向量检索）应作为子 Span 由常规埋点产生，而不是塞进工具 Span 属性里——这样服务拓扑图才能反映工具的真实依赖。

2.4 Agent Span（invoke_agent / 编排层）

属性 说明
gen_ai.agent.name / gen_ai.agent.id Agent 标识（如 vehicle-diag-agent）
gen_ai.agent.description 自由文本描述
gen_ai.conversation.id 会话标识，跨请求聚合多轮对话

LangGraph 一次图执行的典型结构：invoke_agent 根 Span → 每个 node 一个子 Span → node 内的 LLM/tool 调用再下一层。这是多数生产 Agent 排障的主战场——只埋 LLM Span 会漏掉规划、节点间路由、子 Agent 交接等真正的耗时点。

2.5 MCP Span

MCP 约定与 GenAI 约定同仓维护：工具发现、tools/call 调用、参数与结果均有标准属性，Higress/agentgateway 等网关已可代理并自动产出 MCP Span。当前同样处于 Development 状态，命名以独立仓库为准。

2.6 评测（Evaluation）

gen_ai.evaluation.name / gen_ai.evaluation.score.value / gen_ai.evaluation.score.label 用于把 LLM-as-Judge 或人工评分回写到链路。实践中评测通常在 Langfuse 侧完成（见文档 08），OTel 侧约定用于跨平台交换。

3. 标准指标（Metrics）

指标 类型 关键维度 用途
gen_ai.client.token.usage Histogram gen_ai.token.type(input/output)、gen_ai.request.model、gen_ai.provider.name Token 用量与成本归因
gen_ai.client.operation.duration Histogram 同上 + error.type LLM 调用时延分布/错误率
gen_ai.server.time_to_first_token Histogram 模型服务端（vLLM 等）暴露 TTFT

4. 内容捕获（Prompt/Completion）与隐私

默认不捕获消息内容，只记录元数据（模型、Token、耗时）。按需开启：

内容捕获的三种落地形态（约定均支持）：

  1. 属性内联：内容作为 Span 属性（JSON 字符串或结构化），适合 POC 与低敏场景；
  2. 事件（Events/Logs）：内容作为与 Span 关联的 Log Record，便于单独设置留存与访问控制；
  3. 外部存储引用：Span 只存对象存储 URI，适合大内容/强合规场景。

纵深防御三层（生产必做，详见文档 10）：

  • SDK 层：非必要不开启内容捕获；
  • Collector 层：redaction 处理器做白名单属性保留 + transform 处理器 OTTL 正则脱敏（手机号/VIN/身份证）；
  • 后端层：Tempo/Langfuse 访问控制，缩小泄露爆炸半径。

6. 本章小结与自查清单

  • 全平台锁定 GenAI 约定版本（建议 OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental）；
  • 六类 Span（推理/Embedding/检索/工具/Agent/MCP）均有归属，Agent 编排层不缺埋点；
  • Token 指标进入 Prometheus，成本可按 模型 × 租户 × 路由 归因；
  • 内容捕获默认关闭，开启场景有脱敏与访问控制方案；
  • 私有属性使用 aits.* 前缀，不占用 gen_ai.* 命名空间。
