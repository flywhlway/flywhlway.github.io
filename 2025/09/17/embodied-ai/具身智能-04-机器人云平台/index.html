4.1 平台总体架构

4.1.1 设计目标与量级假设

设计基线（对标头部玩家的中期量级）：1 万台机器人、200 个站点、单机聚合遥测 5Hz×1KB。由此推出的容量数字要刻在架构上：遥测稳态 ≈ 50MB/s（Kafka 按 robot_id 分区轻松承接）；触发式 bag 回传日均 TB 级（对象存储 + 生命周期分层）；模型 OTA 单次全量 = 1 万台 × 2~8GB（分发网络是一等公民，不是附属功能）。非功能目标：接入面区域化多活、控制面可私有化交付、单站点断云 72 小时业务自治。

4.1.2 七大平面

把 1.2.2 的七职责工程化为七个平面：接入面（南向连接与协议）、设备面（身份/影子/生命周期）、OTA 面（制品/编排/灰度/分发）、数据面（遥测管道与数据引擎）、任务面（Fleet 调度与任务引擎）、AI 面（模型/Agent/知识/记忆服务）、治理面（安全/可观测/配置，横切）。平面即团队边界与 SLA 边界——与你划分 TSP 域的方法一致。

4.2 设备管理与身份：机器人的一生

4.2.1 设备模型

概念 定义 产业物联网对应
Robot ID 平台唯一逻辑身份（证书 CN、命名树根、数据分区键） VIN
SN / 硬件指纹 本体序列号 + 关键部件序列号 车辆 SN/零部件追溯
型号 / 硬件版本 决定兼容矩阵的机型标识 车型/配置字
Device Profile 该型号的能力描述：话题清单、任务集、资源规格 车型信号矩阵

Device Profile 是「一套平台接万种设备」的关键抽象（呼应 1.3.8）：平台代码面向 Profile 编程，车与机器人只是两份 Profile。

4.2.2 身份根：产线预置与两级 CA

PKI 结构：离线根 CA →（按产品线的）中间 CA → 设备证书（CN=Robot ID，产线安全工位签发并写入安全存储，理想落位 TPM/SE，第九篇深化）。证书即出生证：没有产线证书的设备永远进不了平台——信任锚定在制造环节，与你们 TBox 产线灌装证书完全同构。轮换策略：设备证书短周期（如 1 年）自动轮换，中间 CA 可按产品线吊销止损。

4.2.3 注册与激活时序

4.2.4 连接与在线判定

在线状态用三信号合成，任何单一信号都会说谎：MQTT 会话 + 遗嘱消息（连接层）、遥测心跳新鲜度（数据层）、机内 Liveliness 汇总（2.14 的 QoS 事件经云桥上报，业务层）。合成规则示例：连接在 + 心跳新鲜 = 在线；连接在 + 心跳超时 = 假死（连接层活着业务层死了，单靠遗嘱永远发现不了——你在产业物联网踩过的同款坑）。会话侧：EMQX 持久会话 + 云桥离线队列，弱网断续不丢关键上行。

把「激活即绑定配置基线」做成硬门禁：任何设备激活时必须落到唯一的机型基线 + 站点覆盖（2.17 三层的云端版），杜绝「裸设备」入网——配置漂移的治理从激活那一刻开始。

4.2.8 面试可能问什么

  1. 设计万台机器人的身份体系。（要点：两级 CA、产线锚定、CN=Robot ID、轮换与吊销）
  2. 在线状态为什么不能只看 MQTT 连接？（要点：三信号合成与假死场景）
  3. 生命周期状态机如何与其他平面联动？（要点：维护暂停 OTA/任务、退役吊销归档）

4.2.9 最佳实践

  • Robot ID 一处签发、处处引用（证书 CN、命名树、MQTT ClientID、数据分区键、日志字段）——身份一致性是全平台追踪的地基。
  • 激活接口做防重放与防克隆（硬件指纹核对 + 一次性激活票据）。

4.2.10 常见误区

  • ❌ 用自增 ID/随机 UUID 当 Robot ID 而与证书脱钩——身份与信任分离，后患全在安全审计时爆发。
  • ❌ 在线判定只做连接层——「连着的死设备」将污染 Fleet 调度与灰度批次选择。

4.2.11 Obsidian 永久笔记

  • 信任锚在产线：两级 CA + 出生证书，无证不入网。
  • 三信号在线判定：连接 + 心跳 + 机内 Liveliness，识破假死。
  • 生命周期即运营代码化：状态迁移挂钩平台动作。

4.3.3 制品管理：版本、签名与兼容矩阵

制品三要素：不可变版本（内容寻址 + 语义化版本）、签名链（制品签名密钥由治理面 KMS 托管，端侧验签根预置，第九篇闭环到 Secure Boot）、SBOM（依赖清单随制品归档，供应链审计的原料）。兼容矩阵是 OTA 事故的第一道闸：硬件版本 × 固件版本 × 模型版本 × 配置基线 的合法组合表，升级计划生成时静态校验、端侧安装前再动态校验——你们「车型-固件兼容表」的四维扩展版。

4.3.4 分发网络：GB 级载荷到万台边缘

四级瀑布：中心制品库 → CDN → 站点边缘缓存（一个站点只从公网拉一次）→ 站内 P2P/局域网直拉（几十台机器人互为种子）。端侧协议要素：分片下载 + 每片校验和 + 断点续传 + 带宽限速（不与业务流量抢路）+ 充电窗口调度。账要算给管理层听：1 万台 × 4GB 模型，无边缘缓存 = 40TB 公网流量/次；有站点缓存 = 200 站 × 4GB = 0.8TB——分发网络的 ROI 是两个数量级。

4.3.5 端侧 OTA Agent 设计

Agent 即第三篇 task_executor 的产品化：以 RobotTask(ota) 承接任务（审核门 = 兼容矩阵 + 升级窗口条件：充电中/无任务/电量>50%/磁盘余量），执行体按载荷分派——固件走 A/B 分区（bootloader 回滚计数，启动失败自动切回）；模型走双缓冲热切换：新权重下载校验 → 加载到备用槽位 → 本地健康自检（固定样例推理比对）→ 原子指针切换 → 观察期通过后释放旧槽——全程不打断任务间隙以外的作业。Agent 自身必须 Lifecycle 受管（2.12.6）且自升级用最保守通道（双镜像 + 看门狗）。

  CMP -->|达标| RING["灰度环：内部机 → 1% → 10% → 50% → 全量"]
  RING --> BAKE["每环烘烤期：任务成功率/干预率/崩溃率门禁"]
  BAKE -->|门禁破| RB["自动回滚 + 冻结批次 + 采样回传现场 bag"]
  BAKE -->|全环通过| GA["转正为机型基线版本"]

影子模式的机器人版实现：备用槽位加载新模型，与在役模型消费同一传感器流，仅记录输出不驱动执行器；分歧样本按 2.21.4 触发式回传——Tesla 影子模式的完整同构，你对这套飞轮的每个环节都有对应经验。

4.3.7 灰度发布引擎

批次维度四件套：站点（故障影响面隔离）、机型/硬件版本（兼容矩阵切片）、健康分（孪生数据算出的设备体检分，低分设备排后）、业务时段（站点作业日历避峰）。门禁指标建议基线：任务成功率跌幅 >2%、人工干预率升幅 >50%、崩溃/重启率异常、E-Stop 触发数——任一破线即自动回滚 + 冻结后续批次 + 拉取现场证据。与车队分批发布唯一的实质差异：指标从「车机崩溃率」换成「物理作业质量」，回滚的紧迫性更高。

4.4 数字孪生

4.4.1 三层孪生模型

L1 影子（Shadow）：desired/reported 两份 JSON 的收敛机制——运行态的真相源；L2 孪生（Twin）：影子 + 静态结构（URDF/标定/硬件清单/证书）+ 历史轨迹（遥测仓）——设备的全息档案；L3 仿真孪生：结构与场景进 Isaac（第八篇）——可推演的副本。平台建设顺序严格 L1→L2→L3，绝大多数运营价值在前两层。

4.4.2 影子收敛循环

flowchart LR
  OPS["平台侧写 desired（目标配置/版本/模式）"] --> SH["影子服务（Redis 热 + PG 持久）"]
  SH -->|"delta 下发"| BR["云桥"]
  BR --> RB["端侧应用（Parameter/OTA Agent）"]
  RB -->|"reported 上报"| SH
  SH --> DIFF["delta = desired − reported"]
  DIFF -->|"未收敛→重试/告警"| SH
  DIFF -->|"收敛"| DONE["状态一致 ✅"]

要义三条：平台永远写 desired、设备永远写 reported（单向写权限杜绝状态打架）；delta 驱动而非命令驱动（断线重连后自动补收敛，天然幂等）；收敛超时即告警（配置漂移的实时探测器）。这就是你们车辆影子的机制原文——机器人多出来的只是 reported 里的字段（关节/任务状态/模型版本）。

4.7 任务面：Fleet 调度与任务引擎

4.7.1 四层任务模型（先定分层，再谈调度）

flowchart TB
  O["L1 业务订单：『今晚盘点 A 区』（运营系统所有）"] --> F["L2 Fleet 任务：分解+选机+排程（Fleet 调度器所有）"]
  F --> R["L3 机器人任务 RobotTask：单机可执行单元（任务引擎所有）"]
  R --> S["L4 技能/Action：端侧原子能力（机器人本体所有）"]

每层独立状态机、独立重试语义：订单可部分完成、Fleet 任务可换机重派、RobotTask 可取消重发、技能失败向上抛错误码。层间只传「目标与结果」，不传「过程」——与你的「订单系统 → 车队调度 → 远程指令 → 车端执行」四层完全同构，评审时可直接套用同一套边界话术。

4.7.2 Fleet 调度器：资源感知分配 + 任务租约

分配 = 以孪生为输入的匹配问题。输入字段：位置（就近）、电量（够不够干完+返程）、能力（Device Profile 声明的技能集）、健康分（低分不派活）、当前负载与作业日历。策略从简到繁：最近可用 → 加权评分 → 批量优化（高峰期整批求解）。**任务租约（lease）**是可靠性核心：派发即发租约，机器人周期续租；失联超租约 → 任务自动回收重派（幂等靠 task_id + 端侧「重复任务去重」）——这就是消费组 rebalance / 你们远程指令超时重派的机器人版。

4.7.3 任务引擎：Temporal 承载长任务

L2/L3 的执行体落在 Temporal 工作流：天然获得重试、补偿、暂停、人工介入、超时与全程可视化。典型工作流：盘点任务 = 前置检查(孪生) → 下发 RobotTask → 监听回执流 → 异常分支(换机重派/人工介入) → 产物归档(盘点结果+bag引用) → 闭单。与 OTA 编排（4.3.2）共用同一引擎与运维技能——平台里所有「长事务」只养一套工作流基础设施。

4.7.4 地图与场景管理：地图即制品

站点地图（占用栅格/语义层：禁行区、充电桩、电梯、闸机、作业点位）按制品治理：版本化、签名、走 4.3.4 分发网络下发、孪生记录 reported 地图版本。语义层是任务面的坐标真相源：Fleet 任务里的「A 区」由语义地图解析为位姿目标。地图更新走灰度（先一台机器人验证再全站）——把 OTA 的所有纪律复用到地图上，不另起炉灶。

4.7.5 多机协同：两级分界

任务级协同（云端）：错峰排程、分区作业、共享资源调度——电梯/闸机/窄通道建模为「带租约的资源锁」，云端排队授予、超时回收；运动级协同（本地）：实时避碰、会车让行——毫秒级，走机内感知与局部通信，绝不依赖云端（能力放置铁律的协同版）。断云降级：资源锁失联时端侧按保守规则（停等/绕行）自治，恢复后向云端对账。评审否决项：任何把实时避碰放到云端闭环的方案。

4.8.2 日志体系：三键结构化

端侧结构化日志（JSON）强制三键：robot_id / task_id / trace_id——加上节点名与错误码即可全链路串查。流转三通道：本地轮转（常态只留端上）、诊断会话按需拉取（工程师视角）、触发式伴随上传（bag 触发时同窗口日志一并打包，2.21.4 的孪生兄弟）。全量日志上云在万台规模是成本灾难——日志的默认归宿是端上，云端只存索引与被召回的片段。

4.8.3 OTel 三支柱：Trace 贯通云—边—端

Trace 语义：一次 L2 任务 = 一条 Trace。traceparent 从运营 API 进入 Temporal，随 RobotTask 的 JSON 载荷穿过 MQTT 到云桥，云桥把它注入 Action Goal 与端侧日志上下文；端侧各节点耗时以轻量 span（或打点事件）随遥测异步上报，云端按 trace_id + task_id 拼装完整火焰图。你 Langfuse/OTel 的采样、上下文传播、异步拼装经验全部适用——机器人特殊点只有一个：端侧 span 走「异步上报+云端拼装」而非直连 Collector（弱网与算力所迫）。

4.9 边缘节点管理

4.9.1 站点边缘三职责

每个站点部署一套轻量边缘（1~3 台服务器，K3s）：职责一：制品与数据缓存——OTA 分发网络的站点级（4.3.4）、地图副本、遥测/bag 断网缓冲；职责二：推理池——站内共享 GPU 承接秒级容忍的 AI 负载；职责三：断云自治——云端不可达时维持站点作业。边缘不做的事同样明确：不做训练、不做全局调度、不长期存明细数据——边缘是缓存与执行的延伸，不是小号云。

4.9.2 边缘集群管理：GitOps 拉到 200 个站点

推送式管 200 个集群必死于网络与规模；正确姿势是 GitOps 拉模式：每站点 K3s 内驻 Argo CD（或 Fleet）Agent，拉取 Git 中该站点的 desired state（应用版本 + 站点 values），本地收敛并上报状态——与设备影子同一哲学，只是对象从机器人换成集群。配套两件事：制品预热（OTA/地图计划创建时由预热工作流提前推到站点缓存，发布窗口只做本地分发）；边缘也进孪生（站点级 reported：K3s 健康、GPU 水位、缓存命中率），纳入 4.8.5 的站点大盘。

4.10.2 AI Gateway：唯一入口

网关五件事：认证与配额（按租户/站点/用途计量）、模型路由与降级链（云大模型 → 边缘小模型 → 规则兜底，路由表来自模型注册表的部署位置矩阵）、语义缓存（站点 SOP 类高重复问答命中率极高）、内容与工具调用审计（每次工具调用留痕，第九篇安全闭环）、成本核算。这就是你的模型网关原样进场——机器人域给它的新输入只是「边缘推理池」这一档路由目标。

4.10.3 模型管理：注册表、制品库、OTA 的三权分立

注册表存元数据：模型卡（用途/架构/输入输出契约）、血缘（训练数据集版本 → 训练任务 → 评测结果，第七篇闭环）、许可与合规、部署位置矩阵（哪个版本在云/哪些站点池/哪些机型端上）；制品库存字节（4.3.3）；OTA 负责搬运（4.3.6）。三权分立的价值：审计问「vla-2.3 现在跑在哪、评测过没、数据从哪来」时，一张注册表页答完——模型治理的合规底座。

4.10.4 Prompt 管理：Prompt 即制品

Prompt/系统提示/任务模板一律进 Prompt 库：版本化、绑定评测集（回归门禁：改 Prompt 必跑评测）、灰度（按站点/租户）、生效走配置 OTA 通道（2.13.4 的又一消费方）。你 Langfuse 的 Prompt 管理经验全额适用；机器人域的增量约束：涉及物理动作措辞的 Prompt 变更必须过安全评审（把「尽快完成」改成「全速」这类措辞可能改变现实世界行为）。

4.10.5 Agent 与技能编排：云端大脑调机器人技能

架构铁律三条：技能目录来自 Device Profile（Agent 能调什么由平台声明，不由 LLM 想象）；工具调用只落到 L2 Fleet 任务（Agent 绝不直发 L4 关节级动作——四层任务模型是 Agent 的安全笼）；高危动作过人审门（进入人机共管区、涉及 E-Stop 邻域的动作，工具返回「待批准」而非直接执行）。实现上把 Fleet 任务 API、孪生查询、日志/bag 检索封装为 MCP 工具服务器，LangGraph 规划图直接复用你的存量框架——Agent 面是你带资进组的部分。

4.10.6 Knowledge：AIDO 的机器人分册

语料四类：操作手册与 SOP、维修案例库、故障码释义、站点特有知识（环境/布局/规程）。检索栈按你的存量演进：向量 RAG 起步（Milvus），故障知识用 LightRAG/GraphRAG 建「症状—根因—处置」图谱——这正是你在设备智能分析里趟通的路线，故障图谱 Schema 可整体平移（DTC→error_code、ECU→节点/关节）。消费方：诊断 Agent、工程师 Copilot、任务规划器（「A 区」这类语义解析）。治理：知识按站点/租户分权限，版本随站点基线发布。

  • MQTT 集群会话持久化与遗嘱策略明确；区域多活方案成文
  • 双通道流量隔离（高频小报文 vs 会话/文件）落到部署层

设备面

  • 两级 CA + 产线出生证书；Robot ID 一处签发处处引用
  • 注册激活时序含防克隆/防重放；证书轮换与吊销流程成文
  • 三信号在线判定；生命周期状态机与平台动作挂钩表

OTA 面

  • 四种载荷差异表与各自回滚方式成文；统一 RobotTask 语义
  • 制品不可变 + 签名链 + SBOM + 四维兼容矩阵
  • 分发四级瀑布 + 分片续传验签 + 带宽/窗口策略；ROI 账可讲
  • 模型双缓冲热切换 + 影子评测 + 灰度环 + 门禁指标自动回滚
  • OTA Agent 自升级走最保守通道；回滚演练常态化

数据面

  • 遥测分层存储纪律（热明细/聚合/归档）与容量三数字
  • 三键结构化日志；日志默认在端、三通道召回
  • 一次任务一条 Trace 的贯通方案；端侧异步上报拼装
  • 黄金指标 SLI/SLO 表立项并进周会大盘

任务面

  • 四层任务模型与层间契约；任一层可独立重试
  • Fleet 调度输入五字段 + 任务租约 + 幂等键
  • 地图即制品（版本/签名/灰度）；语义层为坐标真相源
  • 两级协同分界成文；实时避碰不依赖云为评审否决项
  • 无人工闭单率作为任务面第一 KPI

边缘

  • 站点三职责边界成文（明确「边缘不做什么」）
  • GitOps 拉模式 + 站点 values + 边缘进孪生
  • 推理位置决策表 + 三问；断云自治等级 SLA 与对账四步

AI 面

  • AI Gateway 五件事齐备，含边缘降级路由
  • 模型三权分立与血缘可审计；Prompt 即制品带评测门禁
  • Agent 三铁律落到工具层实现（Schema 校验 + dry-run + 人审门）
  • 知识/记忆分库分权限，记忆可溯源可遗忘
  • AI 能力按风险递增分级上线，门禁指标明确

治理面（横切，第九篇深化）

  • 三句读图纪律作为架构评审否决项
  • 全平面统一 robot_id/task_id/trace_id 三键
  • 每平面容量三数字 + 故障演练计划

4.12 第四篇总结

4.12.1 下卷十条核心结论

  1. 从订单到关节共四层任务，层间只传目标与结果——Agent、调度、OTA 全部生活在这套笼子里。
  2. Fleet 可靠性的核心是任务租约 + 幂等键；「无人工闭单率」是任务面第一 KPI。
  3. 地图、Prompt、配置、模型——平台里一切可下发之物都按「制品」治理，复用同一套 OTA 纪律。
  4. 运动级协同永不依赖云；共享资源锁必须带 TTL 与本地保守降级。
  5. 遥测管道原班人马复用，机器人新增的是健康分与 QoS 事件两条衍生流。
  6. 一次任务一条 Trace，三键贯穿云边端；日志默认归宿在端上。
  7. 顶层 SLI 换成物理作业质量：任务成功率、干预率、E-Stop 三件套。
  8. 边缘三职责且明确「不做什么」；GitOps 拉模式 + 预热两段式管住 200 站点。
  9. 推理位置由延迟预算与三问裁决；断云自治按 SLA 分级定价。
  10. AI 面 = 你的 Agent 平台带资进组：Gateway/注册表/Prompt/知识/记忆/工作流各就各位，Agent 三铁律保安全。
