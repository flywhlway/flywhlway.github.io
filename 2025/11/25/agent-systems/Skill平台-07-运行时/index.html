07 · Skill Runtime：加载、隔离、恢复与全链路观测

企业级 Skill Registry 平台工程手册 · 第 07 篇
前置阅读：01 篇（状态机 + Runtime 四职责：注入路由表、存储寻址、沙箱、遥测）、06 篇（会话快照的来源）
本篇回答：技能在执行现场的完整生命周期——Loaded / Activated / Executed / Observed / Cancelled / Retried / Recovered / Measured——每个动词背后的机制与失败模式。

1. 概述：Runtime 的克制

01 篇已立宪：激活权在模型，Runtime 只做四件事。本篇是这四件事的实现细节，但先重申克制原则，因为 Runtime 是最容易”好心办坏事”的组件——每一个”帮模型一把”的旁路逻辑（自动注入、自动重试语义化、输出自动修复）都在侵蚀体系的可预测性。Runtime 的美德是忠实：忠实地提供环境、忠实地记录发生的一切、忠实地不做决策。

2. 运行时架构

3. Loaded：加载与上下文组装

会话初始化的组装顺序（顺序即优先级，进平台规范）：

预算核算在第 3 步实施硬闸：L1 总量超预算（01 篇 5% 线）时降级为两级路由而不是截断列表——静默截断意味着部分技能随机消失，是最难排查的一类”为什么没触发”。降级动作本身发遥测事件，运营可见。

4. Activated：激活观测与二次鉴权

Tool Gateway 对技能路径读取的拦截逻辑：

两个细节：审批阻断返回的是结构化工具错误而非静默失败——模型能读懂并向用户解释审批流程（04 篇 §7 的体验设计在此落地）；resolve_from_snapshot 保证读到的永远是快照版本，即使磁盘上已有新版缓存。

5. Executed：沙箱与脚本执行

5.1 沙箱 profile 体系

技能 manifest 声明 sandbox_profile，Runtime 按 profile 实例化隔离环境：

profile 网络 文件系统 典型技能 隔离技术建议
offline-analysis 无 skill 只读 + uploads 只读 + workspace 读写 03 篇两技能 容器 + seccomp 默认档
net-restricted 域名白名单（经 egress 代理） 同上 需拉包/查内网 API 的技能 容器 + egress 代理
privileged-build 白名单 同上 + 构建缓存卷 前端构建类 gVisor/Kata（不可信代码强隔离）

隔离技术选型的判据一句话：执行的代码是谁写的。技能 scripts 经过发布评审属”半可信”，容器级隔离够用；技能执行中模型现场生成的代码（临时脚本）不可信度更高，值得上用户态内核（gVisor）或轻量虚机（Kata）——同一沙箱池按 profile 混部两档。

5.2 文件系统布局（沙箱内视角）

/skills 只读是供应链防线的运行时一环：任何”执行中技能被改写”都物理不可能，脚本自我修改、交叉污染两类攻击面直接闭合。

5.3 执行协议：超时、流式与输出纪律

exit code 语义约定看似琐碎，实为模型错误恢复能力的地基：模型看到 1 + stderr 说明会走 SKILL.md 的 fallback 分支；看到 137 会改用分片策略。没有约定，一切非零退出对模型都是同一团迷雾。

6. Cancelled / Retried：取消与重试

取消是树形传播：用户停止 → 会话取消令牌 → 当轮所有子令牌（进行中工具调用、沙箱进程组 SIGTERM→宽限 5s→SIGKILL）。两条纪律：

  1. 取消后沙箱 /workspace 保留——用户”停一下”往往接着”换个方式继续”，半成品证据文件是恢复的资本（§7）；
  2. 取消事件进遥测并标注取消时的活动技能——高取消率技能是”执行过程让用户失去耐心”的直接信号，进 05 篇质量分的负项候选。

重试的责任分层（谁的失败谁重试）:

失败层 重试方 策略
基础设施瞬态（沙箱起容器失败、缓存 miss 回源超时） Runtime 自动 指数退避 ≤2 次，对模型透明
脚本业务失败（exit 1） 模型决策 按 SKILL.md fallback，Runtime 不自作主张
模型行为失败（激活了却没按流程走） 不重试 属评测问题，记录进 10 篇的执行评测样本

Runtime 自动重试的边界要收紧到”结果必然幂等”的层面——脚本执行不在其中（脚本可能已写了半个输出文件），这正是 08 篇脚本规范要求幂等写（临时文件 + 原子 rename）的原因：幂等的脚本让模型层重试变得安全。

7. Recovered：Checkpoint 与恢复

技能体系的 checkpoint 与工作流引擎不同——没有引擎状态可存，状态就是文件与对话。恢复设计因此轻量而务实：

03 篇 Skill A 的三段脚本管道天然构成三个 checkpoint。会话中断恢复（新会话续做）依赖两件事：/workspace 按租户策略保留（默认 24h）+ 会话可携带前会话 workspace 引用。刻意不做：透明的引擎级断点续跑——那要求把模型推理状态图灵完备地外化，成本巨大且与”状态就是文件”的简约模型冲突。多智能体平台若已有 LangGraph 级 checkpoint 引擎，二者边界划在：引擎管 Agent 图状态，技能管自己的证据文件，互不越界。

8. Memory：技能与记忆的关系

原则一条：技能是无状态的流程知识，记忆是有状态的用户事实，二者单向可读。

  • 技能执行可读会话记忆（模型本来就看得见），用于个性化执行；
  • 技能不得指令性写入长期记忆（SKILL.md 里不允许出现”将 X 写入用户记忆”）——记忆写入是平台级行为，有自己的隐私过滤管道，技能作为分发内容不得携带绕过该管道的指令。发布流水线的指令扫描（06 篇 §10）包含此模式;
  • 技能自身的”经验积累”（例如码表补充）走发版而不是运行时自改——03 篇 classify_failure 对未映射码的处理是”提示维护者回填规则”而非自写规则，就是这条原则的实例。

9. Observed / Measured：遥测、Tracing 与指标

9.1 OTel Trace 模型

属性约定的两个非显然项：snapshot_id 打在每个 turn（配合 05 篇 as_of 构成完整复现能力）；script_path 与 manifest file_tree 的 role 做运行时一致性校验——执行了一个 role≠script 的文件路径立即告警，这是”声明与行为偏差检测”（04 篇 §6）的落地点。

9.2 指标体系（按消费方组织）

消费方 指标 口径要点
族 owner 激活率、执行成功率、fallback 进入率、P95 激活时延、单次执行 token 成本 全部按 skill_ref×version 分维，灰度对比即两 version 并排
平台 SRE 沙箱池饱和度、冷启动 P95、缓存命中率、L3 回源时延、遥测丢弃率 沙箱预热池水位是首要容量信号
质量体系(10 篇) correction 率、取消率、重试率、examples 线上抽检通过率 喂给 05 篇质量分与 SLO 看板
财务/容量 token 成本按租户×族聚合、沙箱 CPU 秒 技能中心的成本分摊依据

遥测纪律重申：尽力而为，永不阻塞（06 篇 AP-7 的运行时同款）。丢遥测降质量可观测性，阻塞主路径降服务本身——前者可容忍可补救。

10. 失败模式目录

# 失败点 症状 检测 处置
F1 L1 预算超限静默截断 部分技能”随机”不可见 组装期预算核算事件 §3：降级两级路由，禁止截断
F2 快照与缓存不一致 激活读到新版内容 digest 校验失败告警 只读挂载 + digest 校验，会话报错重建
F3 沙箱冷启动风暴 首工具调用 P95 恶化 预热池水位 池容量弹性 + profile 混部配额
F4 stdout 泄洪 单轮 token 暴涨 truncated + stdout_bytes §5.3 硬顶；违规脚本进 08 篇 lint 黑名单
F5 僵尸执行 取消后沙箱进程残留 进程组审计 令牌树 + SIGKILL 兜底 + 池回收器
F6 审批阻断死循环 模型反复尝试读被阻技能 同 ref 连续 blocked 事件 结构化错误含”不要重试”指引；3 次后 Gateway 硬闸
F7 脚本读快照外路径 越权读 seccomp/挂载白名单拒绝 + 告警 安全事件流程（11 篇）
F8 遥测管道反压 主路径时延抖动 管道队列水位 丢弃降级，永不背压

11. 反模式

  • AP-1 Runtime 语义化重试：模型说”再试一次”之外 Runtime 自作主张重跑脚本（§6 分层的破坏）。
  • AP-2 输出自动修复：脚本输出 JSON 微损，Gateway “好心”修复后回给模型——模型据此建立的格式信念与脚本真实行为脱钩，下次没修复就崩。忠实回传 + 让模型走 fallback。
  • AP-3 无差别强隔离：全部脚本上 Kata/gVisor，冷启动与内存税吃掉沙箱池容量。按代码可信度分档（§5.1）。
  • AP-4 workspace 即弃：取消/失败即清理工作区，销毁恢复资本（§6 纪律 1）。
  • AP-5 引擎级透明续跑：见 §7 “刻意不做”。
  • AP-6 遥测同步落库：见 F8。
  • AP-7 技能指令写记忆：见 §8，发布扫描 + 运行时双防。

12. 生产建议与检查清单

  1. 组装顺序与预算硬闸进规范；降级路径有遥测事件。
  2. exit code 协议 + stdout 纪律作为脚本规范强制项，Runtime 与 08 篇 lint 双端执法。
  3. 沙箱按”代码可信度”分档而非一刀切；预热池水位进容量告警。
  4. 取消令牌树 + workspace 保留 + 高取消率进质量负项。
  5. checkpoint = 中间文件协议，写进长流程技能的 SKILL.md 模板。
  6. OTel 属性约定全平台统一，snapshot_id 全链贯穿。
  • onSkillRead 鉴权钩子 + 结构化审批阻断错误
  • resolve_from_snapshot：激活永远读快照版本
  • 三档 sandbox profile + egress 代理 + /skills 只读
  • 超时三层 + \r 折叠流式 + 32KB 硬顶截断协议
  • exit code 语义表进平台规范与技能模板
  • Runtime 自动重试仅限幂等基础设施层
  • workspace 24h 保留 + 跨会话引用
  • trace 模型五级 span + role 一致性校验
  • 指标四消费方视图 + 遥测永不阻塞
  • 失败模式目录 F1~F8 各有检测与处置演练
