云原生统一网关架构

本文档描述了基础平台（BP）中云原生网关的技术方案——基于Higress构建三合一云原生网关架构。

BP关键技术方案 - 三合一云原生网关架构（Higress）

📷 原始图片：

一、概述

本文档描述了基础平台（BP）中云原生网关的技术方案——基于Higress构建三合一云原生网关架构。Higress融合安全（WAF）+流量调度+微服务治理三大能力于一体，极大降低网关部署及运维成本。

二、网关架构演进路径

2.1 传统网关模式（Phase 1）

问题：

  • 各种网关功能单一，部署分散
  • 运维、研发工作复杂
  • 部署成本高，资源利用率低

2.2 流量+微服务网关二合一（Phase 2）

改进：合并流量网关与微服务网关

2.3 安全+流量+微服务网关三合一（Phase 3 - 目标架构）

核心价值：三合一高度集成，单一入口统一处理

三、Higress 架构详解

3.1 OPS Plane（运维面）

组件 用途
Console Web管理控制台
Higress CLI 命令行管理工具
kubectl Kubernetes原生管理

3.2 Control Plane（控制面）

  • 双存储支持：同时支持Kubernetes原生和Nacos传统部署
  • 多集群管理：支持跨K8s集群的服务管理
  • xDS协议：与数据面通过xDS协议通信
  • 插件管理：统一的插件生命周期管理

3.3 Data Plane（数据面）

四、主要优势

维度 优势
性能 对比Spring Cloud Gateway/Zuul等传统Java微服务网关性能高出2-4倍
安全 集成安全URL过滤、WAF防护、认证鉴权等安全插件能力
服务治理 流量转发、微服务业务鉴权、限流降级等服务管理
服务发现 具备多注册中心、协议转化等能力，支持Nacos服务注册发现
可扩展性 支持自定义插件管理，Java/Golang/WASM多语言插件

五、关键技术选型

技术 角色
Higress 云原生API网关框架
Envoy 高性能数据面代理
xDS 配置分发协议
WASM 轻量级插件运行时
Sentinel 流控组件
ModSecurity WAF安全引擎
Nacos 服务注册与配置中心
Istiod 可选的Service Mesh控制面

六、关键技术洞察

  1. 三合一集成：安全+流量+微服务统一网关，大幅减少运维复杂度和资源消耗
  2. 高性能：基于Envoy的数据面，性能是Spring Cloud Gateway的2-4倍
  3. 云原生就绪：完全适配Kubernetes，支持Ingress API和Gateway API
  4. 多语言插件：WASM + Java + Golang，满足不同团队的开发习惯
  5. 平滑迁移：内置Nginx Ingress Adapter，支持从Nginx平滑迁移
