06 · Skill 分发体系：从签名产物到 Air-gap 与车端边缘

企业级 Skill Registry 平台工程手册 · 第 06 篇
前置阅读：04 篇 §8.3（产物契约）、05 篇 §10（skill.version.published 事件）、01 篇 §6.2（存储拓扑 C）
本篇回答：产物长什么样、信任链怎么建、缓存拓扑怎么铺、版本锁与热更新的语义边界、以及离线/边缘这两个产业物联网平台绕不开的极端环境。

1. 概述：分发层的设计不变量

分发层的一切设计围绕四条不变量展开，先立后论：

  1. 产物不可变（05 篇 AP-2 的分发侧承接）：同一 ref@version 的字节序列永恒唯一，一切缓存因此可以无限期、无协商地生效；
  2. 内容寻址：产物与其内部文件全部以 sha256 寻址，”验证”与”去重”由同一机制免费提供；
  3. 信任离线可判：任何持有平台公钥集的节点，无需回连即可验证任意产物——这一条是 air-gap 与车端场景的生死线；
  4. 分发只影响新会话：进行中会话锚定其启动时的快照（01 篇会话级版本快照），分发层永不”推送变更进会话”。

2. 打包格式：.skill / .plugin bundle

2.1 结构

信任结构是两级哈希树：manifest.sig 只签 manifest；manifest 的 file_tree 列出每个文件的 digest。验证任意单文件 = 验签 manifest（一次）+ 比对该文件哈希（一次），无需解出整包——这是 §5 懒拉取的密码学前提。

2.2 与 OCI Artifact 的对比决策

自定义 zip bundle OCI Artifact（复用镜像仓库）
基建复用 需自建存储与 GC Harbor/ECR 等现成，含复制/GC/扫描
单文件懒拉取 哈希树原生支持 layer 粒度，需按 role 切 layer 模拟
签名生态 自管密钥 + ed25519 cosign/notation 现成，与镜像同一信任链
边缘/车端解包 zip 任何环境可解 需 OCI 客户端，嵌入式环境偏重
结论 车端/嵌入式分发链路用 云侧仓库与区域复制用

推荐双格式同源：发布流水线产 zip bundle 为真理源，云侧自动转写 OCI Artifact 入镜像仓库（referrers 挂签名与 SBOM）享受现成复制能力；边缘链路直接分发 zip。两格式的 manifest digest 一致，跨格式可互验。

3. 签名与信任链

三个借鉴 TUF（The Update Framework）的关键设计，各自防一类真实攻击：

  1. 密钥分层 + 在线密钥可轮换：在线签名密钥泄露时，轮换密钥并吊销窗口期产物，root 不动，全网信任不重建。
  2. 吊销清单带签名时间戳 + 最大陈旧度：验证方要求清单新鲜度 ≤7 天（可配），防”冻结攻击”——攻击者阻断更新让节点永远用带洞旧版。air-gap 环境的陈旧度策略单独放宽并补偿以人工流程（§8）。
  3. 降版保护：节点记录已见过的每个 ref 的最高版本号，拒绝安装更低版本——除非回滚指令本身带平台签名（区分”攻击性降版”与”运营回滚”）。

激活时是否再验一次？分层回答：云侧沙箱容器内产物来自只读挂载、挂载源已验，激活免验；车端/边缘激活前必验（本地存储的物理接触面不可信）。

4. 分发拓扑

同步语义按内容分两档，与渐进式披露同构（这是本篇最优雅的对称性）：

内容 同步策略 理由
manifest + SKILL.md（L1/L2 对应物） 事件驱动推式全量同步到区域缓存 体积小（KB 级）；resolve 与激活的关键路径不允许 miss 回源穿透
references / scripts / assets / examples（L3 对应物） 懒拉取 + LFU 保留 大文件；单文件哈希可独立验证（§2.1），miss 一次性回源代价可接受

预热例外：compliance:* 与租户 Top-N 激活技能的 L3 随 L2 一起推——热点的 miss 惩罚发生在用户等待中，预热成本发生在后台，划算。

5. 版本锁：三层 lock 语义

  • 层 1→2 的转换时机 = 订阅变更或收到 published/deprecated 事件，且默认不自动前滚大版本（^3.0 内的 minor/patch 自动，MAJOR 必须管理员显式动作——五维兼容性判定第 4/5 维正是为这个闸门服务的）。
  • 层 2→3 每会话一次，snapshot_id 落遥测（07 篇），配合 05 篇 as_of 实现任意会话的技能集复现。
  • lockfile 实体化：resolved_set JSONB 即 lockfile，可导出为文件供 air-gap 打包（§8）与 CI 环境固定（10 篇评测环境必须锁版本，否则评测结果不可比）。

6. 热更新：语义边界与灰度

“热更新”在本体系中的唯一合法语义：新会话解析到新版本。任何”进行中会话换内容”的实现（缓存文件原地覆盖）都会制造模型前后看到两份指令的精神分裂态，是分发层的头号禁令。

灰度维度与推进策略：

灰度的实现落点在层 2：resolved_set 支持同租户多版本按比例分桶（session_id 哈希取模），Runtime 无感——它只忠实使用拿到的快照。

7. 回滚

产物不可变让回滚退化为指针操作：

配套三件事比机制本身重要：

  1. 回滚触发器目录先于事故定义（08 篇发布规范承接）：SLO 破线自动提案、correction 率激增、安全吊销——每类触发器对应回滚半径（单技能 pin / 整 plugin / 全租户）；
  2. 回滚也是发布：走签名（§3 的运营回滚签名，防降版保护误杀）、进审计、发事件；
  3. 数据面回滚不存在：技能无状态（状态在会话与用户数据里），这是技能体系相对服务回滚的巨大简化——守住”技能不落持久状态”（07 篇 §8）就守住了这个简化。

8. Air-gapped 环境

制造/军工/涉密网车厂场景，完整流程：

四个离线特有问题的解法：

问题 解法
吊销清单陈旧度无法满足 ≤7 天 策略降级为”≤上次导入时刻” + 每次导入强制携带最新清单 + 导入频率写进安全合规承诺（技术松一格，流程补一格）
时钟不可信导致签名时间验证失效 验证改用单调序：清单序号必须递增，不依赖墙钟

离线侧自研私有技能 离线本地签名密钥（root 签发的分支 key），产物永不回流公共库——单向阀

9. 边缘与车端部署

产业物联网平台的特有命题：诊断 Agent 不一定跑在云上——厂端工位机、4S 店诊断仪、乃至车端座舱域控都可能承载轻量 Agent。分发链路的末端设计：

两个决策值得展开：

  1. 复用 OTA 基建下发技能包：车端已有安全下发通道（签名、差分、断点、分区校验），技能 bundle 作为一种新 payload 类型接入，而不是另建通道——你的平台在这里有天然主场优势，技能分发的车端可靠性直接继承整车 OTA 的成熟度。反向约束也随之而来：车端技能发版节奏受 OTA 窗口约束，lockfile 按车型×软件版本基线管理，这要求 Registry 的租户模型支持”车型基线”作为一种订阅主体。
  2. 车端技能白名单族：车端算力与存储决定只承载”离线自诊、取证引导、降级话术”类轻技能；重分析（本手册 03 篇两技能）始终云侧执行，车端技能的职责是把证据可靠地送上云。族级 capability 的 surfaces 字段（04 篇 §6）在此成为分发过滤器——surfaces 不含 vehicle-edge 的技能根本不进车端通道。

10. Marketplace 同步与供应链

企业 Registry 镜像上游公共市场（如公共 skills 仓库生态）时，同步不是 rsync 而是准入流水线：

关键立场：外来技能一经引入即视为自有资产管理——vendored 命名空间有 owner（引入团队）、有 SLO、有退役流程。”上游改了我们自动跟”等于把上游维护者纳入你的信任计算基座，供应链事故的标准起点。指令注入扫描的模式库与 11 篇的运行时防线互为补充：扫描防已知模式，沙箱与权限收敛防未知模式。

11. 生态借鉴速查

生态 借什么 不借什么
npm lockfile 语义、语义化版本约束表达式 install 时执行任意脚本（postinstall 是供应链事故温床，技能 scripts 只在沙箱内按需执行）
OCI/镜像 内容寻址、referrers 挂签名/SBOM、区域复制 可变 tag（latest 漂移；本体系 channel 指针在 Registry 层，产物层无 tag）
TUF 密钥分层、吊销新鲜度、降版保护 全套角色模型（threshold 签名等，企业单一发布方场景过重）
apt/系统包 依赖闭包解析、发行版=经验证组合（对应 plugin 版本） 全局单版本共存约束（技能多版本天然可并存）

12. 反模式

  • AP-1 可变 latest 指针进产物层：channel 解析只在 Registry/resolved_set 层发生，缓存与磁盘上只有 digest。
  • AP-2 缓存原地覆盖实现”热更新”：见 §6 禁令。
  • AP-3 TTL 式缓存失效：会话中途失效重取 = 同一会话两个版本。失效单位是会话（01 篇），标脏靠事件不靠时钟。
  • AP-4 边缘全量同步：把万级技能库全量推到厂端磁盘。订阅域过滤 + L3 懒拉是边缘的生存方式。
  • AP-5 上游自动跟版：见 §10。
  • AP-6 回滚绕过发布流水线：”紧急”手工改指针不签名不留痕——恰恰在事故最需要审计的时刻销毁了审计。回滚快是因为机制轻，不是因为跳过流程。
  • AP-7 遥测阻塞分发：边缘节点”必须回传成功才继续服务”。遥测尽力而为，服务永远优先。

13. 生产建议与检查清单

  1. 四条不变量（§1）进平台 ADR，与 05 篇边界 ADR 并列为分发层宪法。
  2. 双格式同源：zip 真理源 + OCI 云侧复制，manifest digest 跨格式一致。
  3. TUF 三件套（密钥分层/吊销新鲜度/降版保护）从第一天实现——事后加装等于全网重建信任。
  4. 同步策略与渐进披露同构：L1/L2 推、L3 懒 + 热点预热。
  5. 车端走 OTA 基建复用 + 白名单族 + surfaces 过滤，lockfile 按车型基线。
  6. 灰度自动推进 + 破线冻结 + 回滚提案人确认，三段式发布安全网。
  • 产物不可变（存储层 WORM）+ 全链内容寻址
  • 两级哈希树：单文件可独立验证
  • 密钥分层 + 吊销清单新鲜度策略（在线 ≤7d / 离线按导入）
  • 降版保护 + 运营回滚签名通道
  • 三层版本锁 + snapshot_id 进遥测
  • 灰度分桶在 resolved_set 层实现，Runtime 无感
  • 回滚触发器目录 + 半径矩阵先于事故定义
  • air-gap 导出器/导入器 + 单调序验证 + 遥测延迟回传
  • 边缘 LFU 配额 + 断网降级陈旧度标注
  • vendored 命名空间准入流水线（许可/扫描/试执行/重签名）

附录 A：缓存节点同步协议

A.1 节点状态机

stateDiagram-v2
    [*] --> BOOTSTRAP: 节点启动
    BOOTSTRAP --> SYNCING: 拉取密钥链+吊销清单+订阅域清单
    SYNCING --> READY: L1/L2 全量同步完成
    READY --> READY: 事件驱动增量(published/deprecated)
    READY --> DEGRADED: 事件流断连 > 阈值
    DEGRADED --> READY: 重连 + 差量对账(digest 清单比对)
    DEGRADED --> STALE_SERVING: 断连超陈旧度上限
    STALE_SERVING --> SYNCING: 恢复连接, 全量对账
    note right of STALE_SERVING: 继续服务但每个快照
      标注 staleness, 进会话遥测

DEGRADED 与 STALE_SERVING 的区分是运营语义：前者静默自愈，后者需要告警但不停止服务——分发层的可用性优先级高于新鲜度（新会话拿到略旧的稳定版本远好于拿不到）。

A.2 同步与懒拉取 API

内容寻址带来的免费礼物在此兑现：ETag = digest + 无限期缓存头，CDN/代理层零配置正确。

A.3 懒拉取时序（L3 miss 路径）

sequenceDiagram
    participant M as 模型
    participant RT as Runtime(节点)
    participant NC as 节点缓存
    participant RC as 区域缓存

    M->>RT: view …/references/error_code_mapping.md
    RT->>NC: 读文件(快照内路径)
    NC-->>RT: MISS
    RT->>RC: GET /artifacts/{digest}/files/references/error_code_mapping.md
    RC-->>RT: 文件流
    RT->>RT: sha256 比对 file_tree 声明 → 通过
    RT->>NC: 写入(LFU 记账)
    RT-->>M: 文件内容 (整体 P95 目标 <300ms)
    Note over RT: 比对失败 → 丢弃+告警+从源重取一次, 再失败即工具错误
