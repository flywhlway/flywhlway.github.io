心法先行（贯穿全书的三句话）：

  • 微调是最后的手段，数据是全部的杠杆——70% 的时间在第四章，不在训练命令上；

二、技术图谱：一页纸直觉 + 架构师五件事

本章是全书唯一的”理论”章，每节压缩为一页纸直觉与架构师需要知道的五件事。数学推导一律略过——要用时查论文（附录 C 给了精读清单）。

2.1 SFT 与 LoRA/QLoRA

一页纸直觉：SFT = 拿(指令,期望输出)对做续写训练，教模型”这类输入该产出这类输出”。全参微调动全部 70 亿参数，显存吃不消；LoRA 的洞察是微调造成的参数变化是低秩的——冻结原模型 W，只训练一对小矩阵 B·A（ΔW = BA，秩 r 通常 8–64），可训练参数降到 0.1%–1%。QLoRA 更进一步：把冻结的底模压成 4-bit（NF4）放显存，LoRA 部分仍用 16-bit 训——7B 模型 QLoRA 训练 12–16GB 显存即可，4090 绰绰有余。

架构师五件事：

  1. LoRA 产物是一个几十–几百 MB 的 adapter 文件，可独立分发、热插拔、多任务并存（vLLM multi-LoRA）——这是”模型即微服务”的物质基础；
  2. 秩 r 不是越大越好：r=16 起步，任务简单降到 8，输出复杂升到 32/64；alpha 习惯取 2r；
  3. lora_target: all（对所有线性层加 LoRA）在现代实践中优于只挂 q/v 投影，LLaMA-Factory 一键配置；
  4. SFT 教技能与格式，不教知识——想灌知识请回 RAG，硬灌的知识会幻觉化；
  5. 灾难性遗忘的头号肇因是学习率过大 + epoch 过多：LoRA-SFT 从 1e-4、2–3 epochs 起步，观察 eval loss。

2.2 DPO（偏好优化）

一页纸直觉：SFT 解决”会不会”，DPO 解决”好不好”。传统 RLHF 要先训奖励模型再跑 PPO（两套模型、训练不稳）；DPO 的洞察是这整套流程可以数学等价地化简为一个分类损失——直接拿(同一输入, 更好的输出, 更差的输出)三元组训练，让模型提高好输出、压低差输出的概率。工程上就是”SFT 的难度 + 偏好数据”，没有 RL 的不稳定性。

架构师五件事：

  1. DPO 必须建立在 SFT 模型之上（先会做，再谈好坏）；
  2. 偏好对的”好/坏”差距要明显且维度单一——差距模糊的数据会教坏模型；
  3. beta 参数（0.1 起步）控制偏离 SFT 模型的程度，越小越保守；
  4. 学习率比 SFT 低一个数量级（5e-6 级），数据量百级到千级即可见效；
  5. 家族变体（KTO/ORPO/SimPO）可在 LLaMA-Factory 里换一行配置切换，选型不焦虑——先用 DPO 建立直觉。

2.3 GRPO 与 RLVR（素养级）

一页纸直觉：RLVR = 可验证奖励强化学习——奖励不来自训练出的奖励模型，而来自确定性判定器（答案对不对、格式合不合法、测试过没过）。GRPO（DeepSeek-R1 的核心算法）解决 PPO 需要额外 critic 模型的负担：对同一问题采样一组（如 8 个）回答，用组内相对好坏作为优势信号——省掉 critic，训练大幅简化。R1 证明了：仅靠 RLVR，模型能自发涌现长链推理。

架构师五件事：

  1. RLVR 的”确定性判定器产生奖励”与你的 M1 第一公理同构——你在 示例业务平台-Evals 里建的确定性 grader，本质就是未来 RL 的 reward function 雏形，这是评估投资的隐藏期权；
  2. RL 适用前提苛刻：任务奖励可自动判定 + 基模型已有一定能力 + 千级以上高质量问题集；
  3. 成本比 SFT 高 1–2 个数量级（每步要采样一组回答），企业场景 ROI 大多为负；
  4. 奖励欺骗（reward hacking）是头号风险——模型学会钻判定器空子而非真正变好，判定器要像防对手一样设计；
  5. 素养目标：能读懂 R1 论文、能对团队讲清 GRPO 组相对优势的直觉、能用第八章模板论证”先别上 RL”。

2.4 Embedding 微调（对比学习）

一页纸直觉：embedding 模型的训练目标是把相关的拉近、不相关的推远（对比学习 InfoNCE）。领域微调 = 用领域内的(查询, 正例文档, 难负例文档)三元组继续训练。难负例（hard negative）是效果的命门：随机负例（如拿菜谱当诊断查询的负例）模型闭着眼都能分开，学不到东西；难负例（同故障域、不同根因的文档）才逼模型学会领域内的细粒度区分。

架构师五件事：

  1. embedding 微调是所有微调中性价比之王：模型小（bge-m3 约 0.6B）、训练快（4090 数小时）、收益直接作用于 RAG 全链路；
  2. 难负例构造是领域知识变现的地方——“什么算容易混淆”只有懂业务的人知道，这正是架构师亲自下场的价值点；
  3. batch size 影响巨大（in-batch negatives 机制：批内其他样本的正例互为负例，批越大免费负例越多）——显存换效果的典型场景；
  4. 温度参数（0.02 级）控制区分的”锐度”，动它之前先动数据；
  5. 微调后的 embedding 必须与 reranker 协同评估——只换 embedding 不管 reranker 可能整体变差（5.6 坑 #4，真实社区血案）。

2.5 数据工程三定律（比任何算法都重要）

  1. LIMA 定律：1000 条精心构造的数据 > 50000 条粗糙数据。质量的定义：输入真实多样 + 输出正确且风格统一 + 难度有梯度。
  2. 蒸馏定律：强模型合成 + 规则/LLM 双重过滤 + 人工终审，是 2026 年企业微调数据的标准生产方式——纯人工标注太贵，纯合成不过滤会教出”AI 味”模型。
  3. 隔离定律：训练数据与评估集必须物理隔离（case_id 级 + n-gram 查重双保险）。评估集污染是最隐蔽的自欺——指标漂亮，上线拉胯。

4.2 七步管线（工单 → 训练数据）

① 采集：三个来源按信噪比排序——AIDO/示例业务平台 设计文档与专利中的诊断用例（密度最高，先榨干）、历史工单/案例库（量大但脏）、专家访谈补录（贵，只补盲区）。目标：种子集 80–150 条真实案例。

② 脱敏（合规红线，管线第一道闸）：正则+词典双引擎——VIN（17 位规则）、车牌、手机号、姓名、经纬度、经销商代码一律替换为语义等价占位符（VIN_A01、城市C类气候区）。脱敏规则单元测试化，每条数据过闸留痕。这一步的实现直接复用你 D2 场景（审计+脱敏）的设计。

③ 结构化抽取：强模型（DeepSeek 级）把自由文本工单抽取为中间表示 {症状, 信号特征, 环境上下文, 确认根因, 处置动作}——注意抽取的是已关单工单的确认根因（有 ground truth），不是猜测。抽取 prompt 与 schema 入库版本化。

④ 合成扩增（种子 150 → 目标 1500），两条正交策略：

  • 输入侧扰动：同一根因的不同呈现——换车型平台、换环境条件、增删干扰信号、调整故障码组合。用强模型生成，约束”根因不变、表象合理变化”；
  • 场景组合：多故障叠加、主次假设排序变化、边界样本（信息不足时输出 insufficient_evidence 也要教——模型要学会说”不知道”）。
  • 扩增配比参考：真实:扰动:组合:边界 ≈ 1:5:3:1。成本：DeepSeek API 生成 1500 条 ≈ ¥40–80。

⑤ 双重过滤：

  • 规则层（零成本，先跑）：JSON 可解析、schema 校验通过、故障码在术语白名单内、confidence 数值合法、去重（MinHash 或 embedding 相似度 >0.95 去重）；
  • LLM 评审层：评分 prompt 按 4 维打 1–5 分（根因合理性/证据链支撑/动作可执行性/难度价值），只保 4 分以上，预期淘汰 20–35%。成本 ≈ ¥30–60。

⑥ 人工终审（LIMA 定律的兑现，不可省）：每条 30–60 秒——扫 JSON 结构、核根因逻辑、标记可疑。工具从简：一个 Streamlit 单页（左边 input 右边 output + 通过/拒绝/修改三键），半天写完，终审 1500 条约 15–25 小时，分两周摊掉。架构师亲审前 300 条——数据的手感是决策力的来源，这个不能外包。

⑦ 隔离与版本化：

  • 去污染双保险：与 示例业务平台-Evals 黄金集做 case_id 硬隔离 + 8-gram 重叠查重，命中即从训练集剔除；
  • 版本化：JSONL + git（数据即代码），每版附 dataset card（来源分布/过滤淘汰率/终审通过率/与黄金集查重报告）；
  • 切分：train/val = 95/5，val 用于训练中的 eval loss，黄金集永不参与训练过程的任何环节。

4.3 难负例挖掘（T1 专属，领域知识变现点）

三路难负例来源，按”难度”递增：

  1. BM25 陷阱负例：用 BM25 检索 query 的 top-30，剔除正例后取 rank 5–25 的文档（词面相似但语义不同——经典难负例带）。FlagEmbedding 自带 hn_mine 脚本可直接产出这一路；
  2. 同域异因负例（手工规则，价值最高）：利用你的领域本体——同故障域（如”高压绝缘”）不同根因、同 ECU 不同症状、同症状不同工况的案例互为难负例。这是”什么容易混淆”的领域判断，写成规则脚本沉淀；
  3. 同因异述剔除：警惕假负例——表述不同但根因相同的案例混进 neg 会重伤训练，用根因代码做一致性校验剔除。

每条 query 配 7–15 条 neg（train_group_size 与之匹配）。目标规模：2000+ 三元组（约 300–500 个独立 query × 扰动变体）。

4.4 数据质量验收清单（每版数据发布前打勾）

  • 脱敏闸全量通过且抽检 50 条人工复核无泄漏
  • schema 校验通过率 100%（不合格的不许进库，不许”训练时再说”）
  • 与黄金集查重报告：0 命中
  • 根因分布无严重头部偏斜（单一根因占比 <15%，否则模型学成”万物皆此因”）
  • 含 8–12% 边界样本（insufficient_evidence 类）
  • 终审通过率、淘汰原因分布已记入 dataset card
  • 数据版本 hash 已生成，实验日志可引用

5.6 已知坑清单（社区血案预习）

  1. 过拟合小语料：epoch>5 或数据 <1000 时通用能力明显衰退——对策：混入 10–20% 通用检索数据（如 mMARCO 中文子集抽样）或早停；
  2. 测试集泄漏：三元组的 query 扰动变体与测试 query 语义重复——对策：按”根因代码”切分训练/测试，同根因案例不跨界；
  3. batch 太小学不动：loss 降但指标不动，多半是有效负例太少——对策：5.3 的显存腾挪优先级；
  4. 微调后 embedding + 未微调 reranker 整体变差（FlagEmbedding issue #296 经典血案）：两者的”相似度口径”错位——对策：T1 阶段先摘掉 reranker 对比裸检索；若生产链路必须 reranker，用微调后的 embedding 重挖难负例、配套微调 bge-reranker-v2-m3（作为 T1 的可选加时赛）；
  5. 假负例毒害：同因异述案例进了 neg——对策：4.3-③ 的根因代码一致性校验，训练前必跑。

八、GRPO / RLVR 素养：读懂、讲清、论证”先不上”

8.1 DeepSeek-R1 精读指南（3 小时投入，只读四处）

读什么 拿走什么
GRPO 公式段（对照 PPO 图示） 一句话直觉：同题采样一组答案，组内比相对好坏当优势信号，省掉 critic 模型
奖励设计段 RLVR 实证：只用”答案正确性 + 格式”两个规则奖励就够了，不训奖励模型（回避 reward hacking 的最大来源）
“aha moment” 段 RL 能让模型自发学会反思与更长推理——理解能力涌现的边界在哪
蒸馏结论段 对企业最重要的一段：把 R1 的推理能力蒸馏进小模型，效果好于对小模型直接做 RL——“买/蒸馏推理能力，别自己炼”是 2026 年企业理性策略

8.2 与你的第一公理同构（面试金句，值得背下来）

RLVR 的本质是：奖励必须来自确定性判定器——答案对不对、格式合不合法、测试过没过，全部规则可判。这与”确定性 × 概率性融合”（M1）完全同构：概率性组件（策略模型）负责探索聪明，确定性组件（判定器）负责裁定正确。我在 示例业务平台-Evals 里构建的确定性 grader，格式校验 + 根因对账那一层，本质上就是未来做 RL 时的 reward function 雏形——评估工程的投资自带一份强化学习的期权。

8.3 “该不该上 RL”六问（论证模板，评审会直接用）

  1. 任务的成败能否自动、便宜、防钻空子地判定？（否 → 出局）
  2. SFT 的数据红利吃干净了吗？（否 → 回去做数据，RL 不救数据懒惰）
  3. 有 ≥1000 个高质量、有难度梯度的问题集吗？（否 → 出局）
  4. 预算能承受 SFT 的 10–100 倍算力 + 数周迭代吗？
  5. 团队有人能诊断 RL 训崩（奖励欺骗/熵塌缩）吗？
  6. 蒸馏现成推理模型能不能达到 80% 的效果？（能 → 蒸馏，句号）

诊断场景当前答案：第 1 问部分通过（根因可对账）、第 2 问未通过（T2 刚起步）、第 3 问未通过（黄金集百级）→ 结论：18 个月内不上 RL，把 grader 与问题集当作 RL 期权持续积累。 这段论证本身就是架构师成熟度的展示。
