云管端架构 / 形成闭环第 19 / 20 篇

云管端 AI Agent 平台系列总结：十条结论与评审清单

系列收束篇：十条结论、落地三阶段与退出准则、投入产出排序、必须先关闭的风险与反模式，以及一份可在评审会上逐条核对的清单。

Flywhl 16 分钟 发布于 2026.01 #云管端#架构设计

先读结论

  1. 这是治理平台而不是模型平台：效果杠杆在上下文供给，模型放在网关之后随时可换。
  2. 落地顺序是收口、闭环、自演进；阶段一必须关闭旁路调用、埋点缺字段、端云双写记忆等六项极高风险。
  3. 安全组件不可降级，性能组件可以；提示词、知识、参数等非代码变更同样进门禁并可秒级回滚。
  4. 闭环内的投入顺序：知识补全、检索与提示词调优、评测集、微调、RLHF，多数团队恰好做反。

本篇的定位

前面各篇从总览、系统架构、分层、模块、组件一路写到数据流、调用链与各专章，本篇把它们收束成四样可以直接拿去用的东西：十条结论、落地三阶段、反模式与风险表、评审清单。结论只写我在设计与推演中确认过的判断，每条都注明详细论证在哪一篇。下一篇（20）会在一段时间之后回看这些判断，逐条检验哪些成立、哪些需要修订。

十条结论

其中第 2 至第 6 条是落地的第一性原则：阶段一的每个工作项，都应能追溯到其中一条。

1. 这是治理平台，不是模型平台

这套平台列为建设重点的六项是注册中心、埋点 SDK、语义缓存与 Token 治理、记忆可视化与回溯干预、RAG 门户与评测、Agent 网关，没有一项关于模型本身。模型放在 LLM 网关之后，是可替换的后端资源（00 篇 ADR-04）；平台的价值落在治理、上下文与闭环上。评审时，凡是”换个更强的模型就能解决”的提案，都应先说明它为什么不是上下文问题或治理问题。

2. 先收口，再优化

所有 AI 流量先经过统一网关与注册中心，才谈得上成本、质量与安全。旁路调用一旦形成，事后收口要推动数十个团队改造，通常以失败告终。收口是否完成要能证明：代码扫描无散落的模型凭据，未注册能力的调用次数为 0。

3. 效果杠杆在上下文供给，不在模型选择

记忆、知识、能力三路上下文决定了大部分效果差异，按我的经验约占八成。模型换代的增益，通常小于把检索、记忆、工具裁剪做扎实的增益。”反复换模型而效果不涨”是最常见的失败模式，一耗就是半年。

4. 可观测先于优化

route_reason、decision_reason、empty_recall、memory_hits 四个字段分别对应模型选择、端云落点、知识缺口、记忆影响面四类问题。每个字段只有几十字节，但事后无法补齐：缺哪一个，那一类问题就永远无法归因，优化只能靠猜。字段口径统一在 05 篇。

5. 大多数变更不是代码变更，但必须按代码管

提示词、检索参数、知识内容、Skill 描述、模型权重都能全量影响用户。只对代码设门禁，就会出现”改代码要评审，改一句提示词直接全量上线”的失衡。因此有两条要求：非代码变更同样进门禁与灰度；这些内容全部配置化，让效果故障的恢复时间从小时级降到秒级。效果类故障远多于崩溃类故障，秒级回滚是 AI 平台最重要的运维能力。

6. 安全组件不可降级，性能组件可以

缓存、知识、记忆、能力中心故障时可以熔断降级；围栏与认证故障时必须拒绝服务。这条区分要写进运维手册并定期演练，否则迟早有人为了可用性把围栏关掉。降级矩阵见 01 篇。

7. 端侧是更优路径，不是兜底

云端主链路的首字时延预算是 1225 ms（01 篇），端侧闭环约 390 ms（06 篇）。对端侧能覆盖的意图，走端侧同时更快、更省、更私密，还能离线可用。落点决策因此应倾向端侧，并作为可配置、可观测的一等能力来建设，而不是散落在代码里的隐含判断。

8. 间接提示注入是首要安全风险

接入第三方 MCP 生态，意味着外部内容会进入上下文。防御重心是架构隔离而不是检测：工具结果与系统指令分区并标记为不可信、工具最小权限、危险操作二次确认、出网白名单。检测模型总有绕过的办法。MCP 安全清单见 12 篇。

9. 最容易被低估的是记忆污染与端云一致性

这两项在演示阶段完全看不见，上量后集中爆发，表现为”记错了”和”前后矛盾”。两者都无法事后补救：记忆污染要靠 source_trace_id 回溯，端云一致要靠单写者原则保证，必须在阶段一定下来。详见 08 篇。

10. 闭环是唯一的护城河

埋点、评测、知识补全或训练组成的飞轮一旦转起来，平台与”直接调 API”的差距会持续拉大。闭环内的投入顺序应当是：知识补全 > 检索与提示词调优 > 评测集建设 > 微调 > RLHF。多数团队的顺序恰好相反。

自研边界：只自研四项

判断顺序是：这项能力是不是差异化竞争力？不是的话，开源方案能否满足八成需求？还不能，商用方案的成本是否可以接受？按这个顺序走下来，这套平台只有四项必须自研：

能力 必须自研的理由
记忆中心（含可视化与回溯干预） 事件溯源、命名空间隔离、端云同步都是强定制需求
落点决策（端或云） 端云协同特有的逻辑，没有现成方案
边缘 Agent 框架控制面 端侧能力编译与按算力分档下发，与业务强绑定
RAG 门户与评测 与业务的知识运营流程深度绑定

网关、向量库、推理引擎用开源加定制插件，ASR/TTS 与内容安全可以采购。组件选型的决策方法见 04 篇，具体开源项目见 18 篇。

落地三阶段

阶段 命题 必做工作项 硬性退出准则 核心人力（人月量级）
一 · 收口（0–6 月） 让所有 AI 流量可见、可管、可停 四网关职责分离并作为唯一出口；注册中心强制校验；埋点内置且关键字段齐全；出站围栏 fail-closed；身份从传输层凭据派生；提示词、参数、模型权重、知识版本配置化；Agent 三重预算与成本熔断；RAG 底座（结构化加父子分块、混合检索、Rerank、过滤前置）与三套评测集；记忆事件日志与单写者原则；训练与推理 GPU 隔离 无旁路调用（代码扫描证明）；Trace 覆盖 100% 且关键字段齐全；未注册能力调用为 0；围栏覆盖全部出站且演练通过；配置类变更秒级回滚；无 GPU 抢占事故 平台 8–12，端侧 4–6，数据 3–4，安全 2–3，质量 2–3
二 · 闭环（6–12 月） 让质量与成本可度量、可优化 前缀缓存与语义缓存；分级用模；上下文三路并行加硬预算；记忆可视化与回溯干预；RAG 门户与知识缺口工单；重问率、打断率等隐式反馈指标；阻断式回归门禁；端侧 SLM 与端侧知识包；A2A 权限交集与红队用例集；影子环境与模型灰度；合规删除级联验证 门禁 100% 执行且为阻断式；端侧闭环可用；知识缺口 7 天内修复；下表阶段二指标达标 平台 6–10，端侧 4–6，算法 4–6，知识运营 3–4，质量 3–4
三 · 自演进（12–24 月） 让平台自己变好 可观测闭环自动化；落点决策学习化；端侧蒸馏流水线；SFT/DPO 月度节奏；失败案例根因派单；对确需多跳的子域引入 LightRAG；端云 Agent 同构（一份 manifest 双编译）；多区域与混沌工程 每类观测数据都有对应闭环；盲测集满意度逐版本不降；单会话成本年降 30% 以上；区域级故障 RTO 不超过 30 分钟；红队通过率 95% 以上；端侧模型可自主迭代 平台 4–8，算法 6–8，数据 3–5

阶段一不做的事：不做 GraphRAG，不做微调，不做多 Agent 自由协作，不追求语义缓存的高命中率。这些提前做，会因为缺少评测与观测而无法验证是否有效。

投入产出排序

效果、成本、延迟三个方向各排一次序。三张表的共同结论是：排在前面的都是低成本的工程动作，训练与复杂架构排在最后。

误拦截没有反馈通道 围栏越收越紧，体验持续变差 抽检、申诉通道、误拦截率 SLO 12
观测成本超过业务成本 观测本身成为成本大头 分层采样、冷热分层、成本占比监控 15
灾备方案从未演练 真实故障时方案失效 按月、按季度执行演练清单 16

评审清单

用于技术评审会逐条核对。任何一项答”否”，都记为风险项并给出关闭计划。

收口与治理

  • 全部模型调用是否只经 LLM 网关？是否有代码扫描证明没有散落的凭据？
  • 端侧是否只经网关访问云端，没有直连内部服务？
  • 未注册的 Agent、Skill、MCP Server 是否会被网关与能力中心双重拒绝？
  • Skill 注册是否强制至少 10 条正例、5 条反例？
  • 每个能力是否有 owner、复核周期与弃用机制？存量适配层是否设了退役日期？

可观测

  • trace_id 是否在端侧生成，并一直贯穿到训练数据？
  • 模型调用 Span 的必填属性是否齐全（口径见 05 篇）？
  • decision_reason、route_reason、empty_recall、memory_hits（含记忆 ID）是否齐全？
  • 骨架 Trace 是否全量采集，没有因为成本降采样？
  • 错误与负反馈是否全部保存上下文快照？
  • 除服务指标外，是否有质量层与业务层指标？
  • 是否有降级率、单会话成本异常、质量劣化三类告警？
  • 每类观测数据是否都有对应的改进闭环？

安全

  • 出站围栏是否覆盖全部出站且 fail-closed？是否演练验证过拒绝服务行为？
  • 入站内容安全是否位于授权与转发之前？
  • 工具结果是否与系统指令分区，并标记为不可信？
  • 是否有出网白名单？
  • 身份是否只从传输层凭据派生，没有自报身份？
  • A2A 是否传递权限交集而非原始身份？
  • 不可撤销操作与车控类操作是否强制多因子确认？
  • 端侧策略不可达时是否收紧而非放开？
  • 红队用例集是否纳入 CI？
  • 合规删除是否级联到向量索引、缓存与记忆，并有验证流程？

效果与成本

  • 检索是否为混合检索，元数据过滤是否在检索之前？
  • 是否有查询改写与 Rerank？
  • 是否强制引用，无依据时拒答？
  • 上下文是否有硬 Token 预算与固定的裁剪优先级？
  • Prompt 是否稳定内容前置，让前缀缓存生效？
  • 语义缓存键是否包含知识版本、车型等全部维度？时效性意图是否强制绕过缓存？
  • 是否按任务分级用模，意图分类不用大模型？
  • cost_tag 是否强制必填？是否有单会话成本熔断？

记忆与知识

  • 记忆是否带 confidence、valid_until、source_trace_id？
  • 记忆抽取是否保守，只抽明确表达、不做推断？
  • 是否有记忆可视化与回溯干预，并能看到影响分析？干预是否秒级生效于在线读路径？
  • 记忆是否按命名空间隔离，隐私区不出端？
  • 端云是否遵守单写者原则？
  • 是否有三套评测集，且盲测集由独立角色维护？
  • 空召回是否自动生成知识缺口工单？

可靠性与运维

  • 降级矩阵是否明确区分可降级与不可降级组件？
  • 配置类变更是否可以秒级回滚？
  • 长连接是否实现三段式优雅下线？
  • 围栏是否与网关同等调度优先级，并配置中断预算？
  • 训练与推理是否物理隔离 GPU 节点池？
  • 是否有预留缓冲副本与定时预扩容？
  • 端侧下发是否满足原子切换、验签、保留旧版、自检、灰度可暂停、避开行驶中六条要求？
  • 数据湖格式是否支持行级删除？
  • 故障演练是否按月、按季度执行，且包含”围栏不可用”场景？

写到本篇时，已有三件事触发了复审，系统性的回看放在 20 篇：

  • MCP 规范在 2025-11-25 又发布一版；2025-12-09，MCP 与 AGENTS.md 捐入 Linux 基金会下新成立的 Agentic AI Foundation（AAIF）。ADR-03 担心的单一厂商风险下降，但注册中心仍要记录每个接入对应的规范版本。
  • Agent Skills 于 2025-10-16 发布，2025-12-18 成为开放标准。注册中心自定义的 Skill 格式需要评估是否向它对齐。
  • LangChain 与 LangGraph 于 2025-10-22 发布 1.0 GA，编排框架的 API 稳定性不再是选型时的主要顾虑。

结语

这个系列想留下的不是一张组件图，而是每个判断背后的理由，以及”如果不这样做会怎样”。组件与产品会换，收口、上下文、可观测、安全边界、闭环这五件事的优先级不会变；下一篇会隔一段时间，再用实际发生的变化来检验这句话。
