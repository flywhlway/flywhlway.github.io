2. 接入层设计

2.1 两条接入路径

路径 来源 协议 特征 可靠性
实时流 云端组件埋点 SDK 消息队列（Kafka） 高频、小消息 至少一次
批量上传 端侧缓冲（经双向认证网关） HTTP 批量 + 压缩 低频、大批量 幂等 + 断点续传

2.2 分区与顺序

要点 做法 原因
分区键 trace_id 哈希 保证同一请求的所有 Span 落在同一分区，便于轨迹重建
顺序保证 分区内有序 同一 trace 的 Span 顺序可用于链路重建
分区数 按峰值 Token/s 与消费能力规划 避免热点分区
端侧幂等 幂等键 = 设备 ID + 批次序号 断网重传不产生重复

2.3 背压与降级

flowchart TB
    Q["队列积压监控"] --> L1{"积压 < 阈值1"}
    L1 -->|"是"| N["正常处理"]
    L1 -->|"否"| L2{"积压 < 阈值2"}
    L2 -->|"是"| D1["降级一：停止采集上下文快照<br/>（骨架 Trace 保留）"]
    L2 -->|"否"| L3{"积压 < 阈值3"}
    L3 -->|"是"| D2["降级二：正常请求 Span 降采样至 20%<br/>错误与负反馈仍 100%"]
    L3 -->|"否"| D3["降级三：仅保留错误、负反馈、Token 计量<br/>其余丢弃并告警"]

降级顺序体现价值优先级：上下文快照（体积最大、价值中）最先丢；错误与负反馈（体积小、价值最高）最后丢；Token 计量永不丢（成本核算不可缺失）。

3. 清洗层

处理 说明 失败处理
Schema 校验 按集中管理的 Schema 校验必填字段与类型 进死信队列（不静默丢弃）
PII 脱敏 SDK 侧已脱敏，此处二次校验兜底 命中则脱敏并告警（说明 SDK 侧有漏）
去重 按 span_id + 幂等键 丢弃重复
时间校正 端侧时钟偏移校正（用服务端接收时间做偏移估计） 偏移过大则标记
敏感类别过滤 按数据分级剔除 L4/L5 内容 剔除并记录
字段裁剪 长文本转为哈希 + 对象存储引用 —
授权标记 打上用户授权范围标记（是否可用于训练） 无授权则标记不可训练

3.1 死信队列不可省

隐式反馈的计算逻辑（推断设计）：

信号 计算方式
重问 同一 session 内，5 min 内出现语义相似度 ≥0.85 的查询

要点 说明
离线计算 画像不做在线实时计算（延迟与成本不允许）

6. 对象存储

内容 采样率 保留 加密 访问控制
上下文快照（Prompt 全文） 正常 1–5%；错误/负反馈 100% 90 天 ✅ 最小授权 + 访问审计
模型完整响应 同上 90 天 ✅ 同上
音频原始数据 默认不存；仅经用户授权的质量改进样本 30 天 ✅ 严格授权
知识源文档 全量 长期 按分级 按知识权限
端侧下发包 全量版本 长期 签名 只读

音频默认不存是重要的合规默认值。音频是最高敏感度的数据（含声纹），存储收益（少量 ASR 优化样本）远小于泄漏风险。仅在明确授权的质量改进计划中留存，且短期限。

7.2 数据质量监控

规则类型 示例 告警
及时性 DWD 表应在次日 06:00 前产出 延迟告警
完整性 dwd_turn 中 route_reason 非空率 ≥99% 字段缺失告警
一致性 dws_cost_daily 总额与网关计量对账偏差 ≤0.5% 对账告警
唯一性 trace_id 唯一 重复告警
值域 intent_confidence ∈ [0,1] 异常值告警
波动 日请求量与前 7 日均值偏差 ≤50% 突变告警
Trace 完整性 关键 Span 齐全率 ≥98% 埋点缺失告警

成本对账是必须做的：数仓算出的成本与网关计量、与供应商账单三方对账。任意两方偏差超阈值都说明某处计量有漏，而成本治理建立在计量准确的前提上。

7.3 数据分级与访问控制

级别 表/字段示例 访问方式
L1 公开 汇总指标、匿名聚合 全员可查
L2 内部 能力元数据、配置 按角色
L3 用户行为 dwd_turn、dwd_session 按需申请 + 审计
L4 敏感 上下文快照内容、精确位置 强审批 + 全程审计 + 时限授权
L5 隐私 （不入湖） 不存在于数据平台

8. 合规能力

8.1 数据主体权利响应

sequenceDiagram
    autonumber
    participant U as 用户请求
    participant P as 合规平台
    participant CAT as 元数据/血缘
    participant SYS as 各存储系统
    participant V as 验证
    U->>P: 提交查询 / 删除请求
    P->>CAT: 查询该用户数据分布
    CAT-->>P: 涉及的表 / 索引 / 缓存 / 对象存储清单
    alt 查询请求
        P->>SYS: 汇总导出
        SYS-->>U: 结构化导出包
    else 删除请求
        P->>SYS: 级联删除（数仓 + 向量索引 + 缓存 + 对象存储 + 记忆）
        SYS-->>P: 各系统删除确认
        P->>V: 删除验证（用历史查询检索，确认无法召回）
        V-->>P: 验证通过
        P->>P: 记录合规凭证（永久保留）
        P-->>U: 删除完成通知
    end
要点 说明
血缘驱动 必须靠元数据血缘定位数据分布，不能靠人工记忆
级联完整 数仓、向量索引、缓存、对象存储、记忆中心全覆盖（见 12 文档 4.3）
验证环节 删除后必须验证，否则无法证明合规
凭证留存 删除记录本身永久保留作为合规证据
训练集处理 已进入训练集的数据需记录；已训练模型无法撤回，需在授权条款中明确

8.2 授权范围管理

授权类型 允许用途
基础服务 提供当次服务，不留存用于改进
服务改进 可用于评测、知识补全、指标分析
模型训练 可用于构建训练集
音频留存 可留存音频用于 ASR 优化

授权标记必须在清洗层就打上并贯穿数仓。若在训练集构建时才去查授权，会因为查询成本而被简化甚至跳过。字段化的授权标记使”过滤未授权数据”成为一次 WHERE 条件。

9. 技术选型

组件 首选 备选 说明
消息队列 Kafka Pulsar / RocketMQ 高吞吐 + 分区键 + 生态
流处理 Flink Spark Streaming 会话窗口聚合、轨迹重建
数据湖 Iceberg / Hudi Delta Lake 支持 upsert 与时间旅行（合规删除需要）

批处理调度 Airflow / DolphinScheduler Dagster 依赖编排
特征存储 Feast 自研 PG 特征表 规模决定
对象存储 企业对象存储 MinIO 快照与文档
元数据/血缘 DataHub / OpenMetadata 自研 合规响应刚需
数据质量 Great Expectations / 自研规则引擎 — 规则化监控

9.1 为什么湖格式要支持 upsert

合规删除要求物理删除特定用户的行。传统只追加的存储（纯 Parquet 分区）无法高效删除单个用户数据，只能重写整个分区。Iceberg/Hudi 的行级删除能力是合规刚需，而非性能优化。这是选型时最容易被忽略的硬约束。

10. 成本与规模

10.1 数据量估算（基于 01 文档 6.2 容量模型）

数据 单请求体积 日量（1200 万请求） 说明
骨架 Trace（全部 Span） ~4 KB ~48 GB/日 100% 采集
Token 与成本明细 ~0.5 KB ~6 GB/日 100%
上下文快照（采样 3%） ~25 KB ~9 GB/日 采样
错误与负反馈快照 ~25 KB ~2 GB/日 假设 3% 请求
端侧决策事件 ~0.3 KB ~4 GB/日 100%
合计原始 — ~69 GB/日 ≈ 25 TB/年 压缩后约 1/5

10.2 成本控制手段

手段 节省
列式存储 + 压缩 5–8×
冷热分层（7 天热 / 之后冷） 冷存储成本约 1/5
快照采样（3% vs 100%） 快照部分 30×
长文本转引用（存哈希 + 对象存储） 数仓体积大幅下降
汇总层预聚合 查询成本下降
分区裁剪与索引 查询成本下降
到期自动清除 避免无限增长

观测成本应控制在业务成本的 3–5% 以内。若超过 10%，说明采样策略需要收紧（优先收紧快照，绝不收紧骨架 Trace）。

11. 风险与治理

风险 影响 治理
埋点数据丢失无人察觉 某组件指标为零被误认为无流量 死信队列 + Trace 完整性监控 + 各组件事件数基线告警
指标口径不一致 不同看板数字不同，决策混乱 数据字典 + 单一汇总层 + 口径评审
成本计量不准 成本治理建立在错误数据上 三方对账（数仓/网关/账单）
PII 入湖 合规事故 SDK 脱敏 + 清洗层二次校验 + 定期扫描
无法定位用户数据分布 合规响应无法完成 元数据血缘（DataHub/OpenMetadata）
存储格式不支持行级删除 合规删除只能重写分区，代价极高 选用 Iceberg/Hudi
删除不验证 无法证明合规 删除后检索验证 + 凭证留存
数据量与成本失控 观测成本超业务成本 采样 + 分层 + 到期清除 + 成本占比监控
授权标记缺失 未授权数据进训练集 清洗层打标 + 训练集构建强制过滤
端侧时钟偏移 时间线错乱，链路重建失败 服务端接收时间校正
数仓延迟导致看板滞后 问题发现不及时 关键指标走流式计算，非批处理

12. 演进路线

阶段 数据平台演进 退出准则
