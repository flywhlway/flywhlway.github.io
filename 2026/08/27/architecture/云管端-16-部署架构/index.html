2. 命名空间划分

Namespace 承载 隔离理由 资源配额策略
ingress NLU GPU 需求特殊（ASR），扩缩容特征独立 GPU 配额独立
orchestration Planner + 各 Cloud Agent 业务迭代最频繁，故障域需与平台组件隔离 每 Agent 独立配额
foundation 记忆/知识/能力/边缘框架 有状态、共享故障域需可控 保障型配额（不可被抢占）
model-gateway LLM 网关 + 围栏 + 缓存 全平台唯一模型出口，最高优先级 保障型 + 优先级最高
governance 注册中心 + 管理门户 低 QPS 高可用，与数据面隔离 小额固定配额
inference 自建推理实例 GPU 独占，调度策略特殊 GPU 独占节点池
observability 采集与看板组件 观测不应影响业务 上限配额（防观测挤占业务）

2.1 优先级与抢占

flowchart TB
    P1["PriorityClass: critical-1000<br/>LLM 网关 · 围栏 · Agent 网关"] --> P2["PriorityClass: high-800<br/>Planner · 记忆 · 知识 · 能力中心"]
    P2 --> P3["PriorityClass: normal-500<br/>Cloud Agents · NLU"]
    P3 --> P4["PriorityClass: low-200<br/>管理门户 · 离线任务 · 观测组件"]

围栏必须与网关同优先级。若围栏被驱逐而网关存活，则会出现”模型可调用但输出无管控”的状态——这比整体不可用更危险。二者必须同生共死（同 PriorityClass + PodDisruptionBudget 联动）。

3.2 扩容延迟的应对

flowchart LR
    S["流量突增"] --> D1["检测延迟 30-60 s"]
    D1 --> D2["Pod 调度 10-30 s"]
    D2 --> D3["启动与预热 10-60 s"]
    D3 --> D4["总响应时间 1-2.5 min"]
    D4 --> R["期间靠什么撑?"]
    R --> R1["① 预留缓冲副本<br/>常态利用率控制在 60%"]
    R --> R2["② 限流排队<br/>而非直接拒绝"]
    R --> R3["③ 语义缓存<br/>突增流量常高度重复"]
    R --> R4["④ 定时预扩容<br/>早晚高峰前"]

AI 平台的扩容比传统服务慢得多（模型加载、连接池预热）。因此必须依赖预留缓冲 + 定时预扩容，而不能完全依赖 HPA 被动响应。峰均比 4:1 的场景（见 01 文档 6.2）尤其需要定时策略。

4. GPU 调度与推理部署

4.1 GPU 节点池划分

节点池 用途 GPU 类型 调度策略
pool-llm-serving 主力 LLM 推理 高显存 独占，不与其他负载混部
pool-slm-serving 小模型（分类/抽取/压缩） 中等 可多实例共享单卡（MPS/MIG）
pool-embedding Embedding + Reranker 低显存或 CPU 高密度部署
pool-asr 语音识别 中等 独立（流式，长连接）
pool-training 训练与蒸馏 高显存多卡 与在线推理物理隔离

训练与在线推理必须物理隔离。共享节点池会导致训练任务抢占显存，引发在线推理 OOM。这是最常见且后果最严重的 GPU 调度错误。

4.2 推理服务部署要点

要点 配置
推理引擎 vLLM / SGLang（支持连续批处理与前缀缓存）
连续批处理 开启，最大批次按显存与延迟目标调优
前缀缓存 必须开启（见 10 文档 6.4）
最大序列长度 显式限制，防单请求撑爆显存
预热 启动后跑若干预热请求再加入负载均衡
探针 readiness 需实际推理成功才通过（不仅端口存活）
优雅下线 等待在途请求完成（最长 60 s）
显存监控 显存使用率告警阈值 85%

5. 存储部署

存储 部署形态 高可用 备份 特殊要求
PostgreSQL 主从 + 只读副本 自动故障切换 每日全备 + WAL 归档 记忆事件日志表需长期保留
向量库 集群多副本 副本冗余 索引可重建（保留源数据） 索引重建耗时长，需容量规划
Redis 主从 + Sentinel/Cluster 自动切换 RDB + AOF 会话丢失影响可接受（降级为新会话）
Kafka 多副本（ISR ≥2） Broker 冗余 — 分区键 = trace_id
全文索引 集群多副本 副本冗余 快照 与向量库同步更新
对象存储 企业级 多副本/跨区 版本化 生命周期策略（到期清除）

5.1 向量库容量规划

用途 规模估算 向量维度 索引类型 内存估算
知识库 百万级 chunk 768 HNSW 约 6–10 GB（含图结构）
长期记忆 千万级条目（全用户） 768 HNSW + 分片 需分片
语义缓存 百万级问答 768 HNSW + TTL 约 6–10 GB

向量库的隐性成本是索引重建。更换 Embedding 模型需全量重建，百万级 chunk 的重建可能耗时数小时且期间双份存储。容量规划必须预留重建所需的双份空间（见 09 文档 8.1 影子索引流程）。

7.3 端侧下发的六条铁律

# 铁律 违反后果
1 先下载校验完整再切换（原子切换） 半新半旧状态，行为不可预测
2 必须验签 供应链攻击入口
3 保留上一版本，回滚不依赖网络 故障后无法自救
4 切换后自检（冒烟用例） 问题上线后才被用户发现
5 灰度分批 + 异常自动暂停 一次全量事故
6 大包避开行驶中与移动网络 流量成本与体验问题

配置类变更能做到秒级回滚，是 AI 平台最重要的运维能力。因为大部分效果问题来自配置（提示词、参数、模型选择），秒级回滚意味着故障影响可控制在分钟内。这也是为什么这些变更必须配置化而非硬编码。

9. 灾备与演练

9.1 故障场景与 RTO/RPO 目标（推断设计）

场景 RTO RPO 应对
单 Pod 故障 < 30 s 0 K8s 自动重建
单可用区故障 < 5 min 0 多 AZ 部署，流量切换
单区域故障 < 30 min < 5 min 跨区切换（DNS + 存储副本提升）
外部模型供应商故障 < 1 min 0 Fallback 链（见 10 文档 4.1）
向量库故障 < 10 min 索引可重建 副本切换；降级跳过 RAG
PostgreSQL 主库故障 < 2 min < 1 min 自动故障切换
Redis 故障 < 1 min 会话丢失可接受 降级为无状态单轮
Kafka 故障 < 5 min 埋点可缓冲 本地缓冲 + 恢复后补传
端云网络中断 0（端侧接管） 待同步数据保留 端侧离线闭环

9.2 必做的故障演练

演练 频率 验证目标
主模型供应商全故障 月度 Fallback 链是否真的通到端侧兜底
围栏服务不可用 月度 是否正确 fail-closed（拒绝输出而非放行）
Planner 全故障 季度 规则兜底路由是否生效
记忆/知识服务熔断 月度 降级后是否仍可用且用户可感知
断网 30 分钟 月度 端侧闭环 + 恢复后同步是否正确
单可用区断电 季度 流量切换与容量是否足够
证书批量过期模拟 半年 轮转与宽限期机制
Agent 死循环 月度 三重预算与成本熔断是否触发

最重要的演练是”围栏不可用”。因为它验证的是一个反直觉的行为：系统应当拒绝服务而非降级放行。若演练发现系统”贴心地”跳过了围栏继续输出，那就是一个严重的安全缺陷。

10. 运维手册要点

10.1 关键运维原则

# 原则 说明
1 安全组件不可降级 围栏、认证故障时拒绝服务，不得为可用性关闭
2 性能组件可降级 缓存、知识、记忆、能力中心可熔断降级
3 降级必须可感知 降级事件告警 + 计入 SLO + 用户明确告知
4 配置优先于代码 能配置化的绝不硬编码（为了秒级回滚）
5 端侧 fail-closed 端侧策略不可达时收紧而非放开
6 变更必须有门禁 包括提示词、知识、参数等非代码变更
7 长连接优雅下线 停止接新 → 等存量 → 超时强关并发错误事件
8 训练与推理隔离 物理隔离 GPU 节点池
9 成本熔断常开 单会话成本上限硬约束
10 所有告警带 trace 样例 便于立即排查

10.2 常见故障速查

现象 优先检查 常见根因
首字延迟突增 各 Span 耗时分布 检索变慢 / 模型供应商劣化 / 缓存命中率下降
成本突增 Top 消耗方 + budget_exhausted Agent 循环 / 缓存失效 / 上下文膨胀
回答质量下降但无技术告警 最近的配置变更（prompt/模型/知识版本） 变更未走门禁
大量用户认证失败 证书到期数 + 吊销列表 证书批量过期
缓存命中率骤降 知识版本 / Embedding 版本变更 版本变更触发缓存全失效（预期行为，需容量准备）
某 Agent 全部失败 该 Agent 依赖的工具健康度 MCP Server 故障 / 权限变更
端侧升级失败率高 自检失败原因分布 差分包与基线不匹配 / 存储不足
记忆答错 记忆影响分析视图 记忆污染 → 回溯干预止损
SSE 频繁断连 网关优雅下线日志 / 客户端重连 网关重启 / 中间设备超时
指标为零但有流量 死信队列 + Trace 完整性 埋点 Schema 不合规

配置管理要点 说明
配置与代码分离 配置变更不需重新构建镜像
环境差异最小化 仅连接串与配额不同，逻辑配置一致
敏感配置托管 密钥进密钥管理系统，不进配置文件与镜像

12. 风险与治理

风险 影响 治理
训练任务抢占推理 GPU 在线推理 OOM 物理隔离节点池 + 资源配额
围栏被驱逐而网关存活 输出无管控 同 PriorityClass + PDB 联动
扩容慢导致高峰不可用 用户不可用 预留缓冲 + 定时预扩容 + 限流排队
粗暴重启中断长连接 大量回答中断 优雅下线（60–120 s）
向量库索引重建无容量 无法升级 Embedding 预留双份空间
端侧下发半新半旧 行为不可预测 原子切换 + 自检 + 回滚
端侧下发未验签 供应链攻击 强制签名校验
数据库变更不兼容 发布期间报错 两阶段变更
观测组件挤占业务资源 业务受影响 观测 namespace 上限配额 + 低优先级
灾备从未演练 真实故障时方案失效 月度/季度演练清单（9.2）
配置硬编码 无法秒级回滚 配置化原则（10.1 第 4 条）
跨区强一致引入高延迟 体验劣化 用户归属区域主写 + 异步复制

13. 演进路线

阶段 部署运维演进 退出准则
阶段一 命名空间与优先级划分；围栏与网关联动；配置化改造（提示词/参数/模型权重）；优雅下线；训练推理隔离；基础灾备 配置类变更可秒级回滚；无 GPU 抢占
阶段二 定时预扩容 + 缓冲副本；影子环境；端侧下发六铁律落地（含自检与自动暂停）；月度演练清单执行；多 AZ 完备 高峰无扩容不及 P1；端侧升级失败率 ≤1%
阶段三 多区域就近接入与故障切换；向量库升级流程标准化（影子索引 + 双份容量）；混沌工程常态化；容量与成本自动规划 区域级故障 RTO ≤30 min；演练全部通过
