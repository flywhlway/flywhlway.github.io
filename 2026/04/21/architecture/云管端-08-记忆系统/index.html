2. 三层记忆模型

2.1 短期记忆（Short-Term Memory）

维度 内容
定义 当前会话内的对话历史与临时状态
存储 Redis（Hash + List），TTL = 会话周期（建议 30 min 空闲过期）
内容 最近 N 轮原文（建议 N=3）+ 滚动摘要 + 结构化实体表
Token 预算 ≤ 1500
写入时机 每轮同步写入（轻量，仅追加）
读取 直读，延迟 < 10 ms

滚动摘要机制：

flowchart LR
    T1["轮1原文"] --> T2["轮2原文"] --> T3["轮3原文"] --> T4["轮4"]
    T4 --> C["轮1压缩入摘要"]
    C --> SUM["滚动摘要"]
    T2 & T3 & T4 --> KEEP["保留最近3轮原文"]
    SUM & KEEP --> CTX["短期记忆输出"]
    ENT["结构化实体表<br/>车型/日期/地点/金额<br/>不参与摘要压缩"] --> CTX

实体表是防止信息丢失的关键。自然语言摘要必然丢失具体实体（”上周三”变成”最近”，”3 号充电桩”变成”某个充电桩”）。维护一份键值实体表随上下文传递，可在压缩率与信息完整性之间取得平衡。

2.2 长期记忆（Long-Term Memory）

维度 内容
定义 跨会话持久化的用户事实、偏好、经历
存储 PG（结构化字段 + 事件日志）+ 向量库（语义召回）
内容 事实条目（陈述句形式）+ 元数据
Token 预算 ≤ 800
写入时机 异步（会话结束触发抽取）
读取 向量召回 + 时效衰减加权

记忆条目数据结构（推断设计）：

字段 类型 说明
memory_id string 主键
user_ref string 用户匿名标识
namespace string 命名空间（共享区/Agent 私有区/隐私区）
content text 事实陈述（”偏好安静的驾驶环境”）
category enum 偏好 / 事实 / 经历 / 约束
confidence float 置信度 0–1
source_trace_id string 来源轮次，支撑回溯干预
source_quote text 原始表述片段（供人工核对）
created_at / updated_at ts
valid_until ts 时效边界（可空=长期有效）
access_count / last_access int/ts 用于热度衰减
status enum active / superseded / invalidated
superseded_by string 被哪条记忆取代
embedding_version string 向量模型版本

source_trace_id 与 source_quote 是”回溯干预”能力的技术前提。没有它们，运营人员看到一条错误记忆时无法判断它从哪来、是否该删。这两个字段的成本极低，价值极高。

2.3 用户画像（User Profile）

维度 内容
定义 由行为数据离线聚合的统计特征
存储 特征表（PG / 特征平台）
内容 稳定倾向类字段（活跃时段、内容偏好类型、交互风格、常用能力）
Token 预算 ≤ 300（按意图只取相关字段）
更新 离线批处理（日级）

2.4 三者对比

维度 短期记忆 长期记忆 用户画像
时间尺度 分钟~小时 周~年 周~年
数据形态 对话文本 事实陈述 结构化特征
生成方式 直接追加 模型抽取 统计聚合
精度 高（原文） 中（抽取有误差） 高（统计）
可解释性 高 中（需溯源） 高
主要风险 压缩丢失 污染 更新延迟、冷启动
是否需人工干预 否 是 否

3. 记忆召回（Memory Recall）

flowchart TB
    Q["查询 + 意图"] --> QR["查询改写<br/>提取记忆相关要素"]
    QR --> P1["并行检索"]
    P1 --> V["向量召回 Top-20"]
    P1 --> F["元数据过滤<br/>namespace + status=active + 未过期"]
    P1 --> C["类别定向召回<br/>按意图取相关 category"]
    V & F & C --> FU["融合去重"]
    FU --> W["加权重排"]
    W --> W1["相关性分数 × 0.5"]
    W --> W2["置信度 × 0.2"]
    W --> W3["时效衰减因子 × 0.2"]
    W --> W4["访问热度 × 0.1"]
    W1 & W2 & W3 & W4 --> TK["Top-K 截断（建议 K=5）"]
    TK --> BD["Token 预算裁剪"]
    BD --> OUT["记忆切片 + 来源标记"]

3.1 时效衰减函数（推断设计）

记忆类别 半衰期 理由
基础事实（长期不变的偏好倾向） 无衰减 稳定
一般偏好 180 天 会变化
短期意图（”最近在找充电桩”） 7 天 时效性强
情境状态 1 天 极易过期

衰减因子 = 0.5 ^ (age_days / half_life_days)，与置信度共同作为加权项。

3.2 召回质量的三个陷阱

陷阱 表现 解决
召回过多 记忆挤占知识空间，回答被无关个人信息干扰 硬 K 值上限 + Token 预算 + 相关性阈值
召回错误记忆 比没有记忆更糟（”你说过你不喜欢这个”——但用户从未说过） 置信度阈值（建议 ≥0.7 才注入）+ 抽取质量把控
召回过期记忆 用旧偏好回答新需求 时效衰减 + valid_until + 情境类记忆短 TTL

宁少勿错：一条错误记忆造成的信任损伤，远大于十条缺失记忆带来的体验缺失。置信度阈值应设得保守。

4. 记忆写入与演化

4.1 抽取流程

sequenceDiagram
    autonumber
    participant EV as 会话结束事件
    participant EX as 抽取器（小模型）
    participant DD as 去重/冲突检测
    participant MG as 记忆管理器
    participant ST as 存储
    participant HR as 人工复核队列

    EV->>EX: 完整会话轨迹
    EX->>EX: 抽取候选事实（结构化输出）
    EX-->>DD: 候选列表（含置信度与原文引用）
    DD->>ST: 检索既有相关记忆
    ST-->>DD: 相关记忆集
    DD->>DD: 判定：新增 / 更新 / 冲突 / 丢弃（重复）
    alt 冲突
        DD->>MG: 应用冲突策略
        MG->>ST: 旧记忆标记 superseded + 写新记忆
    else 新增
        DD->>ST: 直接写入
    end
    alt 高风险类别 或 置信度中等
        MG->>HR: 进人工复核（默认不生效）
    end
    MG->>ST: 追加记忆事件日志

4.2 抽取提示词设计要点（推断设计）

要点 说明
只抽取用户明确表达的内容 禁止推断（”用户提到堵车” ≠ “用户讨厌堵车”）
输出结构化 每条含 content / category / confidence / source_quote
明确禁止类别 敏感类别不抽取（健康、财务、身份特征等，按合规要求定义）
时效判定 抽取时即判定是否为情境性（短 TTL）
置信度校准 明确陈述=高；含”可能/也许”=中；间接推断=不抽取

抽取的第一原则是保守。宁可漏抽，不可错抽。记忆污染的修复成本远高于漏抽的体验损失，因为错误记忆会在后续所有会话中持续产生错误影响。

4.3 冲突解决策略

冲突类型 示例 策略
直接矛盾 旧：”偏好 A”；新：”偏好 B” 新的取代旧的（旧记 superseded），保留历史用于溯源
程度变化 旧：”偶尔用 X”；新：”经常用 X” 更新程度，保留同一条
范围细化 旧：”偏好安静”；新：”通话时偏好安静” 保留细化版，旧的降级为一般规则
时效过期 旧情境记忆已过 TTL 自动失效，不视为冲突
来源可信度差异 明确陈述 vs 间接推断 高置信度优先，不因时间新旧覆盖

5. 可视化与回溯干预（图示圈注核心能力）

5.1 为什么这是差异化能力

绝大多数 AI 产品的记忆是黑盒：用户不知道系统记住了什么，运营无法查看与修正。这带来三个无法解决的问题：

  1. 用户投诉”你怎么会这么说”，客服无法定位原因。
  2. 一条错误记忆持续污染所有后续会话，无法止损。
  3. 合规要求”可查询、可删除个人数据”无法满足。

原图把「可视化」与「回溯干预」与短期/长期记忆并列并圈注，说明该架构已经把记忆治理视为一等能力。

        V2["单条溯源<br/>来自哪次会话哪一轮<br/>原始表述片段<br/>抽取模型与版本"]
        V3["记忆时间线<br/>创建/更新/取代/失效 全历史"]
        V4["影响分析<br/>该记忆被哪些会话召回过<br/>影响了哪些回答"]

    end

视图 面向 数据来源 价值
记忆全景 用户 + 运营 记忆表 透明度、合规

影响分析 运营 Trace（记忆召回埋点） 评估错误记忆的影响面
冲突视图 运营 冲突检测结果 主动质量治理

「影响分析」是最容易被忽略但价值最高的视图。发现一条错误记忆后，第一个问题是”它已经影响了多少次回答”。这需要在召回时埋点记录 memory_hits 中的具体 memory_id，成本很低但事后无法补齐。

5.3 回溯干预能力设计

干预动作 效果 权限 是否可逆
单条失效 状态置 invalidated，不再召回 运营 / 用户 可逆（事件日志保留）
单条修正 写新记忆取代旧记忆 运营（需审核） 可逆
置信度调整 手工调整置信度 运营 可逆
类别重划 修正 category 与 TTL 运营 可逆
批量清空 清空某用户/某命名空间全部记忆 用户请求 / 合规流程 不可逆（合规要求硬删除）
抽取回滚 撤销某次抽取产生的全部记忆 运营 可逆
黑名单规则 禁止抽取某类内容（全局生效） 平台管理员 可逆

干预流程：

stateDiagram-v2
    [*] --> 发现问题: 用户投诉 / 冲突检测 / 抽检
    发现问题 --> 定位: 可视化溯源
    定位 --> 影响评估: 影响分析视图
    影响评估 --> 立即止损: 单条失效（秒级生效）
    立即止损 --> 根因分析: 抽取提示词 / 模型 / 会话本身
    根因分析 --> 规则加固: 加入黑名单规则或调整抽取策略
    规则加固 --> 批量修复: 同模式记忆批量扫描处理
    批量修复 --> 回归验证
    回归验证 --> [*]

止损必须秒级生效。这要求失效操作直接作用于在线读路径（缓存同步失效），而不是等下一次批处理。

6. 端侧记忆与端云同步

6.1 端侧记忆的三个分区

分区 内容 是否同步 理由
端侧短期 当前会话 不同步 生命周期短，同步无价值
端侧长期/偏好 设备级偏好、常用操作 双向同步 跨设备一致性
隐私区 用户标记为不上云的内容 永不同步 隐私承诺

6.2 同步与冲突（详见 05 文档 6.1）

sequenceDiagram
    autonumber
    participant E as 端侧记忆
    participant SY as 同步服务
    participant MG as 双向认证网关
    participant C as 云端记忆中心
    E->>SY: 变更集（含变更序号 + 版本向量）
    SY->>MG: mTLS 提交
    MG->>C: 幂等写入（幂等键=设备ID+序号）

        C-->>MG: 接受

6.3 单写者原则

记忆域 唯一写权威 另一端角色
长期事实记忆 云端 Memory Agent 端侧提交候选，不直接写
设备级设置偏好 端侧 云端仅备份
用户画像 云端离线任务 端侧只读缓存
隐私区记忆 端侧 云端无感知

违反单写者原则的后果无法通过增加逻辑修复。若端云都能直接写同一条长期记忆，则必然出现不一致，且随着记忆条数增长，冲突数量呈非线性上升。这是必须在阶段一确定的设计决策。

7. 记忆压缩

压缩层次 对象 方法 触发条件
L1 轮次压缩 单轮对话 保留意图与实体，丢弃寒暄 每轮
L2 滚动摘要 超过窗口的轮次 生成式摘要 + 实体表保护 窗口满
L3 二次压缩 长会话的摘要 摘要的摘要 摘要超预算
L4 长期记忆归并 同类记忆条目 归并为更一般的陈述 同类条目 > 阈值
L5 冷记忆归档 长期未召回的记忆 移出在线索引，保留可查 半年未召回

L4 归并示例（推断设计）：三条记忆”偏好 X 类内容””偏好 Y 类内容””偏好 Z 类内容”（同属一大类）可归并为”偏好该大类内容，尤以 X 为主”。归并需保留原条目引用以支持溯源。

压缩必须保留溯源链。压缩后若丢失原始来源，回溯干预能力立即失效。事件日志的价值在此体现：物化视图可以压缩，事件日志不可变。

8. 技术选型

需求 推荐方案 备选 说明
短期记忆存储 Redis 内存 + 持久化 TTL 与高频读写
长期记忆结构化存储 PostgreSQL MySQL 需事件日志与事务
长期记忆语义检索 pgvector（复用 PG） Qdrant / Milvus 记忆规模通常远小于知识库，pgvector 足够且运维简单
记忆框架 自研（PG + pgvector + 事件表） Mem0 / Zep 自研的理由：回溯干预与命名空间隔离是强定制需求，现成框架难以满足
端侧记忆存储 SQLite + 嵌入式向量（sqlite-vec / usearch） 纯 SQLite + FTS 端侧规模小，量化向量 256 维足够
抽取模型 小模型（成本 1/20） 大模型 抽取是结构化任务，小模型足够
画像特征存储 PG 特征表 Feast / HBase 按规模选择

8.1 为什么建议自研记忆层

需求 现成框架支持度 说明
命名空间隔离与私有区 弱 多数框架单一记忆空间
事件溯源 + 回溯干预 弱 多数框架只存最终状态
端云同步与单写者 无 完全是本架构特有需求
置信度与时效衰减 部分 需定制权重
合规硬删除 部分 需贯穿向量索引

结论：用现成框架快速验证效果，用自研方案承载生产。这也符合原图把记忆中心做成完整子系统（含可视化与干预）而非引入一个库的判断。

9. 记忆系统评测

指标 定义 目标（推断设计）
抽取准确率 抽取事实与人工标注一致比例 ≥ 90%
抽取错误率（严重） 抽出用户未表达内容的比例 ≤ 1%
召回相关率 召回记忆与当前查询相关的比例 ≥ 80%
召回错误影响率 因错误记忆导致回答错误的比例 ≤ 0.5%
冲突检出率 矛盾记忆被检出的比例 ≥ 95%
干预生效延迟 失效操作到在线不再召回 ≤ 5 s
个性化增益 有记忆 vs 无记忆的满意度差 ≥ +15%
记忆规模 单用户活跃记忆条数 50–300（超出需归并）

“记忆规模”是健康度指标。单用户记忆超过数百条通常意味着抽取过于宽松或归并缺失，此时召回精度会显著下降。

10. 风险与治理

风险 影响 治理
记忆污染 错误记忆持续影响所有后续会话 保守抽取 + 置信度阈值 + 冲突检测 + 回溯干预 + 抽检
