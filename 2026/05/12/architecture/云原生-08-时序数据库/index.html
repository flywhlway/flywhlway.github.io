一、概述

本文档描述了大数据平台（DF）在时序数据库领域的关键技术方案。该方案旨在解决传统Hive/ClickHouse等关系型OLAP数据库在时序分析场景下算力消耗过大、”算不动”的痛点，通过引入专业时序数据库IoTDB，构建完整的时序数据处理链路。

二、解决痛点

当前趋势与挑战

  • Hive和ClickHouse等关系型OLAP数据库在故障分析、时序分析等场景中消耗大量算力，无法进行有效计算
  • 随着车辆增加，车端海量数据上传量持续增长
  • 部分业务场景的计算面临”算不动“的困境

主要优势

  • 时序业务场景下，数据查询处理能力显著增强

三、技术架构（左半部分 - 整体定位）

展示时序数据库在现有大数据集群架构中的定位：

架构层 组件
业务应用层 售后质量、能源体验、升级体验、座舱体验、智驾体验
数据存储分析层 离线存储分析平台（Hive/MySQL/Spark/HDFS）→ 实时存储计算平台（ClickHouse/Flink）→ 🔵时序存储计算平台（IoTDB/TsFile）
数据加工层 Kafka → 实时解析 → 实时解码 → Flink/Spark
原始数据层 智能车（3代电子电器架构：IAM智联域/ICC智算域/ICM智能域/IPD智驾域）+ 业务系统（MES/TSP/OTA/RDS/VSOC）+ 手机App/充换电

关键信息：时序存储计算平台（IoTDB + TsFile）是在现有大数据集群架构中新增的第三个存储分析平台。

六、关键技术洞察

  1. 三平台并立：离线(Hive)+实时(ClickHouse/Flink)+时序(IoTDB)三大存储计算平台互补
  2. IoTDB选型：Apache IoTDB原生支持产业物联网时序场景，TsFile格式提供极致压缩和查询性能
  3. 算力瓶颈破解：将时序分析从通用OLAP迁移至专业时序库，解决”算不动”问题
  4. 湖仓融合：时序数据库与Hive数据湖打通，实现冷热数据分层
  5. AI赋能：时序数据直接对接AI算法层，支持异常检测和预测分析
