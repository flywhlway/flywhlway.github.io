1. 方案详述（来源：LobeHub 功能调研与部署-dify深度研究DSL）

下面给你一份Dify v1.12.1 / Workflow 模式 / DSL v0.5.0 的企业版工作流 DSL，已将「搜索模块」替换为：

  • ✅ Tavily（默认必跑）
  • ✅ SearXNG（自建备选，配置了就自动参与）
  • ✅ Brave Search API（备选，配置了就自动参与）
  • ✅ 混合搜索聚合：三路结果统一解析 → 合并去重 → 域名黑白名单/每域名上限 → 进入证据流水线

实现方式为：在 Search Round Iteration 内并行/串行调用三路搜索，每个搜索节点都设置 error_strategy: default-value，所以即使你不配置 SearXNG/Brave，也不会影响导入与运行（只会使用 Tavily 的结果）。

✅ 可直接导入 DSL（企业版：Tavily + SearXNG + Brave 混合搜索）

导入后在 Environment Variables 填：

  • TAVILY_API_KEY（必填）
  • SEARXNG_BASE（可选，例如 http://searxng:8080）
  • BRAVE_API_KEY（可选）

2. 方案详述（来源：LobeHub 功能调研与部署-dify深度研究DSL）

下面给你一份 Dify v1.12.1 / Workflow 模式 / DSL v0.5.0 的企业私有化可落地版「Manus 深度研究」工作流 DSL（YAML），在不改 DSL 版本、不破坏可导入性前提下，完成你提出的升级点：

✅ 多轮 Iteration（Search Round 1..N）：按 search_queries[] 自动跑 N 轮搜索
✅ 来源去重 + 站点黑白名单 + 每域名上限：防刷屏、过滤低质站、控制覆盖面
✅ 证据缓存（同一次运行内）：跨轮去重 + 避免重复抓取同 URL（“运行内缓存”）
✅ 结构化引用输出：生成 BibTeX + GB/T 7714 两种格式（基于 URL/标题/访问日期，可落地）
✅ 标准化模块：Search Round Iteration → 聚合器 → Evidence Iteration → 总核查 → 报告排版 → 引用附录

重要说明（务实）：

  1. “跨运行持久化缓存”（例如把抓取结果缓存到 Redis/DB，下次直接复用）在纯 DSL 内不可靠，因为 v1.12.1 的 Workflow 更偏“单次运行编排”。企业版建议用一个 HTTP 缓存服务（可选），我已经预留了节点位（默认关闭，不影响导入）。
  2. 引用格式（BibTeX/GB/T）在不额外抓取 metadata 的情况下，最稳定做法是用 URL + title + access date 生成（可审计、可复现）。如果你要 DOI/期刊信息，需要额外接 Crossref/元数据抓取服务。

✅ 可直接导入的 DSL（企业可落地版）

复制为：manus_research_enterprise_v1_12_1.yml，在 Dify → Studio → Workflow → Import DSL 导入即可。

导入后请到 Environment Variables 填：

  • SERPER_API_KEY（必填，否则搜索节点会返回空）
  • DOMAIN_WHITELIST / DOMAIN_BLACKLIST（可选）
  • MAX_PER_DOMAIN（建议 2~3）
  • CACHE_SERVICE_BASE（可选，启用跨运行缓存时用）
