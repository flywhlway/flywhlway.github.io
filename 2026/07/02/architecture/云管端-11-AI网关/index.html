11 · AI 网关体系（AI Gateway）

文档类型：架构设计说明书 · 网关专章
对应图示：Agent 网关（SSE 流式 / A2A 桥接 / 内容安全）+ 语音网关 + 双向认证网关 + LLM 网关
说明：本架构有 4 个网关，职责严格分离。把它们合并成一个”大网关”是最常见的架构错误

1.1 为什么必须分开

网关 流量特征 资源模型 合并后的问题
① 语音网关 高带宽长连接、持续流 连接数与带宽受限 音频占满连接池 → API 请求排队
② Agent 网关 请求响应 + 长耗时流式 CPU 与连接双约束 与音频混部互相拖垮
③ 双向认证网关 大批量、低频、可延迟 带宽突发 同步大包挤占交互带宽
④ LLM 网关 内网出口、极长耗时 上游依赖不可控 外部模型故障影响端侧接入

核心判断：网关的分离依据是流量特征与故障域，不是功能。四种流量的资源模型完全不同，任意两者合并都会导致故障传播。原图把三个网关并列画在「管」层、LLM 网关画在云内，正是这一判断的体现。

2. Agent 网关（图示圈注核心）

2.1 处理流水线

flowchart LR
    IN["端侧请求"] --> A1["① TLS 终止"]
    A1 --> A2["② 身份认证<br/>证书派生身份"]
    A2 --> A3["③ 入站内容安全<br/>规则同步 + 模型异步"]
    A3 --> A4["④ 授权<br/>能力 ID 校验 + 权限"]
    A4 --> A5["⑤ 限流配额<br/>四维"]
    A5 --> A6["⑥ 流量染色<br/>灰度标记"]
    A6 --> A7["⑦ A2A 寻址<br/>目标解析 + 权限交集"]
    A7 --> A8["⑧ 协议转换<br/>HTTP → 内部 RPC"]
    A8 --> OUT["Planner"]
    OUT -.->|"流式结果"| A9["⑨ SSE 封装<br/>分片 + id + 心跳"]
    A9 -.-> IN

顺序不可调换的三条约束：

约束 原因
内容安全在授权与转发之前 违规请求越早拒绝，消耗的下游资源越少
能力 ID 校验在限流之前 未注册能力应直接拒绝，不占用配额
SSE 封装在最后 只有拿到结果流才能封装；且需与内容安全分段校验协同

2.2 认证与身份

身份类型 来源 是否可自报 用途
设备/车辆身份 mTLS 客户端证书派生 否 设备级限流、能力可见性、审计
用户身份 OIDC 令牌 / 会话票据 否 记忆命名空间、权限、画像
Agent 身份 注册中心签发的 Agent 凭据 否 A2A 鉴权、能力权限
会话标识 网关签发 否 短期记忆边界、限流粒度

绝对禁止业务层自报身份。若请求体中的 user_id 被信任，则任何设备都可冒充任意用户读取其记忆。身份必须由传输层凭据派生。

2.3 限流与配额（四维模型）

flowchart TB
    R["请求"] --> D1{"维度1: 设备<br/>防单车异常"}
    D1 --> D2{"维度2: 用户<br/>防单用户滥用"}
    D2 --> D3{"维度3: Agent<br/>防单业务打满"}
    D3 --> D4{"维度4: 意图/Skill<br/>防单能力雪崩"}
    D4 --> P["通过"]
    D1 & D2 & D3 & D4 -->|"超限"| L["排队 / 拒绝 / 降级"]
维度 限流单位 建议策略
设备 请求数/分钟 + Token/分钟 宽松（正常用户不会触发），异常值告警
用户 Token/小时 中等，防滥用
Agent Token/s + 并发数 严格，按 Agent 独立配额
意图/Skill 并发数 保护下游脆弱能力（如三方 MCP）

AI 网关与传统 API 网关最本质的差异：限流单位必须是 Token/s 而非 QPS。一个 100k token 的请求与一个 100 token 的请求，QPS 相同但资源消耗差 1000 倍。仅按 QPS 限流的网关在 AI 场景下几乎无效。

2.4 SSE 流式实现要点

要点 实现 不做的后果
首包快返 立即发送 event: start（含 trace_id） 客户端不知道是否已连上
事件 id 每个分片带自增 id 断线无法续传
断线续传 支持 Last-Event-ID 请求头 弱网下用户看到内容重来
心跳 每 15 s 发送注释行保活 中间设备超时断连
背压 客户端消费慢时缓冲上限 + 丢弃策略 网关内存被拖垮
结束事件 event: done 含统计信息（token、耗时、引用） 客户端不知道何时结束
错误事件 event: error 含可读原因与是否可重试 客户端无法正确处理失败
分段安全校验 与围栏协同，逐片放行 违规内容已经推给用户

SSE 事件设计（推断设计）：

事件类型 载荷 说明
start trace_id、预计能力 建连确认
delta 文本增量 主内容流
tool 工具名、状态 让用户看到”正在查询…”
citation 引用元数据 知识来源
degraded 降级原因 明确告知能力受限
done token 统计、耗时 结束
error 错误码、可重试标记 失败

tool 事件对体验影响很大：工具调用可能耗时数秒，若期间没有任何反馈，用户会认为卡死。推送”正在查询充电桩信息…”可显著改善感知延迟。

2.5 A2A 桥接（安全模型见 07 文档 4.1）

能力 说明
目标寻址 Agent ID → 实际服务端点（经注册中心解析）
权限交集 有效权限 = 调用方权限 ∩ 目标权限 ∩ 用户授权
深度限制 A2A 调用链深度 ≤ 3，防循环
环检测 调用链记录，检测 A→B→A
协议协商 版本兼容检查
超时传递 剩余预算随调用传递，防总耗时失控

3. 语音网关

能力 要点
长连接管理 连接数配额、空闲回收、优雅重启（不断连）
编解码协商 支持多编码，按带宽自适应
会话粘性 同一音频会话固定到同一 NLU 实例（流式 ASR 有状态）
抖动缓冲 平滑网络抖动，避免识别中断
带宽自适应 弱网降码率而非断连
独立限流 与 API 配额池分离

3.1 SLI 定义

SLI 目标 说明
首字识别延迟 P95 ≤ 400 ms 从用户开口到首个识别字返回
音频链路断连率 ≤ 0.5%
丢包重传率 ≤ 2%
连接建立成功率 ≥ 99.9%

4. 双向认证网关

能力 要点
mTLS 双向证书校验，客户端证书由制造阶段注入根证书派生
证书生命周期 短周期证书 + 自动轮转；吊销校验（CRL/OCSP）
防重放 nonce + 时间窗（建议 ±5 min）+ 已用 nonce 缓存
幂等 幂等键 = 设备 ID + 变更序号
断点续传 大批量同步支持分片与续传
带宽治理 同步流独立带宽配额；行驶中抑制大包
身份到租户映射 设备身份 → 数据分区，防跨车数据访问

4.1 证书管理是最易失守的环节

flowchart TB
    M["制造阶段<br/>注入设备根证书 + 私钥（HSM 保护）"] --> A["激活阶段<br/>派生业务证书"]
    A --> R["运行阶段<br/>定期自动轮转（如 90 天）"]
    R --> E{"轮转失败?"}
    E -->|是| E1["告警 + 宽限期<br/>宽限期内仍可用"]
    E1 --> E2{"宽限期内恢复?"}
    E2 -->|否| E3["降级为只读同步 + 强制告警"]
    E -->|否| R
    R --> RV["吊销场景<br/>设备被盗/私钥泄露/报废"]
    RV --> RVL["加入吊销列表<br/>网关实时校验"]
风险 治理
私钥泄露 HSM/TEE 保护，不可导出
证书过期未轮转 提前 30 天开始轮转尝试 + 宽限期 + 告警
吊销不及时 吊销列表实时生效（缓存 TTL ≤ 5 min）
无法批量吊销 支持按批次/型号批量吊销能力

5. LLM 网关

模型路由、缓存、Fallback 的详细设计见 10 文档。本节聚焦其网关属性。

网关能力 说明
统一出口 所有模型调用的唯一出口（P2），禁止业务直连
凭据托管 供应商 API Key 集中管理，业务不接触
Prompt 审计 全量记录（采样存储）Prompt 与响应，供合规与排查
Token 计量 唯一权威计量口径
内容安全联动 出站结果送安全围栏
出网管控 出网白名单（只允许访问已审核的模型端点）
成本归因 cost_tag 强制
配额与熔断 见 10 文档

5.1 为什么凭据必须托管在网关

若业务持有 Key 后果
Key 散落在各服务配置中 泄露风险高、轮转困难
无法统一计量 成本无法归因
无法统一审计 合规无法满足
可绕过网关直连 安全围栏、缓存、限流全部失效

判定平台是否真正收口的唯一标准：搜索全部代码库，是否存在除网关外的任何组件持有模型供应商凭据。若有，收口是名义上的。

6. MCP 网关能力（能力中心内嵌）

MCP 工具调用虽不经独立网关，但需具备网关级治理（推断设计）：

能力 说明
凭据托管 每个 MCP Server 独立凭据，由平台托管
出网白名单 只允许访问已审核的 MCP 端点
权限最小化 按 Agent × Server 授予最小工具集
超时与重试 独立超时（建议 3 s），非幂等操作不重试
结果校验 按声明 Schema 校验
结果隔离 标记为不可信外部数据
调用审计 全量记录调用方、参数、结果摘要
熔断 单 Server 故障不影响其他
版本锁定 Server 声明变更需重新审核

7. 网关可观测

层 指标
连接层 连接数、建连成功率、断连率、TLS 握手耗时
认证层 认证成功/失败率、证书即将过期数、吊销命中
安全层 入站拦截率、拦截原因分布、误拦截反馈数
限流层 各维度触发次数、排队时长、拒绝率
路由层 各目标分流比例、route_reason 分布
流式层 首包延迟、SSE 事件数、重连次数、背压丢弃数
成本层 Token/s、成本、缓存命中率、Top 消耗方

7.1 网关必备的三个告警

告警 阈值 原因
认证失败率突增 > 基线 3× 可能是证书批量过期或攻击
首包延迟 P95 劣化 > 目标 1.5× 直接影响用户感知
降级率持续升高 > 1% 持续 5 min 隐性故障（可用但一直降级）

8. 网关部署与容量

网关 部署形态 弹性 关键容量约束
语音网关 独立集群，就近 POP 按连接数扩容 连接数、带宽
Agent 网关 独立集群，多 AZ HPA（并发 + Token/s） 并发连接、CPU
双向认证网关 独立集群 按同步流量扩容 带宽、TLS 握手 CPU
LLM 网关 K8s 独立 namespace HPA + 连接池预热 上游并发上限、缓存内存

8.1 优雅重启（长连接场景的关键）

sequenceDiagram
    autonumber
    participant LB as 负载均衡
    participant OLD as 旧实例
    participant NEW as 新实例
    participant C as 客户端
    LB->>NEW: 启动并就绪探测通过
    LB->>OLD: 摘除新流量（保留存量连接）
    OLD->>C: 现有 SSE 流继续直到完成
    OLD->>C: 新请求返回 503 + 重定向提示
    Note over OLD: 等待存量连接自然结束（上限 60 s）
    OLD->>OLD: 强制关闭剩余连接（发送 error 事件）
    OLD->>LB: 下线

AI 网关的重启比传统网关困难得多：单个 SSE 流可能持续 30 s+。粗暴重启会导致大量用户回答中断。必须实现”停止接新、等存量结束、超时强关并发送错误事件”三段式优雅下线。

9. 技术选型

网关 首选 备选 说明
Agent 网关 Higress / Envoy + AI 插件 Kong / APISIX / 自研 Go 需 Token 级限流与 SSE 支持
语音网关 自研（Go/Rust）或商用 RTC 网关 gRPC 双向流 长连接与音频特化
双向认证网关 Envoy（mTLS）+ 自研业务层 Nginx + 自研 PKI 集成
LLM 网关 LiteLLM（起步）→ 自研/Higress AI（规模化） Portkey 起步用现成，规模化后自研以承载定制治理
服务网格（云内） Istio / Linkerd 自研 mTLS 云内服务身份与加密
工作负载身份 SPIFFE/SPIRE 云厂商 IAM 服务间身份

9.1 自研 vs 开源的决策点

场景 建议
起步验证（0–6 月） 用开源（LiteLLM + Higress），快速跑通
Token 级限流、成本归因、缓存联动等定制治理 逐步自研插件而非替换整个网关
语音与端云同步网关 自研（业务特化程度高，开源方案不匹配）
完全自研全部网关 ❌ 不推荐（重复造轮子，安全风险高）

10. 风险与治理

风险 影响 治理
网关合并导致故障传播 音频问题影响 API，模型故障影响接入 四网关物理隔离、独立配额与故障域
身份可自报 冒充任意用户读取记忆 身份仅从传输层凭据派生
仅按 QPS 限流 大 Token 请求打满资源 Token/s + 并发双维度
长连接数耗尽 无法建连 连接配额 + 空闲回收 + 就近 POP + 扩容
粗暴重启中断流式 大量回答中断 三段式优雅下线
入站安全成为瓶颈 首字延迟劣化 轻量规则同步 + 模型检测异步 + 流式复检
证书过期批量失效 大面积不可用 提前轮转 + 宽限期 + 到期数监控告警
业务持有模型凭据 收口失效 凭据集中托管 + 代码扫描审计
SSE 无续传 弱网体验差 Last-Event-ID + 幂等续传
A2A 身份透传越权 权限提升攻击 权限交集 + 每跳鉴权 + 深度限制
误拦截无反馈通道 正常请求被拦且无人知 拦截样本抽检 + 用户申诉通道 + 规则调优闭环

11. 演进路线

阶段 网关演进 退出准则
阶段一 四网关职责分离落地；身份从凭据派生；能力 ID 强制校验；Token/s 限流；LLM 网关收口全部模型凭据 代码库中无旁路调用与散落凭据
阶段二 SSE 续传与优雅下线；入站安全异步化；A2A 权限交集模型；语义缓存接入 LLM 网关；成本归因看板 首字延迟达标；降级率 ≤1%；成本可下钻
阶段三 自研治理插件替代通用能力；多区域就近接入；网关侧智能路由（按实时质量与成本动态调权）；MCP 网关能力独立化 网关成为可持续演进的平台组件而非瓶颈
