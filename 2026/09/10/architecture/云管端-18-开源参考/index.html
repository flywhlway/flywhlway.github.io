文档类型：架构参考 · 选型对照表
说明：以下为按能力域组织的候选方案清单，含成熟度判断、适配性评估与选型决策要点。所有评价为工程视角的一般性判断，具体选型需以实际压测与业务约束为准。
时效提示：AI 基础设施生态演进极快，本清单需每季度复审。

1. 选型方法论

1.1 五维评估框架

flowchart TB
    E["候选方案"] --> D1["① 能力匹配度<br/>是否覆盖本架构必需能力"]
    E --> D2["② 成熟度<br/>生产案例 · 社区活跃 · 版本稳定性"]
    E --> D3["③ 可运维性<br/>部署复杂度 · 可观测 · 故障恢复"]
    E --> D4["④ 可退出性<br/>数据迁移成本 · 是否锁定"]
    E --> D5["⑤ 总成本<br/>许可 + 硬件 + 人力维护"]
    D1 & D2 & D3 & D4 & D5 --> R["决策"]

1.2 本架构的关键筛选条件

能力域 一票否决条件（不满足则淘汰）
模型网关 不支持流式；不支持 Token 级计量；无多厂商适配
向量库 不支持元数据过滤；不支持混合检索
API 网关 不支持 SSE；不支持自定义限流维度
数据湖格式 不支持行级删除（合规删除刚需，见 15 文档 9.1）
可观测 不支持自定义 Span 属性（GenAI 六必填字段）
Agent 框架 无法外置状态（无法水平扩展）；无终止条件机制
推理引擎 不支持连续批处理或前缀缓存
记忆方案 不支持命名空间隔离；不保留写入来源（无法回溯干预）

2. Agent 编排与框架

方案 语言 成熟度 本架构适配性 关键优势 关键局限
LangGraph Python 高 ⭐⭐⭐⭐⭐ 状态图显式可控、Checkpoint 原生、条件边适合 Planner Python 栈；图定义有学习曲线
Temporal 多语言 很高 ⭐⭐⭐⭐⭐（外层流程） 持久化执行、副作用幂等、重放能力 非 AI 专用，需自行封装 LLM 调用
Spring AI / Spring AI Alibaba Java 中高 ⭐⭐⭐⭐（Java 栈团队） 与企业 Java 生态无缝；Spring 生态治理能力 Agent 高级能力相对薄
LlamaIndex Workflows Python 中高 ⭐⭐⭐⭐ 与 RAG 能力一体 编排能力弱于 LangGraph
AutoGen Python 中 ⭐⭐（研究用） 多 Agent 会话范式 自由讨论模式不适合生产 SLA
CrewAI Python 中 ⭐⭐ 角色分工直观 可控性与可观测偏弱
Dify / n8n 低代码 中高 ⭐⭐⭐（快速验证/内部工具） 上手快、可视化 深度定制受限，不适合承载核心链路

推荐组合：Temporal（外层流程骨架）+ LangGraph（节点内 Agent） —— 流程可靠性与 Agent 灵活性兼得（见 04 文档 A4）。

方案 成熟度 适配性 命名空间隔离 来源溯源 端云同步 结论

15. 综合推荐栈（两套）

15.1 Python 主导栈（推荐给算法能力强的团队）

flowchart LR
    A["LangGraph + Temporal"] --> B["LiteLLM → Higress AI"]
    B --> C["vLLM 自建 + 外部 API"]
    A --> D["LlamaIndex 底座<br/>Qdrant + ES + BGE + BGE-Reranker"]
    A --> E["记忆：PG + pgvector + 事件表（自研）"]
    A --> F["OTel + Langfuse + Prometheus + Grafana + Loki"]
    F --> G["Kafka + Flink + Iceberg + ClickHouse + DataHub"]
    G --> H["LLaMA-Factory（SFT/DPO/蒸馏）"]

15.2 Java 主导栈（推荐给企业 Java 生态深厚的团队）

flowchart LR
    A["Spring AI Alibaba + Temporal(Java SDK)"] --> B["Higress AI Gateway"]
    B --> C["vLLM 自建 + 外部 API"]
    A --> D["自研 RAG 底座<br/>Elasticsearch（混合检索）+ BGE"]
    A --> E["记忆：PG + pgvector（自研）"]
    A --> F["OTel Java Agent + Langfuse + Prometheus"]
    F --> G["Kafka + Flink + Iceberg + Doris"]
    G --> H["Python 侧独立训练栈（LLaMA-Factory）"]

混合栈是常态：在线服务用 Java（复用企业治理与运维体系），算法与训练用 Python。二者通过 gRPC/HTTP 与统一的模型网关解耦。不要为了”技术栈统一”而强行让算法团队用 Java 做训练。

16. 生态风险提示

风险 说明 应对
AI 基础设施迭代极快 半年前的最佳选择可能已被超越 每季度复审本清单；架构层面保持可替换（意图化调用、标准协议）
MCP 规范仍在演进 版本变更可能带来兼容问题 版本锁定 + 适配层隔离
开源项目治理风险 单一公司主导的项目可能改许可证 优先选基金会托管或多方参与项目；评估退出成本
向量库锁定 索引格式不通用，迁移需全量重建 保留源数据与 embedding_version，确保可重建
商业服务数据出境 合规风险 敏感数据链路优先自建或境内服务
模型许可证 部分开源模型有商用限制 注册中心记录许可证；法务审核
过度依赖单一供应商 涨价/限流/停服 多源冗余 + 意图化调用（换模型 = 配置变更）
