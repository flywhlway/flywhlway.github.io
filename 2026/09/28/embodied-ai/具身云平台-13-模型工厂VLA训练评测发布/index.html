第 13 章 模型工厂：VLA 训练、评测与发布

平台工程师不训练 SOTA 模型，但要搭建让模型可重复地被生产、被检验、被安全交付的工厂。

Flywhl 10 分钟 发布于 2026.09 #VLA#MLOps#模型评测

先读结论

  1. 骨干加动作头：动作头类型决定端侧时延旋钮。
  2. 模型三契约：观测、动作、运行，加载时断言。
  3. 五元组复现：基座、数据集哈希、代码、配置、种子。
  4. 三级评测：离线、仿真、真机，分组报告。
  5. 评测对象即发布对象：评测直接加载发布制品。

本章定位：平台工程师不训练 SOTA 模型，但要搭建让模型可重复地被生产、被检验、被安全交付的工厂。本章用工程视角讲 2026 年的 VLA 谱系、模型三契约、LeRobot 工作流、训练编排与可复现、三级评测与评测 CI、模型注册与发布晋级链，以及“从部署经验中学习”对平台的新要求。
对应代码：p03（数据集清单 → 训练输入）、p02（模型制品与灰度）｜建议学时：5 小时

13.1 平台视角的模型

13.1.1 模型是制品生产线的产物

对算法团队，模型是研究成果；对平台，模型是一条生产线的产物：输入是数据集清单与训练配置，经过训练、评测、适配、签名，输出是可以灰度发布的制品。平台要保证这条线可重复（同样的输入得到同样的输出）、可检验（每一步都有门禁）、可追溯（任何线上模型都能追到数据与代码）。

13.2 2026 年 VLA 谱系（工程视角）

13.2.1 架构共识：骨干 + 动作头

主流 VLA 可以理解为 视觉语言骨干（VLM）+ 动作头：骨干负责“看懂场景、听懂指令”，动作头负责把理解变成连续动作。动作头的主要形态：

动作头 原理（一句话） 平台关注点
离散化 token 把动作量化成词表里的 token，像生成文字一样生成动作 推理步数多，时延随动作维度增长
直接回归 直接输出连续动作 最快，但多峰动作表达能力弱
扩散 / 流匹配 从噪声逐步“去噪”出一段动作（动作块） 质量好；去噪步数是时延旋钮

GR00T N1.7 就是“VLM 骨干 + 扩散 Transformer 动作头”的代表；π 系列使用流匹配动作专家。对平台而言，动作头类型决定了端侧时延的主要旋钮，要写进模型卡。

13.2.2 值得跟踪的模型与获取方式

模型 形态 获取方式 平台含义
π0.7 / π*0.6 / MEM 通用操作策略、经验强化学习、长时记忆 合作授权；早期版本开源（openpi，支持 PyTorch） 长任务与经验学习对任务面、数据面提出新要求
GR00T N1.7 3B，人形与跨本体，Apache 2.0 开源权重，已进入 LeRobot 推理约需 16GB 显存，微调约需 40GB 以上
Gemini Robotics ER 2 具身推理（慢脑） 经 Gemini API 公开可用 典型“云端调用型”能力，走 AI 网关（第 15 章）
Gemini Robotics On-Device 2 端侧 VLA 受信测试 端侧 VLA 商业供给在形成
开源小模型（如 SmolVLA、OpenVLA 系列） 轻量、易微调 开源 教学、原型、低算力机型

13.2.3 三种获取策略

策略 适用 平台工作重点
调用 API 慢脑推理、快速验证 网关、限流、计费、断网兜底、数据出境评估
微调开源基座 大多数企业 数据集、训练编排、评测、引擎矩阵
自研基座 头部公司 以上全部 + 大规模训练集群

绝大多数团队处在第二种。这也意味着模型工厂的核心不是“训练框架”，而是“数据集 → 微调 → 评测 → 发布”的流水线效率。

13.3 模型三契约

13.3.1 契约内容

契约 内容 违反后果
观测契约 相机名称与数量、分辨率、帧率、状态向量维度与顺序、归一化方式 模型“看错”：能跑，但输入语义错位
动作契约 动作空间（关节/末端增量）、维度与顺序、坐标系、动作块长度、执行频率、反归一化统计量 机器人“乱动”——最危险
运行契约 热稳态 P99 时延、显存、精度、所需算子 卡顿、OOM、加载失败

13.3.2 运行时断言

契约必须在加载时被机器检查，而不是写在文档里：

p02 的兼容检查已经在云端和端侧校验了“动作空间”，这里把它扩展成完整的契约断言。

13.4 LeRobot 工作流

13.4.1 一条开源的端到端链路

LeRobot 把“采集 → 数据集 → 训练 → 评测 → 部署”组织成一套统一的库与格式，2026 年又接入了 GR00T 与 Isaac 遥操作工具。平台团队的价值在于把它从单机脚本变成机队级流水线：

LeRobot 单机形态 平台化形态
本地录制演示 机队触发回传 + 遥操作采集会话管理（第 12 章）
本地数据集目录 不可变清单 + 湖仓 + 血缘
单机训练命令 训练任务模板 + GPU 队列 + 实验追踪
本地评测 评测 CI + 场景包 + 门禁
手动部署到机器人 引擎矩阵 + 签名 + 灰度

13.4.2 训练任务的最小描述

五元组（基座、数据集哈希、代码提交、配置、种子）决定一个模型。缺任何一项，三个月后都无法复现，也无法回答“这个模型为什么在 sh-02 表现差”。

13.5 训练编排与可复现

13.5.1 GPU 池：共池不共队列

训练、评测、仿真渲染、数据处理都需要 GPU，但负载特性完全不同：训练是长任务、要稳定；评测是批量短任务、要快；仿真渲染吃显存与图形能力。做法是共用资源池，分设队列与配额，评测队列设较高优先级——评测排队是飞轮转速的常见瓶颈（第 12 章）。

13.5.2 实验追踪

每次训练记录：五元组、损失曲线、检查点、离线评测结果、资源消耗。实验追踪系统与模型注册表打通：只有被追踪的实验产出的检查点，才能被登记为候选模型。

13.6 三级评测

13.6.1 离线、仿真、真机

级 做法 能发现什么 局限
L1 离线 在保留集上做开环回放：比较预测动作与真实动作 明显退化、特定分组退化 开环≠闭环：误差会在闭环中累积
L2 仿真 在仿真场景包中闭环执行，统计成功率 闭环行为问题、安全问题 Sim2Real 差距（第 14 章）
L3 真机 影子评测 → 灰度环（第 9 章） 真实分布下的表现 成本高、周期长

13.6.2 评测集治理四条

  1. 分组：按场景、物体类别、站点、光照分组报告，只报总分会掩盖局部退化（第 9 章反光包装案例）；
  2. 冻结：评测集版本化且冻结，只能新增分组、不能悄悄替换样本；
  3. 防泄漏：评测片段与训练片段按片段哈希严格隔离（p03 的哈希划分），同一片段衍生的数据不能跨集合；
  4. 来源多样：一部分来自线上失败与介入（难例），一部分来自随机基线（常态）。

13.6.3 评测即 CI

flowchart LR
  C["候选检查点"] --> E1["离线评测<br/>分组指标"]
  E1 -->|任一关键分组退化 > 阈值| X["打回 + 失败样本"]
  E1 --> E2["仿真评测<br/>高相关场景包"]
  E2 -->|成功率低于基线| X
  E2 --> P["进入适配与发布"]

评测结果自动写入模型卡与注册表，门禁配置本身版本化（第 9 章结论：门禁指标集合也是需要评审的制品）。

13.7 模型注册与发布晋级链

13.7.1 三权分立

组件 管什么 不管什么
模型注册表 元数据：谱系、五元组、评测结果、晋级状态、模型卡 不存字节
制品库 字节：权重、引擎、签名 不决定能否发布
OTA 面 搬运与灰度 不评估模型好坏

三者分离，任何一方都无法单独让一个模型上线——这是模型治理的第一道防线。

13.7.2 晋级链

dev → staging（离线+仿真通过）→ shadow（真机影子）→ canary（环 0/1）→ ga（全量）→ deprecated。每次晋级都有门禁与审批记录；降级（例如线上发现问题）同样留痕。注册表中的晋级状态驱动 OTA：只有 canary 及以上状态的模型才能被纳入发布计划。

stateDiagram-v2
  [*] --> dev
  dev --> staging: 离线评测 + 仿真评测通过
  staging --> shadow: 适配链通过（契约断言 + 热稳态）
  shadow --> canary: 影子分歧可接受
  canary --> ga: 灰度环逐环通过
  canary --> staging: 门禁破线（回滚 + 冻结 + 取证）
  ga --> deprecated: 新版本全量后
  ga --> staging: 线上重大问题（降级留痕）
  deprecated --> [*]

13.8 端侧适配链

13.8.1 从检查点到五件套

导出 ONNX（固定输入契约）→ 按引擎矩阵构建（第 6 章策略 B）→ 量化与校准（校准集来自目标场景，进入血缘）→ 契约断言与热稳态压测 → 生成模型卡与制品五件套 → 签名入库（第 9 章）。适配链是模型工厂与 OTA 的接口，也是最适合平台团队完全接管的一段。

13.9 从部署经验中学习

13.9.1 新范式对平台的要求

π*0.6 这类方法用真实部署中的经验（成功、失败、人工纠正）做强化学习，让模型在岗位上持续变好。对平台意味着：

要求 平台能力
每次任务都有结果标注 任务面的成功/失败/介入记录与片段关联（三键贯穿）
人工纠正要被捕获 遥操作接管的动作序列完整回传（介入触发）
策略更新更频繁 更快的评测 CI 与更自动化的灰度
在线学习的安全边界 学习只发生在云端，端侧只接收经过门禁的新版本；绝不在机器人上直接在线更新权重

最后一条是底线：模型可以从经验中学，但发布纪律一条都不能少。

13.10 双向 SLA：平台与算法团队

13.10.1 两张清单

算法团队交付给平台（缺项拒入库） 平台承诺给算法团队
模型卡：三契约、五元组、评测结果、许可证 数据集：清单化、可复现、可检索，转速可度量
归一化统计量与预处理代码 训练资源：队列与配额可预期
离线评测脚本与分组定义 评测 CI：候选模型当天出结果
已知失效模式说明 真机反馈：影子分歧与线上失败样本自动回流
目标机型与精度要求 发布：引擎矩阵构建、签名、灰度、回滚

清单就是接口。一句话讲清立场：平台不要求模型可解释，但要求它可检测、可中断、可回滚。

13.11 案例推演：归一化统计量错配

13.11.1 现象

一个新模型通过了离线与仿真评测，灰度环 0 上机后，机械臂动作幅度明显偏大，急停触发一次，门禁一票否决并自动回滚。

13.11.2 根因

训练使用的数据集 v2 重新计算了动作统计量（加入了反光包装定向数据后，动作分布变了），但导出流程仍然打包了 v1 的统计量文件。离线评测在归一化空间里比较，看不出问题；仿真评测用的是训练框架自带的反归一化，也没问题；只有端侧运行时用了制品里打包的旧统计量。

13.11.3 平台动作

  1. 统计量只从数据集清单中读取（p03 的 stats 字段），导出流程禁止手工指定；
  2. 契约断言增加“统计量来源的数据集哈希必须等于模型五元组中的数据集哈希”；
  3. 仿真评测改为使用与端侧完全相同的运行时与制品（评测对象就是发布对象）；
  4. 急停一票否决门禁证明了价值——它挡住了一次可能的设备损坏。

🚗→🤖 迁移对照

车联网 / AI 平台 模型工厂 迁移方式
智驾模型训练平台 VLA 微调流水线 直用
模型注册表 注册表 + 制品库 + OTA 三权分立 直用
端到端智驾模型 VLA（骨干 + 动作头） 改造
仿真回灌评测 三级评测 + 评测 CI 直用
编译产物绑定芯片 引擎矩阵 直用
模型卡 三契约 + 五元组模型卡 改造

⚠️ 一线踩坑

  • 只报总分：局部分组退化被平均掉。对策：分组报告，关键分组单独设门禁。
  • 评测对象不是发布对象：评测用训练框架推理，发布用端侧引擎，两者行为不一致。对策：评测直接加载发布制品。
  • 五元组缺项：线上问题无法复现与归因。对策：训练任务模板强制五元组，缺项不排队。
  • 在机器人上在线更新权重：绕过所有门禁。对策：学习只在云端，端侧只接收发布版本。

🛠️ 动手练习

  1. 为你选择的一个开源 VLA 写一份模型卡（三契约 + 五元组 + 许可证），并用 13.3.2 的断言函数对照你的 Device Profile 检查。
  2. 基于 p03 导出的数据集清单，写一份训练任务模板，并说明哪些字段来自清单、哪些来自代码仓库。
  3. 设计一个评测集的分组方案（至少 5 个分组），说明每个分组的来源与门禁阈值。
