第 22 章 实战六：ROS 2 端侧套件与全家桶联调

p06 是全书唯一运行在“机器人上”的工程：一个 ROS 2 Jazzy 工作空间，包含自定义接口、底盘仿真、状态聚合、任务执行器与 MQTT 云桥——机器人的“TBox”。

Flywhl 11 分钟 发布于 2026.09 #ROS 2#云边协同#实战项目

先读结论

  1. 云桥是唯一通道：只读状态、只调任务与参数。
  2. 回调只入队：隔离网络线程与 ROS 执行器。
  3. 任务事件永不丢：离线队列三级优先级。
  4. 契约测试：端云实现漂移时先红。
  5. 真实形态联调：部署相关缺陷只在真实形态出现。

本章定位：p06 是全书唯一运行在“机器人上”的工程：一个 ROS 2 Jazzy 工作空间，包含自定义接口、底盘仿真、状态聚合、任务执行器与 MQTT 云桥——机器人的“TBox”。本章讲清 p06 的设计与验证方式，再把六个工程拼成一套全家桶：一条命令拉起 broker、云端、仿真机队、具身 Agent，以及可选的真 ROS 2 机器人。
代码位置：code/p06-ros2-edge-kit、code/capstone｜对应理论：第 4、5 章（ROS 2）、第 8 章（接入）、第 10 章（任务）｜建议学时：8 小时

22.1 目标与验收

22.1.1 p06 的四个节点

节点 职责 车联网类比
sim_base 模拟底盘：位姿、电量、温度，接收速度与模式 车辆 ECU 仿真

22.1.2 验证方式与边界

云桥是机器人与外界的唯一通道：它只订阅聚合后的状态、只调用任务动作与参数服务，从不直接发布速度指令。这让第 16 章的 SROS2 最小权限可以精确描述为一份很短的权限文件。

22.2.2 接口定义

通用任务动作 + JSON 参数是一个有意的取舍：新增任务类型不需要改接口、不需要重新编译所有包，代价是参数校验下沉到执行器——执行器必须对每种任务类型做参数白名单校验（与 p04 安全笼同理）。

22.3 云桥的三条纪律

22.3.1 线程纪律：回调只入队

在 paho 的网络线程里直接调用 rclpy 是一类难以复现的并发缺陷来源。“回调只入队、定时器里处理”把两个事件循环隔离开——这与你在车端 TBox 软件中隔离通信线程与业务线程是同一原则（第 5 章 5.8.2）。

22.3.2 离线纪律：优先级队列

断网时上行消息按优先级区别对待（OfflineQueue）：

优先级 内容 断网时的处理 理由
P0 任务事件与结果 有界缓存（默认 500 条），满了丢最旧，恢复后全部补发 云端靠它判断任务结局
P1 影子回报 只保留最新一条 回报是“状态”，旧的没有意义
P2 遥测 直接丢弃并计数 过期遥测无价值，补发只会挤占带宽

任务事件永远不能被遥测挤掉——否则云端会因为收不到“已完成”而回收一个其实已经完成的任务。恢复连接后先补 P0、再补 P1。

22.3.3 影子纪律：白名单、范围、逐项回报

影子 delta 经 plan_param_ops 转换为“哪个节点的哪个参数设为什么值”：不在白名单的键拒绝，超出范围的值拒绝，拒绝原因写进回报的 rejected 字段。第 17 章实验 3 指出 p01 的仿真机器人没有范围校验；p06 的云桥正是它的生产化答案。

22.4 契约测试：端云之间的“接口合同”

22.4.1 为什么需要

p01 的仿真机器人与 p06 的云桥是两份独立实现，它们必须说同一种 ECL v1。契约测试用 p06 的 protocol_mapping 生成上行消息，交给 p01 的协议解析与服务处理，断言云端能正确更新在线状态、影子与任务。任一方改协议，契约测试先红——这比任何文档都可靠。

22.4.2 测试地图

文件 覆盖

22.5.3 实测：多进程联调

capstone/verify_multiprocess.py 用子进程拉起 p01 服务端、3 台仿真机器人和 p04 Agent；broker 优先用本机 mosquitto，没有就起一个 eclipse-mosquitto:2 容器。端口取 code/ports.env 的测试临时栈（23610/23630），与开发栈、compose 栈可以同时存在。启动过程按就绪条件轮询（broker 端口 → /healthz → 3 台 ONLINE），不靠固定等待。实测输出：

注意任务创建时的状态是 SENT 而不是单进程剧本里的 ACCEPTED：经过真实 broker 后，端侧的接受回执是异步到达的。同一套代码在不同部署形态下的时序差异，只有真实形态的联调才能看到。

22.5.4 联调发现的缺陷

第一次多进程联调时，Agent 对所有指令都返回“无法规划”。原因是规则规划器的机器人 ID 正则写死了 amr-、ros- 等前缀，而全家桶里的仿真机队叫 cap-001（第 20 章缺陷 4）。单进程剧本恰好都用 amr- 前缀，测试全绿，问题被掩盖了。这就是为什么全家桶联调是交付前的必经步骤。

22.5.5 真实 ROS 2 容器验收发现的缺陷

p06 早期只做了静态校验、映射单测与契约测试（全部通过）。第一次在 ros:jazzy-ros-base 镜像里真正启动，暴露了一串这三层都测不到的问题：

现象 根因 修复
launch 报 Invalid namespace，四个节点一个都没起来 ROS 2 名称只允许字母数字与下划线，launch 直接用 ros-001 当命名空间 ros_namespace() 把设备 ID 映射为 ros_001，云端身份不变；单测覆盖
影子下发 {"report_hz": 2} 不生效 JSON 整数 2 → ROS 整数参数，而 report_hz 声明为 double，ROS 2 强类型拒绝 协议映射层按参数类型规范化（2 → 2.0），布尔值不再被当成数字
ROS 结果事件把云端记录的最后阶段清空 动作结果里没有阶段，云桥上报 stage=""，云端直接覆盖 云端空阶段不覆盖已知阶段；p01 回归测试
云端未就绪时机器人永远“未激活” 开发态开通只试一次，编排启动顺序稍有偏差就失败，之后所有上行被拒收 开通退避重试（已注册则沿用身份）；compose 加健康检查，云端健康后才启动机器人
刚上线就派单被拒“电量 0.00” 电池话题 1 Hz，首帧状态里电量还是初始值 0 电量未知前不发布 RobotState
偶发云桥网络线程崩溃（竞态） on_connect 可能早于 self.client 赋值被回调 先赋值再连接；拒绝码不再当作已连接

这张表是本章最重要的结论之一：契约测试保证“说同一种语言”，运行时验收才保证“真的能说出口”。把 ROS 2 镜像里的运行时测试与 compose 联调放进交付门禁，成本是几分钟，换来的是“书里的命令读者照做就能跑通”。

22.6 在你的机器上运行

22.6.1 四种方式

端口全部来自 code/ports.env（全家桶 23110/23130、p06 23210/23230、多进程联调 23610/23630），各栈可同时运行；启动前可用 make ports-check 预检占用。

22.6.2 ROS 2 侧的排障清单

现象 检查
launch 报 Invalid namespace 命名空间是否含连字符等非法字符（应为 ros_namespace(robot_id)）
云端看不到 ros-001 云桥日志中的开通与 MQTT 连接；MQTT_HOST 是否为服务名；云端是否健康
上线但状态 DEGRADED state_aggregator 是否在发布；ros2 topic hz 查看频率
任务一直 SENT ros2 action list 是否有任务动作；执行器是否拒绝（类型/电量/模式）
影子参数不生效 回报里的 rejected 字段；参数是否在白名单与范围内；Wrong parameter type 说明类型未规范化
容器间 DDS 串扰 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST 是否生效（Jazzy 的发现范围设置）

22.7 扩展练习

22.7.1 从套件到产品

  1. 为 task_executor 增加每种任务类型的参数白名单校验，并补单元测试；
  2. 实现漫游宽限：云桥短暂断线在 N 秒内恢复时，不发布离线相关的回报；
  3. 在 p06 中加入一个“诊断原语”服务：接收云端的白名单命令（节点列表、话题频率），返回结构化结果，接入 p05 的检查环节；
  4. 为 p06 的四个节点写 SROS2 权限文件，并在 Docker 中启用访问控制；
  5. 在 CI 中用 Gazebo 替换 sim_base，跑一次端到端冒烟测试（第 14 章）。

⚠️ 一线踩坑

  • 在网络线程里调用 ROS：偶发死锁或崩溃。对策：回调只入队。
  • 离线队列不分优先级：遥测挤掉任务事件，已完成的任务被误回收。对策：P0 必补、P1 留最新、P2 断网即丢。
  • 只做单进程测试：部署形态相关的问题被掩盖（ID 前缀、异步时序）。对策：全家桶联调进入交付门禁。
  • 容器内 DDS 互相发现：多个机器人容器的话题串在一起。对策：限制发现范围、区分域 ID。
  • 设备 ID 直接当 ROS 命名空间：连字符是非法字符，launch 当场失败。对策：ID → 命名空间做成确定性纯函数并单测。
