第 19 章 实战三：数据飞轮流水线——从一次人工介入到一个定向数据集

先读结论

  1. 配额统计也是监控：丢弃量突变往往是设备异常。
  2. 先排序再去重：近重复里留价值最高者。
  3. 定向数据集靠新增数据：重新切分不产生新信息。
  4. 瓶颈会移动：转速要持续测量。

本章定位：p03 把第 12 章的数据引擎做成了可运行的流水线：触发与配额、元数据先行、分区入湖、以景搜景、四级漏斗、不可变数据集、血缘、LeRobot 风格导出、飞轮转速。本章沿着剧本走一遍“线上问题 → case 家族 → 定向采集 → 新数据集”，并复盘构建过程中发现的四个问题。

19.3.2 读数

  • 配额在工作：122 次新颖性触发被丢弃片段、只留元数据——新站点上线时几乎一切都“新”，没有单独配额会挤占介入片段；
  • 漏斗淘汰主要来自近重复：同一片段里的多个触发（介入 + 低置信 + 分歧）裁出的片段高度相似，保留价值最高的一个；
  • 以景搜景有效：场景向量把“反光包装”这一语义聚在一起，Top20 全部命中；
  • 转速瓶颈会移动：优化评测与灰度后，新瓶颈变成“补齐 case 家族到发布数据集”——下一步该投资的是定向采集的自动化。

19.4 代码导读

19.4.1 触发与配额

detect 找出所有候选触发，admit 按“单机每日总量 + 单触发器上限”放行。被拒的触发计入 dropped——配额本身的统计也是监控指标：某站点丢弃量突然上升，往往意味着设备异常（例如传感器故障不停报错）。

19.4.2 近重复：保留价值最高者

先按价值排序再去重，保证一组近重复里留下的是“人工介入”而不是“随机采样”。测试 test_funnel_stats_consistent_and_dedup 验证了这一点，并验证漏斗守恒：进入数 = 通过数 + 各级淘汰数。

19.4.3 不可变清单与继承

内容哈希由“排序后的片段 ID + 各片段摘要”决定。同样的内容永远得到同一个版本；inherit=True 时新版本包含父版本的全部片段，并重新计算动作统计量——第 13 章“统计量错配”案例的根源正是这里：统计量必须跟着清单走。

19.5 构建复盘：四个问题

19.5.1 阶段验证发现的问题

# 现象 根因 修复 教训
1 剧本中 v2 与 v1 版本号相同 v1 已含全部 pick_place 片段，“继承 + 反光子集”内容哈希不变，被幂等逻辑正确识别 改为“先定向采集新数据、再发 v2” 定向数据集的价值来自新增数据，不是重新切分旧数据
2 新颖性触发占回传 65% 以 sh-01 数据为参照时，其他站点全部“新颖” 新颖性单独配额 每类触发器单独配额
3 低置信触发从不命中 合成数据的置信度是逐帧独立噪声，连续 15 帧低于阈值几乎不可能 生成器改为“整段低置信” 真实低置信是整段的，“连续 N 帧”规则正是为此设计
4 小规模运行时剧本崩溃 找不到符合条件的探针片段 探针逐级回退 剧本与工具都要对“数据稀少”稳健

第 2、3 条已作为“一线踩坑”写回第 12 章。

19.7 实验

19.7.1 五个实验

  1. 把 quota_per_trigger 中的新颖性上限改为 99，观察介入片段在数据集中的占比变化；
  2. 把 dup_sim 从 0.995 调到 0.98，观察漏斗通过数与数据集多样性的变化；
  3. 新增一个“耗时异常”触发器（单任务耗时超过同类 P95），补测试；
  4. 为 ClipIndex 增加“事件时间线”查询：给定片段，返回同一机器人前后 60 秒内的所有片段与事件；
  5. 用 LeRobot 官方工具把 export 目录转换为官方格式（需要安装 LeRobot），对比两者结构。

⚠️ 一线踩坑

  • 把重新切分当成新数据：定向数据集没有新增信息（问题 1）。
  • 单一配额：新颖性挤占介入（问题 2）。
  • 合成数据不像真实数据：规则在合成数据上永不触发，误以为规则有问题（问题 3）。

🎯 面试与评审要点

  1. 讲一次从线上问题到定向数据集的完整链路。（触发 → 元数据先行 → 以景搜景 → 定向采集 → 继承发版 → 血缘）
  2. 你的漏斗如何保证不丢高价值数据？（先按价值排序再去重；各级统计守恒可审计）
  3. 飞轮转速的瓶颈会移动吗？（会：优化一段后下一段成为瓶颈，持续测量）
