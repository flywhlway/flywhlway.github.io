第 16 章 安全与合规：从芯片到 Agent 的纵深防御

把车联网“TSP / OTA / 远程诊断”的纵深防御体系迁移到机器人。

Flywhl 9 分钟 发布于 2026.09 #机器人云平台#安全#合规

先读结论

  1. 安全三重交集：IT、OT、物理安全交织。
  2. 信任链到模型：芯片、引导、系统、应用、模型、运行时。
  3. 两个信任锚：芯片公钥与产线证书。
  4. 密钥分用途分周期：泄露不连锁，越近端侧越短命。
  5. SROS2 最小权限：云桥被攻破的伤害上限由权限文件决定。

本章定位：把车联网“TSP / OTA / 远程诊断”的纵深防御体系迁移到机器人。机器人安全的特殊性在于三重交集：IT 安全（数据与账号）、OT 安全（设备与控制）、物理安全（人身与财产）交织在一台会动的设备上。本章给出威胁模型、信任链、身份与密钥、三层通信安全、供应链、远程访问、数据合规与安全运营的完整框架。
对应代码：p02（签名与防回滚）、p04（安全笼与哈希链审计）、p01（接入准入）、p06（云桥守门）｜建议学时：5 小时

16.1 威胁模型：三重交集

16.1.1 攻击面矩阵

资产 \ 威胁 冒充 篡改 抵赖 泄露 拒绝服务 越权
云平台 伪造设备接入 篡改任务/制品 无审计的操作 数据库泄露 接入风暴 运营账号越权
端侧主控 克隆设备 刷入恶意固件/模型 — 本地数据被拷走 磁盘写满 调试口提权
机内网络（DDS） 伪造节点 注入控制指令 — 嗅探图像 话题洪泛 未授权订阅
本体（物理） — 传感器欺骗 — — 物理阻挡 危险动作
Agent 冒充操作员 环境注入 无法追溯决策 泄露场景信息 Token 耗尽 调用越权工具

最后一行与倒数第二行是车联网里没有的：本体行意味着安全事件的后果可能是人身伤害；Agent 行意味着攻击可以从“看到的字”开始（第 15 章）。

16.1.2 STRIDE 物理化

传统 STRIDE 的每一项在机器人上都有物理版本：冒充一个急停信号源、篡改一个安全速度参数、拒绝服务让机器人停在通道中央堵住消防通道。威胁建模时，每一条都要追问“最坏的物理后果是什么”。

16.2 信任链：从芯片到模型

16.2.1 五环信任链

flowchart LR
  ROM["芯片 ROM<br/>（熔丝公钥）"] --> BL["引导程序<br/>Secure Boot 验签"]
  BL --> K["内核 + rootfs<br/>验签 + dm-verity"]
  K --> APP["平台与业务软件<br/>包签名 + 完整性"]
  APP --> M["模型与技能制品<br/>加载前验签（第 9 章）"]
  M --> RUN["运行时<br/>契约断言（第 13 章）"]

车联网的信任链通常止于应用层；机器人必须延伸到模型：一个被替换的模型权重，可以让机器人做出任何动作，而固件签名对此毫无察觉。p02 的端侧 Agent 在安装前做“签名 → 摘要 → 兼容 → 安全版本”四项校验，就是这一环的最小实现。

16.2.2 两个信任锚

信任链有两个锚：芯片里的公钥（在产线熔断，决定能跑什么代码）与产线签发的设备证书（决定能以谁的身份接入平台）。两个锚都在制造环节建立，安全从产线开始，这与 TBox 产线灌装完全一致。

16.3 身份与密钥

16.3.1 密钥分用途、分周期

密钥 / 证书 存放 用途 轮换
根 CA 离线 HSM 签发中间 CA 长期（离线保管）
中间 CA（按产品线） 在线 HSM 签发设备与服务证书 数年；可单独吊销止损
设备证书 端侧安全芯片 / TPM 云—端 mTLS 约一年，自动轮换
DDS 节点证书 端侧（受保护存储） 机内 SROS2 随软件版本
固件签名密钥 HSM 固件制品 按策略，与模型密钥分离
模型签名密钥 HSM 模型制品 同上
配置签名密钥 HSM 配置与技能制品 同上
接入令牌 端侧内存 短时访问 小时级

分用途：模型签名密钥泄露不影响固件信任链；分周期：越靠近端侧、越频繁使用的凭据寿命越短。p02 支持多把受信公钥，正是为了让密钥轮换期间新旧签名都能被验证。

16.3.2 私钥不出芯片

设备私钥在安全芯片内生成、在芯片内签名，永不导出。一台机器人被拆开，攻击者拿到存储也拿不到私钥，无法克隆它的身份。

16.4 通信安全三层

16.4.1 云—端、机内、边缘

层 机制 要点
云—端 mTLS + 主题 ACL（第 8 章） 每台只碰自己的子树；上行只发上行主题
机内 SROS2（ROS 2 基于 DDS Security 的安全能力：认证、访问控制、加密） 按话题授权：谁能发布控制指令、谁能订阅相机
边缘 站点服务证书 + 网络分区 机器人网络与办公网络隔离

16.4.2 SROS2：机内不再“默认信任”

默认的 DDS 网络里，同一网段任何进程都能订阅任何话题、发布任何指令——包括速度指令。SROS2 为每个节点签发身份（enclave），并用签名的权限文件规定它能发布、订阅哪些话题。权限文件应当从 Device Profile 与节点清单自动生成，而不是手写：

云桥是机器人对外的唯一通道，它被攻破时能造成的最大伤害，由这份权限文件决定。云桥不能发布 cmd_vel，就意味着即使云端被攻破，攻击者也只能下发“任务”，而任务还要经过执行器准入与物理安全网。

16.4.3 性能代价

加密与签名会增加时延与 CPU 开销。实用做法：控制与安全相关话题启用认证与访问控制；高带宽图像话题在单机内走共享内存、按需加密；先做访问控制，再做全量加密。

16.5 供应链安全

16.5.1 四类 SBOM

类别 内容 用途
软件 SBOM 操作系统包、ROS 包、Python/C++ 依赖及版本 漏洞影响面分析
模型 SBOM 基座模型、许可证、训练数据集版本、微调五元组 许可合规、问题追溯
数据 SBOM 数据集来源构成、授权依据、脱敏方式 合规审计、删除请求
硬件 BOM 主控、传感器、关节模组型号与固件 硬件漏洞与召回

16.5.2 CVE 联动

新漏洞公告发布 → 在软件 SBOM 中检索受影响组件 → 结合孪生档案（第 8 章）自动圈定受影响设备清单（哪些机型、哪些版本、在哪些站点）→ 生成修复制品 → 走 OTA 灰度。这条链路把“漏洞响应”从“排查几天”变成“几小时出清单”，是车联网安全运营里最值得原样迁移的一项。

16.5.3 依赖锁定

镜像基于固定摘要、依赖锁定版本、构建可复现；外部模型权重下载后校验摘要并登记模型 SBOM。任何进入机器人的字节，都要能说清它从哪来。

16.6 远程访问

16.6.1 诊断会话的管控

远程诊断会话（第 11 章）按能力分级：只读默认开放给值班角色；日志与片段拉取需要审批与脱敏；实时可视化限时、限人、会话结束自动关闭；任何会改变机器人行为的操作都作为任务下发并走人审。调试端口（SSH、串口）在量产设备上默认关闭，开启需要工单、限时证书与全程审计。

16.7 数据合规

16.7.1 三件事

  1. 个人信息：画面中的人脸、工牌、语音在端侧或边缘脱敏（第 12 章“合规左移”）；
  2. 客户数据主权：客户工厂的布局与产品外观属于客户，回传需授权，混合云部署保证原始数据留在客户侧（第 7 章）；
  3. 可删除：接到删除请求时，沿数据血缘找到所有派生数据集与模型，完成删除或重训评估。

16.7.2 跨境

在中国境内采集的数据，默认在境内存储、处理与训练；需要出境时按个人信息保护与数据出境的相关法规完成评估或备案。平台层面的做法是区域隔离：数据湖、训练集群、模型制品按区域部署，跨区域流动走审批与审计。

16.8 功能安全的边界

16.8.1 平台不负责安全功能

急停、安全速度、力矩限制、协作区限速等安全功能必须由独立于平台与模型的硬件与安全控制器实现，并按适用标准（工业机器人 ISO 10218 系列、协作应用 ISO/TS 15066、服务机器人 ISO 13482 等）设计与认证。平台的职责是三件事：让安全状态可见（急停事件、安全区触发实时上报）、让安全配置受控（安全相关参数的变更必须审批、签名、可追溯）、让安全事件可追溯（自动取证包）。

16.8.2 两类安全的交集

信息安全与功能安全在一个点上交汇：安全相关配置的完整性。攻击者如果能篡改协作区限速参数，就把信息安全漏洞变成了人身风险。所以安全相关参数单独分类：独立签名、变更双人审批、端侧只读挂载、每次启动自检比对。

16.9 安全运营

16.9.1 事件响应：一台被盗的机器人

  participant AL as 告警<br/>(地理围栏/异常断连)
  participant SOC as SOC 值班

  SOC->>DEV: 结案后 → 退役（数据归档、影子冻结）

16.9.2 安全事件进入可观测

安全事件（证书异常、未授权接入尝试、签名校验失败、注入命中、异常急停）与运维事件使用同一套三键与告警体系（第 11 章），SOC 与运维共享取证包。p01 的 rejected_uplink_msgs、p02 的签名与防回滚失败、p04 的审计哈希链，都是安全信号的来源。

16.10 零信任落地与自检

16.10.1 四层零信任

身份（每台设备、每个节点、每个服务都有证书）→ 最小权限（主题 ACL、SROS2 权限、技能目录、安全笼）→ 持续验证（短时令牌、设备健康作为访问因子：安全版本过低的设备限制能力）→ 可追溯（审计与取证）。

16.10.2 平台安全自检清单

检查项 通过标准
设备身份 所有在营设备证书有效，无共享证书
主题 ACL 模板化，无通配越权
机内 DDS 控制类话题启用 SROS2 访问控制
制品 四类载荷全部签名，端侧验签，防回滚生效
密钥 分用途，HSM 保管，轮换在期
SBOM 四类齐全，CVE 联动可在数小时内出受影响清单
远程访问 调试口默认关闭，会话限时审计
Agent 无直控工具，参数白名单，高风险人审，审计防篡改
数据 边缘脱敏，区域隔离，血缘支持删除
功能安全 安全功能独立于平台；安全参数受控

车联网安全 机器人安全 迁移方式

⚠️ 一线踩坑

  • 信任链止于固件：模型文件没有验签，被替换后无人察觉。对策：信任链延伸到模型与技能。
  • 机内默认信任：同网段任何进程都能发布速度指令。对策：SROS2 访问控制，权限从 Profile 自动生成。
  • 一把密钥签所有：一次泄露全线失守。对策：分用途、分周期、HSM。
  • 安全参数当普通配置：协作区限速被随手修改。对策：独立分类、双人审批、只读挂载、启动自检。
  • 量产设备留着调试口：现场被人插线提权。对策：默认关闭，工单开启，限时证书。

🛠️ 动手练习

  1. 以 p06 的四个节点为对象，写出它们的 SROS2 权限矩阵（谁能发布/订阅哪些话题），说明云桥的最小权限。
  2. 在 p02 中模拟一次密钥轮换：新密钥签发新制品，端侧同时信任新旧两把公钥，确认旧制品与新制品都能安装，然后移除旧公钥。
  3. 为你的场景写一份“机器人被盗”响应手册，对照 16.9.1 的时序补充业务侧动作。

🎯 面试与评审要点

  1. 机器人安全和车联网安全最大的不同？（本体与 Agent 两个新攻击面，后果物理化）
  2. 信任链为什么要延伸到模型？（替换模型等于替换行为；端侧四项校验）
  3. SROS2 解决什么问题？（机内默认信任；按话题授权；权限从 Profile 生成）
  4. 平台和功能安全的关系？（安全功能独立；平台负责可见、受控、可追溯）
